# PRD 模块统一模板

> **用法**：每个 Writer 拷贝本文件作为起手，按 11 章节顺序填写。章节编号与顺序**不得调整**。

---

# M<编号> <代号> – <中文名> PRD

> 版本 v1.0 · 适用 Muxvo Rust 重构 · 行数上限 <根据模块预算>

## 1. 模块定位

- 一句话说明"这个模块对用户意味着什么"（≤ 40 字）
- 不用该模块用户会损失什么（1-2 句）
- 与相邻模块的分界（最多列 3 条，格式：`XX 属于本模块 / YY 属于 [M??]`）

## 2. 目标用户与场景

- **主要用户画像**：1-3 类（如"CLI 重度用户"/"Skill 作者"/"新手"），每类一句话
- **Top3 使用场景**：每个场景一段话（200 字内）描述"在什么情况下、想解决什么、期望怎么做"
- **使用频率**：日常 / 偶尔 / 首次，注明该模块典型使用节奏

## 3. 用户故事

用 Given-When-Then 格式，每条一个 ID：

```
US-<CODE>-001
Given  <前置条件>
When   <用户动作>
Then   <用户看到的结果>
```

**必须覆盖**：
- 首次使用路径（至少 1 条）
- 主要功能路径（至少 3 条）
- 切换/恢复路径（至少 1 条）
- 退出/清理路径（至少 1 条）

**数量**：8-15 条

## 4. 功能需求清单

按优先级列表化。一行一个功能，**只写"能做什么"**，不写"怎么做"。

| ID | 功能 | 优先级 | 用户可感知的结果 |
|---|---|---|---|
| REQ-<CODE>-001 | <功能一句话> | P0 | <用户看到/得到的结果> |
| REQ-<CODE>-002 | ... | P1 | ... |

**优先级定义**：
- **P0** = 没有就不发布
- **P1** = 首发期望
- **P2** = 后续迭代

**数量**：15-30 条

## 5. 详细需求条目

每条 REQ 展开为一小段，格式固定：

```
### REQ-<CODE>-NNN <功能短名>

**触发方式**：（用户视角：点击什么 / 按什么键 / 进入什么页面）
**前置条件**：（必须满足的状态，用户视角）
**正常流程**：
  1. 用户 <动作>
  2. 系统显示 <变化>
  3. 用户 <下一步动作>
**用户看到的反馈**：（视觉 / 文案 / 动画 / 声音）
**结束状态**：（完成后用户停留在哪里、看到什么）
**异常情况**：（列举 1-3 个，如"无网/无权限/超额"，各自的用户感知）
**相关**：[M??-REQ-NNN]（引用其他模块的 ID）
```

**禁止**出现：
- 函数名、变量名、类名
- 状态枚举值（用"用户看到 X"代替"state=X"）
- 存储位置 / 进程 / 通道 / API / 文件路径

## 6. 主要用户旅程

至少 3 段旅程，每段 5-12 步。格式：

```
### Journey <编号>：<场景名>

1. **用户** 做 X
   → **用户所见**：<界面变化>
   → **用户感受**：<情绪 / 心智>
2. ...
```

**必写旅程**：
- Journey 1：首次进入（新手视角）
- Journey 2：核心高频路径（老手视角）
- Journey 3：异常/恢复路径

## 9. 边界、限制与异常

- **数量限制**：同时几个 / 最多多少 / 最长多久
