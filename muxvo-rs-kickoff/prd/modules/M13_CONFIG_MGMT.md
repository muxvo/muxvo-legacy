# M13 CONFIG_MGMT – Claude 配置管理 PRD

> 版本 v1.0 · 适用 Muxvo 重构 · 行数上限 805

## 1. 模块定位

- **一句话**：用四个一级 Tab（Skills / MCP / Hooks / Plugins）把 Claude 的几类可配置资源以可视化列表的方式呈现给用户，让他们无需去翻各种隐藏目录就能看清"自己装了什么、哪些在生效"。
- **不用它会怎样**：用户只能手动在 `~/.claude/` 及各个项目目录下翻文件，名字记不住、状态看不到、损坏了也不知道。对新手而言，"Claude 究竟能做什么定制"完全是黑盒。
- **与相邻模块的分界**：
  - 四个 Tab 本身的菜单入口、列表、搜索、详情、启停、空态、损坏态 属于本模块。
  - Skills Tab 里点开某个文件后的 Markdown 可视化编辑器属于 [M12 FILE_VIEWER]（Skills Tab 只调用它、不自实现）。
  - 文件面板（终端右侧滑出的文件浏览器）属于 [M11 FILE_PANEL]，与本模块无关。
  - 偏好设置、主题、快捷键绑定 属于 [M14 ONBOARD_PREFS]。
  - 模块内部的错误弹窗规范属于 [M15 APP_RELIABILITY]。

## 2. 目标用户与场景

### 主要用户画像

- **Claude 高级用户**：装了几十个 Skill、多个 MCP 服务器、自己写过 Hook。需要一个地方能看清"目前到底配了什么、哪些启用了、哪些是项目级的、哪些是全局的"。
- **新手**：刚开始用 Claude Code，听说过"Skill"、"MCP"、"Plugin" 这些名词但从未亲眼见过自己装了哪些，希望有一个图形化列表能一目了然。
- **Skill 作者**：自己写 Markdown 格式的 Skill 文档，需要频繁在侧栏切换 Skill 并对其内容做小幅编辑，不希望每次都要手动打开编辑器。

### Top3 使用场景

**场景 1 — 盘点家底**：用户用 Claude 一段时间后，好奇自己总共装了哪些 Skill。用户点击菜单栏的 Skills 按钮，进入 Skills Tab，左侧列表按"系统"和各个项目分组显示，一眼看到每个分组下的条目数量。用户滚动、扫视，明白"我有 14 个系统 Skill、3 个项目 Skill"。

**场景 2 — 关掉不想要的 Plugin**：用户装过一个 Plugin 体验了一下但不想再让它生效。用户点击 Plugins Tab，在左侧列表里找到它，点击进入详情，看到一个开关处于"启用"状态。用户点一下开关，开关立即滑到"已禁用"，颜色变灰，下次启动 Claude 它就不会再自动加载。

**场景 3 — 编辑一个 Skill 的说明**：Skill 作者想给自己写的 Skill 的描述改一个词。用户进入 Skills Tab，在左侧列表点击目标 Skill，中栏显示该 Skill 目录下的文件结构，自动加载了 SKILL.md。右栏进入可视化的 Markdown 编辑界面，作者改一个词、按 ⌘S 保存，左上角的小红点消失。

### 使用频率

- **Skills Tab**：Skill 作者日常高频（每天 5-20 次），高级用户周频，新手偶发。
- **MCP / Hooks / Plugins Tab**：多数用户偶发使用（每周 0-2 次），属于"装的时候确认一眼、平时不看"。
- 四个 Tab 整体定位是"浏览 + 轻量启停"，不是"长时间工作的主界面"。

## 5. 详细需求条目

### REQ-CONFIG_MGMT-001  菜单栏四个 Tab 按钮

**触发方式**：用户把鼠标移到窗口顶部菜单栏。
**前置条件**：Muxvo 已启动。
**正常流程**：
  1. 菜单栏从左到右依次显示"终端 / Skills / MCP / Hooks / Plugins / 聊天历史"六个按钮。
  2. 用户点击任何一个 Tab 按钮。
  3. 对应 Tab 的整页视图出现，同时其它面板自动关闭。
**用户看到的反馈**：被点击的 Tab 高亮（底色变深或带下划线），其它 Tab 恢复普通态。
**结束状态**：停留在新 Tab，之前 Tab 被完全覆盖。
**异常情况**：无（菜单栏始终可点）。
**相关**：[M14-REQ-NNN]（偏好设置入口也在菜单栏）

### REQ-CONFIG_MGMT-002  Tab 互斥显示

**触发方式**：在已打开某 Tab 时点击另一个 Tab。
**正常流程**：先关闭当前 Tab，再打开目标 Tab；整个切换过程没有中间的"两个 Tab 同时存在"状态。
**用户看到的反馈**：视图立刻替换，没有叠层。
**异常情况**：切换时若当前 Tab 有未保存的编辑（只发生在 Skills Tab）→ 弹出未保存提示对话框，由用户决定是否切换（REQ-014）。

### REQ-CONFIG_MGMT-003  Tab 整页覆盖终端

**触发方式**：点击任一 Tab 按钮。
**正常流程**：Tab 以整页浮层形式覆盖终端网格；整页内部按本模块规范的左右/三栏布局展示。
**用户看到的反馈**：不是从侧边弹出的抽屉，而是直接占据整个工作区。
**结束状态**：用户视线聚焦在当前 Tab，终端被完全遮住。

### REQ-CONFIG_MGMT-004  统一的左右布局

**触发方式**：任意 Tab 打开时。
**正常流程**：左栏是固定宽度的条目列表，右栏占据剩余宽度显示详情；两栏之间有可拖拽的分隔线。
**用户看到的反馈**：四个 Tab 的骨架高度一致，换 Tab 不会有"结构错位"的感觉。
**例外**：Skills Tab 有一个额外的中栏"文件树"，仅在用户选中一个 Skill 后出现，未选中时隐藏，参见 REQ-009。

### REQ-CONFIG_MGMT-005  按 Esc 退出 Tab

**触发方式**：用户在任一 Tab 按下 Esc。
**前置条件**：当前没有进入子编辑态（MCP/Hooks 表单编辑态、Skills 未保存对话框）。
**正常流程**：整页 Tab 关闭，界面恢复到原先的终端视图。
**例外**：
- 在 MCP/Hooks 的"新增/编辑表单"里按 Esc → 先退回"查看详情"状态，不退出 Tab。
- 在 Skills Tab 里有未保存改动时按 Esc → 先弹未保存提示对话框。

### REQ-CONFIG_MGMT-006  Skills 列表按分组显示

**触发方式**：进入 Skills Tab。
**正常流程**：列表顶部显示"系统 Skills"分组（来自 `~/.claude/skills/`），下方按项目名依次显示每个项目的 Skill 分组；每个分组标题左边有一个三角箭头，右边显示该组条目数。
**用户看到的反馈**：一眼看出"哪些是全局公用、哪些是某个项目独有"。
**异常情况**：某个分组为空 → 整个分组不显示。

### REQ-CONFIG_MGMT-007  Skills 列表字母排序

**正常流程**：同一分组内的条目按名称 A→Z 升序排列。分组之间"系统 Skills" 永远排在最上，其余项目分组按项目名升序。
**用户看到的反馈**：顺序稳定可预期，不会"昨天第三今天第七"。

### REQ-CONFIG_MGMT-008  Skills 搜索框

**触发方式**：用户点击列表顶部的搜索输入框。
**正常流程**：用户一边输入，列表一边实时过滤；过滤范围包括 Skill 名称和 Skill 描述两个字段；不区分大小写；分组结构保留，空分组被隐藏。
**用户看到的反馈**：输入即见效，没有"要按回车才生效"的等待。
**异常情况**：无命中 → 列表区域显示 "No matching skills"。
**边界**：搜索仅在列表里过滤，不同时在文档正文中查找（文档正文里的高亮属于编辑区的独立功能）。

### REQ-CONFIG_MGMT-009  Skills 三栏布局

**触发方式**：用户在 Skills Tab 的左栏点击一个 Skill 条目。
**正常流程**：
  1. 左栏该条目变为高亮。
  2. 中栏出现并展开该 Skill 目录下的文件树（文件夹+文件）。
  3. 右栏自动加载 SKILL.md 并以"所见即所得"渲染。
**用户看到的反馈**：从两栏变三栏，像熟悉的"文件管理器+编辑器"布局。
**异常情况**：Skill 目录无法读取 → 中栏为空，右栏显示损坏态（REQ-017）。

### REQ-CONFIG_MGMT-010  Skills 自动加载 SKILL.md

**触发方式**：用户在左栏选中一个 Skill。
**正常流程**：系统自动找到该 Skill 根下的 SKILL.md 并把它加载到右栏；若该 Skill 不是标准目录结构（而是一个独立的 `.md` 文件），则直接加载那个文件。
**用户看到的反馈**：不需要再点一次文件就能看到文档内容。

### REQ-CONFIG_MGMT-011  Skills 的 Markdown 可视化编辑

**触发方式**：右栏正在显示 Markdown 文件时。
**正常流程**：用户直接在渲染视图上修改文字、加粗、列表等；编辑能力与 [M12-REQ-NNN] 完全一致，本 Tab 只是调用。
**用户看到的反馈**：所见即所得，不会暴露源码标记（除非主动切换到源码模式）。
**相关**：[M12-REQ-NNN]（Markdown 编辑能力）

### REQ-CONFIG_MGMT-012  源码 / 所见即所得 切换

**触发方式**：点击右栏顶部"Source" / "WYSIWYG" 按钮，或按 ⌘/ 快捷键。
**前置条件**：当前打开的文件是 Markdown。
**正常流程**：按钮在"Source"和"WYSIWYG"两种文案间切换；右栏编辑区相应地在纯文本和可视化视图间切换。
**异常情况**：当前文件不是 Markdown → 按钮与快捷键无效。

### REQ-CONFIG_MGMT-013  Skills 保存快捷键

**触发方式**：用户按 ⌘S。
**前置条件**：右栏当前有打开的文件且处于"有未保存改动"状态。
**正常流程**：系统写入当前文件内容；保存成功后文件名旁边的红点消失。
**用户看到的反馈**：红点消失即表示保存成功，不需要额外提示。
**异常情况**：写入失败 → 红点保留，并由 [M15-REQ-NNN] 负责统一错误提示。

### REQ-CONFIG_MGMT-014  未保存提示对话框

**触发方式**：在当前文件有未保存改动时，用户尝试切换 Skill、切换文件、按 Esc 关闭 Tab。
**正常流程**：弹出一个居中对话框，显示当前文件名和三个按钮："保存"、"放弃"、"取消"；按"保存"则保存后继续原操作；按"放弃"则丢弃改动后继续；按"取消"则停留在当前文件。
**用户看到的反馈**：对话框把风险具象化，避免意外丢失改动。
**相关**：[M12-REQ-NNN]（未保存提示对话框规范）

### REQ-CONFIG_MGMT-015  Skills 来源徽章

**触发方式**：列表渲染时自动显示。
**正常流程**：根据 Skill 的归属显示徽章："CC"（Claude Code 专属）、"CX"（Codex 专属）、"GM"（Gemini 专属），或同时显示多个徽章（表示多工具共享）。
**用户看到的反馈**：徽章使用不同底色，帮用户快速区分这个 Skill 是给谁用的。
**异常情况**：无法识别归属 → 不显示徽章（默认为通用）。

### REQ-CONFIG_MGMT-016  Skills 空态

**触发方式**：用户首次进入 Skills Tab 且系统目录与项目目录下都没有任何 Skill。
**正常流程**：左栏列表区域居中显示："还没有 Skill"，下方用灰色小字显示两个常用放置位置的提示："~/.claude/skills/"、"<project>/.claude/skills/"。
**用户看到的反馈**：
> 空态文案："还没有 Skill"
> 次级提示："~/.claude/skills/"、"<project>/.claude/skills/"

### REQ-CONFIG_MGMT-017  Skills 损坏态

**触发方式**：某个 Skill 条目在列表里可见（因此说明它的目录存在），但当用户点击它进入详情时发现 SKILL.md 缺失或无法识别结构。
**正常流程**：右栏不显示空文档，而是显示友好提示"此 Skill 无法识别，请检查文件"，下方给出原文件路径和一个"重试"按钮。
**用户看到的反馈**：橙色警告图标 + 灰底提示框，区别于"正常文档"的外观。
**异常情况**：用户点重试 → 重新尝试加载，加载成功则进入正常态，失败则维持损坏态。

### REQ-CONFIG_MGMT-018  MCP 服务器列表按范围分组

**触发方式**：进入 MCP Tab。
**正常流程**：左栏按"系统"和"项目"两个分组展示服务器。"系统"分组来源于全局与桌面级配置，"项目"分组来源于当前工作项目。每个分组标题左侧有三角箭头、右侧显示数量。
**用户看到的反馈**：一眼看出"哪些是全局生效、哪些只对当前项目生效"。
**异常情况**：两个分组都为空 → 进入空态（REQ-023）。

### REQ-CONFIG_MGMT-019  MCP 服务器类型徽章

**正常流程**：每条服务器右侧显示两个徽章：一个是范围徽章（CC / Project / Codex 等），一个是类型徽章（STDIO / HTTP / SSE）。
**用户看到的反馈**：类型徽章让用户一眼知道"它是本地命令还是远端 URL"，不用点进去看。

### REQ-CONFIG_MGMT-020  MCP 服务器详情只读展示

**触发方式**：用户点击左栏某条服务器。
**正常流程**：右栏显示名称（大字号）+ 范围徽章 + 类型徽章；下方按字段展示：命令、参数、URL、请求头、环境变量、所在配置文件路径。只有填写过的字段才显示，未填字段隐藏。
**用户看到的反馈**：结构化表格，像一份"说明书"。
**异常情况**：某个字段是 JSON 对象 → 用等宽字体的多行预格式块展示。

### REQ-CONFIG_MGMT-021  MCP 全局服务器可编辑

**触发方式**：用户选中一个"系统"范围的服务器。
**正常流程**：详情底部出现"编辑"和"删除"两个按钮；点"编辑"进入表单；点"删除"立即生效（不弹二次确认，删除的是配置而不是数据，用户可重新添加）。
**用户看到的反馈**：按钮颜色区分——"编辑"用主色，"删除"用红色。
**异常情况**：保存时遇到错误（例如必填字段为空）→ 对应字段边框变红，按钮不生效。

### REQ-CONFIG_MGMT-022  MCP 项目范围只读提示

**触发方式**：用户选中一个"项目"范围的服务器。
**正常流程**：详情底部不显示任何操作按钮，取而代之显示一行灰色小字："此服务器来自项目配置，只能在项目目录下手动编辑"。
**用户看到的反馈**：用户明白这个条目为什么没有按钮。

### REQ-CONFIG_MGMT-023  MCP 空态

**触发方式**：用户从未配置过 MCP 服务器。
**正常流程**：左栏显示"还没有 MCP 服务器"；右栏显示"选择一个服务器查看详情"的中性占位文案。
**用户看到的反馈**：空态清楚，无误导。

### REQ-CONFIG_MGMT-024  MCP 损坏条目提示

**触发方式**：某个服务器条目在配置文件里存在但内容不完整（例如 stdio 类型但缺少命令字段）。
**正常流程**：该条目仍在列表里显示，但名称变为灰色，左侧出现一个小警告图标；点进去右栏显示"此服务器配置不完整，缺少：命令"一类的提示。
**用户看到的反馈**：灰度 + 警告图标 + 具体缺字段说明，帮助用户定位问题。

### REQ-CONFIG_MGMT-025  Hooks 列表按事件分组

**触发方式**：进入 Hooks Tab。
**正常流程**：左栏按事件名（PreToolUse、PostToolUse、SessionStart、Stop、Notification 等）分组；组标题使用事件名大写字符串；同一事件下的多个触发器按添加顺序排列。
**用户看到的反馈**：按"什么时候会触发"聚合，符合用户心智。

### REQ-CONFIG_MGMT-026  Hooks 来源徽章

**正常流程**：每条触发器显示一个来源徽章：Global（用户主目录）、Project（当前项目目录）、Local（项目目录下的本地扩展）。
**用户看到的反馈**：不同来源用不同底色区分。

### REQ-CONFIG_MGMT-027  Hooks 类型徽章

**正常流程**：每条触发器显示一个类型徽章：command（运行外部命令）、prompt（发一段提示词）、agent（调用子智能体）。

### REQ-CONFIG_MGMT-028  Hooks 详情字段展开

**触发方式**：用户点击一条触发器。
**正常流程**：右栏按字段展开：事件名（最大标题）+ 类型徽章 + 来源徽章 + 命令（等宽字体）+ 匹配条件（若有）+ 超时时间（若有）+ 是否异步（若有）+ 状态消息（若有）+ 配置文件路径。
**用户看到的反馈**：像一张"触发器档案"。

### REQ-CONFIG_MGMT-029  Hooks 空态

**触发方式**：用户从未配置过任何触发器。
**正常流程**：左栏显示"还没有 Hooks"；右栏显示占位文案"选择一个 Hook 查看详情"。

### REQ-CONFIG_MGMT-030  Hooks 仅全局可编辑

**触发方式**：用户选中一条触发器。
**正常流程**：若来源为 Global，详情底部出现"编辑"和"删除"按钮；若来源为 Project 或 Local，则显示"此触发器来自项目配置，只能在项目目录下手动编辑"。
**用户看到的反馈**：与 MCP Tab 的规则一致，降低学习成本。

### REQ-CONFIG_MGMT-031  Plugins 列表按市场分组

**触发方式**：进入 Plugins Tab。
**正常流程**：左栏按 Plugin 来源的"市场"名称分组（若未知则归入 "Unknown"）；每个分组标题为市场名。
**用户看到的反馈**：一眼看出"这几个 Plugin 来自同一个市场"。

### REQ-CONFIG_MGMT-032  Plugins 启停状态点

**正常流程**：列表每一行 Plugin 名称左侧有一个小圆点：启用为亮绿色，禁用为灰色。
**用户看到的反馈**：不点进去也能看到整排的启停状态。

### REQ-CONFIG_MGMT-033  Plugins 启停开关

**触发方式**：用户进入 Plugins Tab 并选中一个 Plugin。
**前置条件**：该 Plugin 已安装。
**正常流程**：右栏详情顶部有一个开关 + 一行文字说明（"已启用" 或 "已禁用"）；用户点击开关立即切换，无需确认。
**用户看到的反馈**：开关滑块滑动，背景色在彩色和灰色之间切换；左侧列表的状态点同时更新。
**异常情况**：写入失败 → 开关回弹到原状态，由 [M15-REQ-NNN] 负责显示错误提示。

### REQ-CONFIG_MGMT-034  Plugins 启停立即持久化

**触发方式**：用户点击启停开关。
**正常流程**：切换后立即保存设置；关闭并重开 Muxvo 后该 Plugin 的启停状态保持。
**用户看到的反馈**：与"操作系统里的开关"同样可靠，不需要手动点"保存"。

### REQ-CONFIG_MGMT-035  Plugins 详情信息区

**正常流程**：在启停开关下方显示 Plugin 的版本号、作者、描述、安装日期（短日期）、最近更新日期（短日期）、所属市场标签。
**用户看到的反馈**：像看一个软件商店的详情页。

### REQ-CONFIG_MGMT-036  Plugins 内容分解

**正常流程**：详情下方单独一段"Contents"区块，分四组列出该 Plugin 包含的 Commands / Skills / Hooks / Agents；每组是一个带标题的无序列表；某一类没有则不显示该组。
**用户看到的反馈**：用户能看到"这个 Plugin 到底给我带来了什么"。
**异常情况**：该 Plugin 没有任何内容 → 整段显示"无内容（仅作容器用）"。

### REQ-CONFIG_MGMT-037  Plugins 空态

**触发方式**：用户未装任何 Plugin。
**正常流程**：左栏显示"还没有 Plugin"；右栏显示占位"选择一个 Plugin 查看详情"。

### REQ-CONFIG_MGMT-038  Plugins 加载失败态

**触发方式**：读取已装 Plugin 清单时出现错误。
**正常流程**：左栏不显示普通空态，而是显示具体错误文案（例如"无法读取已装 Plugin 列表"）。
**用户看到的反馈**：明确区别于"空"和"出错"。

### REQ-CONFIG_MGMT-039  所有 Tab 的列表计数

**正常流程**：每个 Tab 左栏顶部显示"<Tab 名> + 当前数量"。数量随分组和损坏条目的数据一起统计。
**用户看到的反馈**："一眼扫"时不用数。

### REQ-CONFIG_MGMT-040  左右栏可拖动分隔

**正常流程**：左栏与右栏之间有一条 1px 竖向分隔线；鼠标移上去变为左右双箭头，按住拖动可调整左栏宽度，范围约 150-500 像素。
**用户看到的反馈**：能根据 Skill 名称长度或偏好自由调整。
**异常情况**：宽度达到边界不再移动；松开鼠标即保留。

### REQ-CONFIG_MGMT-041  列表折叠分组

**正常流程**：分组标题左侧有一个三角箭头，点击标题可折叠或展开该分组；折叠后只剩标题可见；本次会话内保留折叠状态，关闭 Tab 再进入时所有分组回到默认展开。
**用户看到的反馈**：长列表更易扫视。

### REQ-CONFIG_MGMT-042  同名冲突提示

**触发方式**：系统检测到两个来源不同但名称相同的 Skill / MCP 服务器 / Hook / Plugin。
**正常流程**：两条都在列表里显示；选中其中任何一条时，在详情右上角添加一个黄色感叹号图标，悬停 tooltip 提示"存在另一个同名条目，可能相互覆盖"。
**用户看到的反馈**：不阻断使用，只提示风险。
**异常情况**：三条及以上同名 → tooltip 改为"存在 N 个同名条目"。

### REQ-CONFIG_MGMT-043  菜单栏 Tab 高亮

**正常流程**：当前打开的 Tab 对应按钮使用高亮样式（加粗 + 底色）；点击终端 Tab 时回到终端视图且所有 Tab 按钮都不高亮。

## 6. 主要用户旅程

### Journey 1：新手第一次看自己装了哪些 Skill

1. **你** 刚装完 Muxvo、导入了原来的 `~/.claude/` 配置。你从菜单栏看到一个叫 "Skills" 的按钮。
   → **你所见**：菜单栏上整齐排着六个 Tab 按钮。
   → **你感受**：第一次看到自己是不是装过 Skill 很好奇。
2. **你** 点击 Skills。
   → **你所见**：整个工作区被一个左右分栏的大页面覆盖；左栏顶部标题写着 "Skills" 和一个数字 "14"，下方有"系统 Skills"分组显示 11 项，还有一个项目分组显示 3 项。
   → **你感受**："原来我装了这么多"。
3. **你** 滚动浏览一下名字。
   → **你所见**：每个条目有一行名字和一行简介，右边跟着一个小小的 "CC" 徽章。
4. **你** 随便点一个名字叫 "doc-chunker" 的。
   → **你所见**：中栏出现，里面是它的文件夹结构；右栏立刻显示它的说明文档（可视化渲染、有标题、有列表）。
   → **你感受**：不需要去翻文件就能看内容，舒服。
5. **你** 按 Esc。
   → **你所见**：整页 Tab 关闭，回到终端。
   → **你感受**：心里清楚了自己的 Skill 家底，5 秒能再看一次。

### Journey 2：Skill 作者修改自己写的 Skill

1. **你** 自己写了一个叫 "team-sync" 的 Skill，想改一下描述里的一个词。点菜单栏 Skills 进入。
   → **你所见**：左栏按分组列出所有 Skill。
2. **你** 在列表顶部的搜索框输入 "team"。
   → **你所见**：列表瞬间只剩一条 "team-sync"。
   → **你感受**：反应很快。
3. **你** 点击它。
   → **你所见**：中栏文件树显示 SKILL.md 已被选中（蓝色底）；右栏显示你写过的那段内容。
4. **你** 把一个词从 "自动同步" 改成 "批量同步"。
   → **你所见**：右栏顶部文件名旁边出现一个红色小圆点。
   → **你感受**：知道自己有未保存的改动。
5. **你** 按 ⌘S。
   → **你所见**：红点消失。
   → **你感受**：保存成功，简单直接。
6. **你** 按 Esc。
   → **你所见**：整页关闭，回到终端继续干活。

### Journey 3：启用/禁用 Plugin 并查看内容

1. **你** 昨天装了一个 Plugin 叫 "xhs-poster"。今天想确认它有没有启用。
   → **你所见**：点击菜单栏 "Plugins" 进入。
2. **你** 在列表里找到它，左侧的圆点是亮绿色。
   → **你感受**：原来已经启用了。
3. **你** 点开它看详情。
   → **你所见**：右栏顶部是一个开关（处于开状态），下方有版本号、作者、描述、安装日期；最下方 "Contents" 区块列出它带来的 1 个 Command、2 个 Skill。
   → **你感受**："哦原来这个 Plugin 给我加了这些东西"。
4. **你** 暂时不想让它生效。点开关。
   → **你所见**：开关滑到关的一侧，背景变灰；左侧列表的小圆点同步变成灰色。
   → **你感受**：确认状态已切换。
5. **你** 关掉 Muxvo 明天再来看。
   → **你所见**：明天打开 Plugins Tab，那个 Plugin 的开关仍然是关的。
   → **你感受**：状态稳定。

### Journey 4：遇到损坏的 Skill 如何恢复

1. **你** 手动在 `~/.claude/skills/` 里放了一个写了一半的 Skill 目录，SKILL.md 还没写。
2. **你** 进入 Skills Tab。
   → **你所见**：左栏列表里能看到这个目录，但点进去右栏显示"此 Skill 无法识别，请检查文件"，并有一个重试按钮。
   → **你感受**：不慌，知道是我自己没写完。
3. **你** 用别的编辑器补齐 SKILL.md，保存。
4. **你** 回到 Muxvo 点"重试"。
   → **你所见**：右栏刷新，正常显示文档。
   → **你感受**：恢复路径顺，系统没报红底错误。

| Plugins Tab | 浏览并启停 Plugin | 菜单栏 → Plugins | Esc / 点击终端 Tab |
| 未保存提示对话框 | Skills 编辑时防止丢失改动 | 在有未保存时切换 / 关闭 | 点"保存"/"放弃"/"取消" |
| MCP/Hooks 编辑表单 | 全局条目的增删改 | 详情页"编辑"或顶部"+" | 点"保存"/"取消"或 Esc |

### 7.2 各页关键区域

**共性骨架**：
- **顶栏**：位于页面最上方的 Tab 切换仍然是窗口菜单栏本身，不是各 Tab 自己的顶栏。每个 Tab 的"内部顶栏"只是列表标题 + 计数徽章 +（MCP/Hooks 有）新增按钮。
- **左栏**：固定宽度（初始 280 像素），可通过分隔线拖动调整（约 150-500 像素）；顶部是标题 + 计数；搜索框（Skills 独有）；下方是分组列表。
- **右栏（或最右栏）**：占剩余宽度；选中时显示详情、未选中时显示占位文案。
- **分隔线**：1px 竖向细线，鼠标悬停变为双箭头。

**Skills Tab 特殊点**：
- 左栏内含搜索框。
- 中栏（文件树）：初始 280 像素，仅在选中某 Skill 后显示；可拖动分隔线调整。
- 右栏是文件编辑区，顶部有"文件名 + 未保存红点 + Source/WYSIWYG 切换按钮 + 文件类型标签"。

**MCP Tab 特殊点**：
- 左栏顶部有一个 "+" 按钮用于新增全局服务器。
- 右栏在"查看"模式下显示只读详情；切换到"编辑/新增"模式后变为表单。

**Hooks Tab 特殊点**：
- 左栏顶部有 "+" 按钮用于新增全局触发器。
- 左栏分组标题是事件名（大写字符串）。
- 右栏详情显示字段较多，按"事件 / 命令 / 匹配 / 超时 / 异步 / 状态消息 / 路径"自上而下排列。

**Plugins Tab 特殊点**：
- 左栏没有 "+" 按钮（本 PRD 不含市场与安装，参见 §10）。
- 每条左侧有一个状态点（亮绿/灰）。
- 右栏顶部有启停开关；下方是信息区；最下方是 Contents 分组列表。

## 8. 状态与交互规则

### 8.1 可见状态清单

- **Tab 未开**：用户看到终端视图，菜单栏中所有 Tab 按钮都不高亮。
- **Tab 打开**：某一个 Tab 的整页内容覆盖终端。
- **列表为空**：对应 Tab 的左栏显示空态文案。
- **列表正常**：左栏显示分组和条目。
- **分组折叠**：分组标题上的三角箭头朝右，下方条目隐藏。
- **分组展开**：三角箭头朝下，下方条目显示。
- **未选中任何条目**：右栏显示占位文案。
- **已选中一个条目**：右栏显示详情，左栏对应条目高亮。
- **处于编辑表单态**（MCP / Hooks）：右栏是表单而非详情。
- **有未保存改动**（Skills）：文件名旁边显示红点。
- **未保存对话框激活**：整个 Tab 灰掉，对话框居中。
- **损坏态**：某条目在列表里灰色+警告图标，或右栏显示错误提示。

### 8.2 状态切换触发

- 用户点 Tab 按钮 → 当前视图切到目标 Tab。
- 用户点左栏条目 → 右栏从"占位"切到"详情"。
- 用户点击右栏"编辑"按钮 → 右栏从"详情"切到"表单"。
- 用户点击表单"取消"或按 Esc → 表单退回"详情"。
- 用户点击分组标题 → 分组折叠/展开互换。
- 用户在 Skills 修改文档 → 文件名旁出现红点。
- 用户按 ⌘S → 红点消失。
- 用户在有未保存时切换 → 弹对话框。
- 用户按 Esc（无未保存、非表单态）→ 关闭 Tab。

### 8.3 快捷键与手势

| 按键/手势 | 作用 | 前置条件 |
|---|---|---|
| 点击菜单栏 Tab | 切换到对应 Tab | 无 |
| Esc | 关闭当前 Tab 或退出子态 | 任意 Tab 内 |
| ⌘S | 保存当前文件 | Skills Tab 编辑右栏处于 dirty |
| ⌘/ | 切换 Source / WYSIWYG | Skills Tab 打开的是 Markdown |
| 点击分组标题 | 折叠/展开分组 | 列表非空 |
| 拖动分隔线 | 调整左栏宽度 | 任意 Tab |
| 单击条目 | 进入详情 | 列表非空 |
| 点击开关（Plugins） | 启停 | Plugins 详情可见 |
| 点击 "+" 按钮 | 进入新增表单 | MCP/Hooks Tab |

### 8.4 多窗口/多标签行为

- 同一 Muxvo 窗口在任意时刻只有一个 Tab 处于打开状态。
- 多个窗口各自独立显示 Tab，互不影响。
- 对同一份配置文件的读取在多窗口间保持一致；某个窗口的启停/编辑会在其它窗口的下一次刷新反映出来。
- 未保存对话框只作用于当前窗口的 Skills Tab。

## 9. 边界、限制与异常

### 数量限制

- 单个 Tab 可展示的条目数量无硬性上限；列表内部支持滚动查看。
- 列表过长（数百条以上）时用户仍可通过搜索或分组折叠快速定位。
- 左栏宽度可调整范围约 150-500 像素。
- 同一 Muxvo 窗口同时只能打开一个 Tab。

### 明确不支持

- 本 PRD 不含"从市场浏览和安装 Skill / Plugin"的任何功能（参见 §10）。
- 本 PRD 不含"新建 Skill/MCP/Hook/Plugin 向导"；Skill 的创建仍然通过用户在终端中让 Claude 协助完成。
- 不支持批量选择多个条目。
- 不支持拖拽排序条目。
- 不支持对项目范围（非 Global）的 MCP/Hooks 做可视化编辑。
- Skills Tab 不支持在内部新建目录、重命名目录、删除 Skill。
- Hooks Tab 的类型切换（command/prompt/agent）目前只在新增/编辑表单里暴露；列表视图不提供快捷类型修改。

### 错误提示文案

| 用户遇到的情况 | 用户看到的提示 | 用户能做的事 |
|---|---|---|
| Skills 目录下没有任何 Skill | "还没有 Skill" + 两条灰色路径 | 在终端中让 Claude 帮你创建 |
| Skills 条目无法识别 | "此 Skill 无法识别，请检查文件" + [重试] | 修复文件后点重试 |
| Skills 搜索无命中 | "No matching skills" | 清空搜索或换关键字 |
| Skills 保存写入失败 | 小红点保留 + 由 [M15] 显示统一错误 | 检查磁盘/权限后重试 |
| MCP 列表为空 | "还没有 MCP 服务器" | 点 "+" 新增（仅全局） |
| MCP 服务器字段缺失 | 条目灰色 + 警告图标 + 详情提示缺哪个字段 | 编辑补全或删除 |
| MCP 项目条目无编辑入口 | "此服务器来自项目配置，只能在项目目录下手动编辑" | 在项目目录内编辑 |
| Hooks 列表为空 | "还没有 Hooks" | 点 "+" 新增（仅全局） |
| Hooks 表单必填字段为空 | 对应字段边框变红，保存按钮无效 | 补齐后再保存 |
| Plugins 列表加载失败 | 列表区显示具体错误文案 | 关闭并重新进入 |
| Plugins 启停写入失败 | 开关回弹 + 由 [M15] 显示错误 | 重试 |
| 两个同名条目 | 详情右上角黄色感叹号 + tooltip 提示 | 自行判断保留哪个 |

### 数据丢失风险

- Skills Tab 有写入能力（编辑 Markdown 文件），因此有"未保存丢失"的潜在风险；通过"文件名红点 + 切换前对话框 + ⌘S"三重提醒降低。
- MCP/Hooks/Plugins 的启停和增删操作都是对配置项的修改，不会影响用户的聊天记录或终端数据；误删后可重新添加，不构成不可恢复风险。
- 本模块不会改动系统目录以外的任何文件。

## 10. 明确不做的事（Out of Scope）

- **Skill / Plugin 市场浏览与一键安装**：本 PRD 不包含任何与远程市场、评分、下载、安装相关的功能。**理由**：市场属于 V2 版功能，需要独立的 Account、审核、付费等支撑。**再考虑**：V2 阶段单独立项。
- **新建 Skill 向导**：本 PRD 不提供"点一下就生成一个空 Skill 目录"的向导按钮。**理由**：Skill 作者本身懂文件结构，新手则通过让 Claude 自动生成更自然。**再考虑**：Skill 作者活跃度上来后再评估。
- **项目级 MCP / Hook 的可视化编辑**：项目内的配置不支持直接在本模块编辑，只能在项目目录中手动修改。**理由**：项目文件的所有权属于项目本身，避免用户在 Muxvo 里误改他人项目的配置。**再考虑**：若未来支持"项目草稿空间"则重新评估。
- **批量操作（多选启停 / 多选删除）**：不支持一次性操作多个条目。**理由**：Plugins 启停是低频操作，批量需求目前未被验证。
- **按名称之外的排序与筛选**：列表只支持"字母排序 + 分组"。**理由**：保持列表稳定可预期；用户需要的"哪些启用"已经由启停状态点承担。
- **按修改时间排序 Skills**：Skill 作者可能希望按"最近编辑"排序来找到自己刚改过的条目。**理由**：会破坏"字母序稳定"的心智模型。**再考虑**：若活跃作者比例高则以二级筛选形式引入。
- **文档全文搜索**：Skills 搜索只作用于名称和描述，不搜索 SKILL.md 文档正文。**理由**：正文搜索已由右栏编辑器的高亮负责（打开某个文档后在文档内查找），列表侧搜索保持"快"的定位。
- **Hook 即时开关**：不支持在列表里直接用开关启停某条触发器（必须进入详情或编辑表单）。**理由**：触发器的可控性敏感，避免手滑误停导致自动化链路失效。
- **Plugin 升级/卸载**：不支持通过 Muxvo 升级或卸载已装 Plugin（卸载需要删除文件，安装需要市场）。**理由**：属于未来 V2 范围。
- **Skills 文件树内的新增/删除/重命名**：中栏只做"浏览 + 点击打开"，不是完整的文件管理器。**理由**：与本模块定位不符，复杂度外溢。

### 11.3 待确认项

- **启停与即时生效**：Plugins 启停持久化已确认，但是否立即影响到当前终端里正在运行的 Claude Code 会话尚不明确（多数场景需重启会话才会重新加载）。本 PRD 仅保证"状态被保存"，不承诺"立刻生效"。**待与产品对齐**：是否需要在开关下方加一句"重启会话后生效"的说明。
- **Hooks 列表的即时开关**：本 PRD 明确不做（§10），但多个用户反馈"禁用某条 Hook"的需求较强。**待与产品对齐**：是否改为 P2 排期。
- **同名冲突的交互强度**：本 PRD 选择"不阻断、加黄色 tooltip 提示"。也有方案是"用红字阻断并要求用户二选一"。**待与产品对齐**：冲突概率和风险程度。
- **Skills 中栏文件树的新建/删除**：本 PRD 不支持。若产品希望"让 Skill 作者顺手新建一个 reference 子文件"，需要在本模块和 [M12] 同时扩展。**待与产品对齐**。
- **MCP/Hooks 表单字段校验**：本 PRD 仅要求"必填字段不为空"。是否需要更严格的命令可执行性校验（例如 stdio 命令是否真的能跑起来）待定。**待与产品对齐**。
- **Plugins 详情中"重启后生效"提示**：与第 1 条相关，待确认。
