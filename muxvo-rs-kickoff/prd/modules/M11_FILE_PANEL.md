# M11 FILE_PANEL – 文件面板 PRD

> 版本 v1.0 · 适用 Muxvo 重构 · 行数上限 575

## 1. 模块定位

- **一句话**：从终端右侧滑出的轻量文件浏览器，帮用户在不离开终端的前提下快速看清当前项目的目录结构。
- **不用它会怎样**：用户只能靠终端里 `ls` / `find` 来了解项目结构，无法在侧边一眼看到文件层次，也无法双击跳转到文件查看。
- **与相邻模块的分界**：
  - 文件面板的入口、树形展示、展开/折叠、NEW 标记、隐藏文件开关 属于本模块
  - 点击文件后弹出的三栏临时视图（左文件树 / 中预览 / 右终端栏）属于 [M12 FILE_VIEWER]
  - 文件实时变化的底层同步机制与全局刷新体感属于 [M15 APP_RELIABILITY]
  - 偏好设置中"默认显示隐藏文件"的开关默认值 属于 [M14 ONBOARD_PREFS]

## 2. 目标用户与场景

### 主要用户画像

- **CLI 重度用户**：每天长时间在 Claude Code 中工作，需要频繁确认"这个项目下有什么文件"而不想打断当前终端。
- **项目切换者**：同时打开多个终端，每个终端对应不同的仓库，需要在几秒内看清某个终端对应的目录结构。
- **新手**：刚开始用 Muxvo，不习惯命令行，希望有一个熟悉的图形化目录树来确认当前在哪个项目里。

### Top3 使用场景

**场景 1 — 确认工作目录**：用户在终端里准备让 Claude Code 改代码，但不确定自己的工作目录是不是那个对的项目。用户点击终端右上的"文件"按钮，滑出面板，看到顶部显示项目名、下方是熟悉的目录结构，立刻确认无误后关闭面板继续工作。

**场景 2 — 浏览生成的新文件**：用户让 Claude 生成了一批新文件，想快速扫一眼都生成了什么。用户打开文件面板，展开目标文件夹，看到新建文件旁边带"NEW"绿色徽标，一眼分辨哪些是新的，双击其中一个进入预览。

**场景 3 — 查看配置文件内容**：用户想看看项目根目录下的 `package.json`。打开文件面板，在根目录列表里找到 `package.json`，双击。面板关闭并进入三栏临时视图显示内容。

### 使用频率

日常高频。CLI 重度用户每天会打开面板 10-30 次，每次停留 5-30 秒。本模块属于"快速一瞥"型交互，不承担长时间停留的阅读任务。

## 5. 详细需求条目

### REQ-FILE_PANEL-001  从终端标题栏打开文件面板

**触发方式**：用户在某个终端的标题栏右上角点击"文件"按钮（带有文件夹图标，悬停时 tooltip 显示"文件"）。
**前置条件**：该终端存在且显示在屏幕上。
**正常流程**：
  1. 用户点击"文件"按钮。
  2. 屏幕右侧出现面板容器，从屏幕外滑入。
  3. 面板完全就位后显示该终端工作目录的内容。
**用户看到的反馈**：面板以约 0.3 秒从右侧滑入；顶部显示项目名；内容区开始显示文件列表。
**结束状态**：面板停留在打开状态，覆盖在原有终端网格之上；原终端网格仍然可见（半透明覆层在面板外部）。
**异常情况**：
- 目录为空 → 进入空态（REQ-FILE_PANEL-024）。
- 无读取权限 → 进入受限态（REQ-FILE_PANEL-025）。
- 目录路径已失效（例如目录已被删除）→ 显示"此目录为空"空态（退化处理）。

**相关**：[M02-REQ-001]（终端标题栏）

### REQ-FILE_PANEL-002  面板从右侧滑入动画

**触发方式**：任何打开面板的操作。
**前置条件**：面板当前关闭。
**正常流程**：
  1. 面板从屏幕右侧外部（相对位移 100%）滑入到贴齐右边。
  2. 动画持续约 0.3 秒，使用平滑缓动。
  3. 动画结束后面板内容可正常交互。
**用户看到的反馈**：面板像抽屉一样顺滑出现，不是"瞬间出现"，不是"跳动出现"。
**结束状态**：面板占据屏幕右侧，宽度约为屏幕的一个固定列（参见 §7.2）。
**异常情况**：用户在动画期间再次点击任意区域，动画正常完成后再响应新操作（不打断动画）。

### REQ-FILE_PANEL-003  顶部显示项目名

**触发方式**：打开面板时自动显示。
**正常流程**：面板顶部左侧显示项目名，取自终端工作目录路径的最后一段，使用青色高亮字体。
**异常情况**：工作目录无法推断出名称（例如根目录 `/`）→ 显示 `~` 作为兜底。

### REQ-FILE_PANEL-004  列出一级文件和文件夹

**触发方式**：打开面板或切换终端时自动触发。
**前置条件**：目录可读。
**正常流程**：内容区显示该目录下所有非隐藏条目；文件夹用文件夹图标、文件用文件图标；每行显示条目名；若为文件，附带大小元数据。
**用户看到的反馈**：一份整齐的列表，像熟悉的文件管理器侧栏。
**异常情况**：空目录 → 空态；无权限 → 受限态。

### REQ-FILE_PANEL-005  文件夹排序在文件前面

**正常流程**：文件夹统一排在文件前面，两组内部再按名称字母排序。
**用户看到的反馈**：从上往下先看到子目录，再看到文件，顺序可预期。

### REQ-FILE_PANEL-007  默认隐藏以 "." 开头的条目

**触发方式**：打开面板时自动生效。
**前置条件**：用户未手动打开"显示隐藏文件"开关。
**正常流程**：面板加载目录后，自动过滤掉名称以 "." 开头的条目；不显示 `.git`、`.DS_Store`、`.env` 等。
**用户看到的反馈**：目录列表干净、聚焦项目源代码文件。
**异常情况**：用户通过偏好设置预设"显示隐藏文件" → 打开面板时直接显示全部（REQ-FILE_PANEL-016）。
**相关**：[M14-REQ-NNN]（偏好设置默认值）

### REQ-FILE_PANEL-008  展开/折叠文件夹

**触发方式**：用户单击某个文件夹条目。
**前置条件**：该条目是文件夹。
**正常流程**：若当前未展开，读取该文件夹内容并插入到该文件夹下方、缩进一层显示；若当前已展开，隐藏其下方所有缩进条目（包括更深层被展开的子文件夹）。
**用户看到的反馈**：图标从"合上"变"展开"（或反之）；子条目在下方出现或移除；每次展开都会读取最新目录内容。
**异常情况**：
- 点击展开后读取失败 → 该文件夹保持"已展开"图标，但下方无子条目。
- 折叠一个父文件夹 → 其所有后代的展开状态也被清除。

### REQ-FILE_PANEL-010  单击文件打开预览

**触发方式**：用户单击一个文件条目（非文件夹）。
**正常流程**：文件面板立即关闭，屏幕进入三栏临时视图并显示该文件内容。
**用户看到的反馈**：面板消失，屏幕变为左文件树 / 中预览 / 右终端栏的新布局。
**结束状态**：用户进入 [M12 FILE_VIEWER] 的主路径。
**异常情况**：文件读取失败 → 由 [M12 FILE_VIEWER] 负责反馈。
**相关**：[M12-REQ-001]

### REQ-FILE_PANEL-011 ~ 013  三种关闭方式

**触发方式**：以下任一操作均可关闭面板：
- 按下 Esc
- 点击面板右上角的 ✕ 按钮
- 点击面板以外任意区域（半透明覆层）

**正常流程**：面板向屏幕右侧滑出并消失，原终端网格恢复交互。
**用户看到的反馈**：面板顺滑退出，恢复到"打开前"的界面。
**补充说明**：用户正在拖拽条目时，"点击外部关闭"会被临时禁用，以免打断拖拽（参见 REQ-FILE_PANEL-020）。
**异常情况**：面板正在滑入动画中触发关闭 → 等待当前动画完成再关闭。

### REQ-FILE_PANEL-014  切换终端的文件面板无动画

**触发方式**：文件面板当前已为终端 A 打开；用户点击终端 B 的"文件"按钮。
**正常流程**：面板保持打开不关闭；顶部项目名立即切换为终端 B；内容区重新加载终端 B 的目录。
**用户看到的反馈**：没有滑入滑出动画，只有顶部名称和内容区瞬间切换。
**结束状态**：面板显示终端 B 的目录。
**异常情况**：终端 B 目录不可读 → 直接进入受限态或空态。

### REQ-FILE_PANEL-015 / 016  隐藏文件开关与持久化

**触发方式**：用户点击面板顶部的"眼睛"按钮。
**正常流程**：按钮在"显示"和"隐藏"两种图标间切换；内容区立即刷新，显示或隐藏点开头的条目；用户的选择被保存，下次打开任一文件面板时保持相同状态。
**用户看到的反馈**：按钮图标变化（带删除线的眼睛 ↔ 完整的眼睛）；开启状态有高亮底色；tooltip 显示 "Show dotfiles" 或 "Hide dotfiles"。
**异常情况**：刷新过程中目录访问失败 → 面板切换到空态或受限态。
**相关**：[M14-REQ-NNN]（偏好设置默认值）

### REQ-FILE_PANEL-017 ~ 019  右键菜单三项

**触发方式**：用户右键点击文件或文件夹条目。
**正常流程**：弹出原生右键菜单于光标位置；菜单显示"复制路径"、"在 Finder 中打开"；若点击的是文件，额外显示"用默认应用打开"。
**用户看到的反馈**：
- "复制路径"→ 完整路径复制到剪贴板，可立即在终端粘贴。
- "在 Finder 中打开"→ 切换到系统文件管理器并定位到该条目。
- "用默认应用打开"→ 文件被系统默认应用打开（例如 .png 用图片预览）。

**异常情况**：右键点击发生在空白区域 → 不弹菜单。

### REQ-FILE_PANEL-020  拖拽条目到终端

**触发方式**：用户按住某个文件条目开始拖动。
**正常流程**：用户把条目拖到终端区域松开，终端的输入区立即插入该文件的完整路径。
**用户看到的反馈**：拖拽过程中界面有可拖拽的视觉反馈；松开时路径文本出现在终端输入位置。
**异常情况**：拖到非终端区域松开 → 无事发生，面板保持原样。
**相关**：[M05-REQ-NNN]（输入区接收外部文本）

### REQ-FILE_PANEL-021  文件大小显示

**正常流程**：每个文件条目右侧以小字号显示大小。<1KB 显示字节数（`120B`），<1MB 显示 KB（`4.2KB`），≥1MB 显示 MB（`3.5MB`）。
**异常情况**：大小信息缺失 → 不显示元数据区域，条目仍可点击。

### REQ-FILE_PANEL-022  不同文件类型使用不同图标

**正常流程**：按类型选择图标：文件夹合上 📁 / 展开 📂；Markdown（.md）📝；JSON（.json）⚙️；其它文件 📄。
**异常情况**：不覆盖代码/图片/PDF/压缩包/二进制的专属图标 → 统一用通用文件图标（详见 §9 的"明确不支持"）。

### REQ-FILE_PANEL-023  NEW 徽标标记新增条目

**触发方式**：面板打开期间目录中新增文件被面板捕获时。
**正常流程**：新文件条目右侧出现绿色小徽标 "NEW"。
**用户看到的反馈**：徽标为绿色、小字号，明显但不刺眼。
**结束状态**：徽标保持到用户关闭面板或面板下次完整刷新为止。
**异常情况**：新文件在面板未打开期间产生 → 下次打开时不再标记为 NEW（仅面板打开期间的新增会被标记）。
**相关**：[M15-REQ-NNN]

### REQ-FILE_PANEL-024  空目录空态提示

**触发方式**：面板或展开的某目录没有任何可显示条目。
**正常流程**：内容区显示居中的空文件夹图标 + 文案。
**用户看到的反馈**：
> 空态文案："此目录为空"

### REQ-FILE_PANEL-025  无权限受限态提示

**触发方式**：面板尝试读取目录时被系统拒绝。
**正常流程**：内容区显示锁图标 + 文案。
**用户看到的反馈**：
> 受限态文案："无法读取此目录，请检查权限"
> 图标：🔒
**异常情况**：用户需要手动到系统设置里授权；本模块不提供授权入口（详见 §10）。

### REQ-FILE_PANEL-027  展开子目录时的加载反馈

**触发方式**：用户单击一个内容较多的文件夹。
**前置条件**：无。
**正常流程**：
  1. 用户点击 → 图标立即变为"展开"状态。
  2. 若读取在可感知时间内完成（约数百毫秒），直接显示子条目。
  3. 若读取时间较长，界面不会阻塞，用户可以继续滚动面板或点击其它条目。
**用户看到的反馈**：无"整个面板卡住"的感受；图标立即响应；子条目就绪后一次性插入。
**结束状态**：子条目显示完毕。
**异常情况**：读取失败 → 该文件夹保持"已展开"外观但无子条目。

## 6. 主要用户旅程

### Journey 1：新手第一次打开文件面板

1. **你** 刚创建了第一个终端，`cd` 到一个项目目录。你看到终端标题栏右上角有一个黄色小按钮上带文件夹图标。
   → **你所见**：按钮悬停时 tooltip 显示"文件"。
   → **你感受**：好奇这是干什么的。
2. **你** 点击"文件"按钮。
   → **你所见**：一个面板从屏幕右侧滑入，约半秒就位。顶部是一个青色的项目名，下方是文件树。
   → **你感受**：像熟悉的 VS Code 侧栏，瞬间有安全感。
3. **你** 扫一眼列表，发现文件夹都在最上面，看到 `src/`、`docs/`、`package.json`、`README.md`。
   → **你所见**：条目整齐、图标一致。
   → **你感受**："哦，这就是这个项目的结构"。
4. **你** 点击 `src/` 文件夹。
   → **你所见**：图标从 📁 变成 📂，下方缩进一层出现更多条目。
   → **你感受**：交互预期对得上。
5. **你** 点击一个 `.md` 文件。
   → **你所见**：面板滑出消失，屏幕进入三栏临时视图显示文件内容。
   → **你感受**：比在终端里 `cat` 好用多了。
6. **你** 按 Esc。
   → **你所见**：三栏视图关闭，回到终端网格。
   → **你感受**：流畅。一次看文件不到 10 秒。

### Journey 2：老手日常高频扫视

1. **你** 正在和 Claude 对话。Claude 说"我已生成 3 个文件到 `src/components/`"。
   → **你所见**：终端内 Claude 的输出滚动。
   → **你感受**：想确认一眼到底生成了什么。
2. **你** 直接点当前终端的"文件"按钮。
   → **你所见**：面板滑入，显示当前 cwd。
3. **你** 点击 `src/`，再点击 `components/`。
   → **你所见**：两层都展开，看到三个带绿色 `NEW` 徽标的新文件。
   → **你感受**："果然生成了，名字也对"。
4. **你** 右键点击其中一个新文件，选择"复制路径"。
   → **你所见**：菜单消失。
5. **你** 按 Esc 关闭面板，在终端粘贴刚才复制的路径，让 Claude 再对这个文件做调整。
   → **你所见**：路径出现在终端输入位置。
   → **你感受**：整个过程不到 5 秒，没离开工作流。

### Journey 3：遇到空目录/无权限的恢复

1. **你** 创建了一个新终端，工作目录刚好是一个空文件夹。点击"文件"按钮。
   → **你所见**：面板滑入，但内容区显示空文件夹图标和"此目录为空"。
   → **你感受**：虽然没内容但能理解。
2. **你** 切到另一个终端（它的 cwd 是系统保护目录），点它的"文件"按钮。
   → **你所见**：面板保持打开，但顶部名称变了，内容区显示锁图标和"无法读取此目录，请检查权限"。
   → **你感受**：知道这不是 Muxvo 的 bug，是系统权限问题。
3. **你** 按 Esc 关闭面板，继续用终端。没有报错、没有白屏、没有卡死。
   → **你感受**：恢复路径很顺。

## 7. 界面规格

### 7.1 页面/面板清单

| 名称 | 作用 | 进入方式 | 退出方式 |
|---|---|---|---|
| 文件面板 | 显示当前终端工作目录的文件树 | 点击终端标题栏的"文件"按钮 | 按 Esc / 点击 ✕ / 点击面板外部 |

### 7.2 关键区域

面板结构从上到下分为"顶栏 / 主区"两段：

**顶栏（约 48 像素高）**：
- 左侧：项目名（青色、等宽字体）。
- 右侧按钮组：
  - 眼睛图标按钮（隐藏文件开关，普通状态 vs 激活状态有视觉区分）
  - ✕ 关闭按钮（琥珀色底 + 强调边框，易于识别）

**主区（占剩余高度）**：
- 纵向列表，每个条目一行。
- 行内元素：图标 → 名称 → （可选）元数据（文件大小） → （可选）NEW 徽标。
- 缩进：每一层嵌套增加固定缩进。
- 超出面板高度时主区可纵向滚动。

**整体容器**：
- 位置：贴右侧边缘，从菜单栏下方到屏幕底部。
- 宽度：固定约 320 像素的一列。
- 背景：半透明模糊玻璃（保持可看到后面的终端轮廓）。
- 右边缘有细线分隔，左侧有阴影与终端网格区分。

### 7.3 五态规格（文件面板）

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 空文件夹图标 + 文案"此目录为空" | 关闭面板 / 切到其它终端 |
| **加载态** | 面板已滑入就位但内容区暂时为空（通常瞬时，用户很少察觉） | 等待（通常几百毫秒内完成） |
| **正常态** | 项目名 + 文件树（文件夹在前，文件在后） | 展开/折叠、点击文件、右键、拖拽、切换隐藏文件 |
| **错误态** | 锁图标 + "无法读取此目录，请检查权限" | 关闭面板 / 切到其它终端 |
| **受限态** | 等同于错误态（本模块的错误来源主要就是权限） | 同上 |

### 7.4 文案示例

> 面板标题（正常）："muxvo"（项目目录最后一段名称，青色）
> 面板标题（兜底）："~"
> 隐藏文件按钮 tooltip（未激活）："Show dotfiles"
> 隐藏文件按钮 tooltip（已激活）："Hide dotfiles"
> NEW 徽标："NEW"（绿色小字号）
> 空态："此目录为空"
> 受限态："无法读取此目录，请检查权限"
> 右键菜单项："复制路径" / "在 Finder 中打开" / "用默认应用打开"

## 8. 状态与交互规则

### 8.1 可见状态清单

- **面板关闭**：用户完全看不到面板。
- **面板正在滑入**：面板从屏幕右侧向内移动（约 0.3 秒）。
- **面板打开**：面板完全就位，可交互。
- **面板正在滑出**：面板向屏幕右侧移动并消失（约 0.3 秒）。
- **目录加载中**：面板打开但内容区暂时为空（用户通常几乎感知不到）。
- **目录空**：内容区显示空态文案。
- **目录受限**：内容区显示受限态文案。
- **文件夹已展开**：图标为"展开"，其下方显示子条目。
- **文件夹已折叠**：图标为"合上"，其下方无子条目。
- **隐藏文件开关关闭**：列表过滤掉点开头条目。
- **隐藏文件开关开启**：列表显示全部条目。

### 8.2 状态切换触发

- 用户点击"文件"按钮 → 面板从关闭进入正在滑入 → 打开。
- 用户点击 ✕ / 按 Esc / 点击面板外部 → 面板从打开进入正在滑出 → 关闭。
- 用户点击另一终端的"文件"按钮（面板已开）→ 内容切换，状态不变。
- 用户点击文件夹 → 该文件夹切换展开 ↔ 折叠。
- 用户点击文件 → 面板关闭 + 进入三栏临时视图（跳转到 [M12]）。
- 用户点击眼睛按钮 → 列表立即重绘。
- 目录读取失败 → 内容区从加载中切到受限态。

### 8.3 快捷键与手势

| 按键/手势 | 作用 | 前置条件 |
|---|---|---|
| Esc | 关闭文件面板 | 面板打开 |
| 单击文件夹 | 展开/折叠 | 面板打开 |
| 单击文件 | 打开三栏临时视图 | 面板打开 |
| 右键文件/文件夹 | 弹出上下文菜单 | 面板打开 |
| 按住拖拽文件 → 松开到终端 | 把路径插入终端输入 | 面板打开 |

### 8.4 多窗口/多标签行为

- 同一窗口同时最多存在一个文件面板。已打开的面板被另一终端接管时不重开，只刷新内容。
- 多个 Muxvo 窗口各自独立，彼此的文件面板互不影响。

## 9. 边界、限制与异常

### 数量限制

- 同一窗口同一时刻最多显示一个文件面板。
- 单层目录显示数量没有硬性上限，但极大目录（例如 2000+ 条）用户可感知到"从展开到可滚动"之间略有延迟；面板不会因此卡住。
- 面板宽度固定约 320 像素，不可调整。

### 明确不支持

- 不支持在文件面板内新建、删除、重命名文件/文件夹。
- 不支持在文件面板内对条目拖拽排序。
- 不支持区分"代码文件 / 图片 / PDF / 压缩包 / 二进制"的专属图标，除 Markdown 与 JSON 外一律使用通用文件图标。
- 不支持搜索/过滤文件名（面板没有搜索框）。
- 不支持显示 Git 状态徽章（修改/新增/删除的 Git 颜色）。
- 不支持预览文件内容缩略图。

### 错误提示文案

| 用户遇到的情况 | 用户看到的提示 | 用户能做的事 |
|---|---|---|
| 目录没有任何文件 | "此目录为空"（空文件夹图标） | 关闭面板或切其它终端 |
| 目录无读取权限 | "无法读取此目录，请检查权限"（锁图标） | 在系统设置授权后重新打开面板 |
| 某个子文件夹展开后读取失败 | 图标保持展开态，下方无子条目 | 再次点击折叠后重试 |
| 动画期间误点 | 不打断动画，完成后才响应下一个操作 | 继续正常操作 |

### 数据丢失风险

本模块只负责展示，不对用户文件进行任何写入或删除。因此不存在本模块导致数据丢失的场景。

## 10. 明确不做的事（Out of Scope）

- **搜索/过滤框**：不提供按名称快速搜索文件的输入框。理由：面板主打"一瞥"，长项目搜索已由终端和其它模块覆盖。**再考虑**：超过 500 个条目的目录是否需要搜索，由后续需求评审决定。
- **Git 状态徽章**：不标记文件的 Git 修改状态。理由：Muxvo 定位是 CLI 工具工作台，不承担 Git 客户端功能。**再考虑**：当 AI 频繁改动多文件时再引入。
- **文件夹拖拽排序**：用户不能通过拖拽重排文件顺序。理由：文件顺序由本地存储决定，重排会造成心智负担。
- **多选 / 批量操作**：用户不能同时选中多个文件执行操作。理由：面板是查看工具而非管理工具。
- **权限授权引导**：本模块不提供"一键授权系统目录"的按钮。理由：这属于操作系统级别的授权，强制引入会增加复杂度，用户通过系统设置自行处理更稳妥。
- **收藏/置顶某个文件夹**：不支持固定常用目录到顶端。理由：每个面板对应的是当前终端的工作目录，不是跨项目的通用浏览器。
- **打开面板后自动展开一层**：默认只展开根目录，不自动展开任何子目录。理由：避免一次性渲染过多条目，保持"轻量一瞥"的定位。**再考虑**：新手引导阶段是否默认展开 `src/` 由 [M14] 决策。

### 11.3 待确认项

- **权限不足的反馈强度**：当前已上线版本中，目录读取失败时面板只显示空列表、不给提示；测试文档要求显示受限态文案（锁图标 + "无法读取此目录，请检查权限"）。本 PRD 按测试文档的期望描述。重构时应以 PRD 为准实现受限态。**待与产品对齐**：是否还需要提供"重试"按钮。
- **NEW 徽标的完整触发条件**：当前界面里有 NEW 徽标的显示槽位，但"何时标记 / 何时消失"在上线版本中尚未完全连线。本 PRD 假设"面板打开期间新增的文件才会被标记，关闭面板后重置"。**待与产品对齐**：是否希望 NEW 在用户主动浏览后自动消失。
- **大目录加载反馈**：当前上线版本未展示任何加载动画。本 PRD 将"加载态"描述为"通常几乎无感知"，但对于 2000+ 条目的超大目录是否需要明确的加载指示，**待与产品对齐**。
- **拖拽到终端之外的目标**：现有行为允许拖到终端，其它目标尚未定义（例如拖到富编辑器、拖到浏览器）。本 PRD 只描述"拖到终端"的主路径。其它目标由 [M05] / [M06] 决定。
