# A5. UI 五态交叉表

> 本附录汇总 15 个模块中主要页面的五种状态（空 / 加载 / 正常 / 错误 / 受限），便于 UI 设计时一次性覆盖。
> 每个模块的详细五态规格见模块 PRD 的 §7.3。

---

## 五态定义

| 状态 | 含义 |
|---|---|
| **空态** | 从未有过数据 / 全新安装 |
| **加载态** | 数据正在获取或渲染 |
| **正常态** | 有内容、能操作 |
| **错误态** | 数据加载失败 / 操作失败 |
| **受限态** | 权限不足 / 功能被禁用 / 需要先做某事 |

## 常见五态规格

### 空态规范
- **视觉**：中央图标（灰色或品牌色）+ 一句标题 + 一句副标题 + 主按钮
- **文案模板**："还没有 XXX" + "点击 YYY 开始"
- **按钮**：必须有一个引导用户下一步的 CTA

### 加载态规范
- **瞬时（< 400ms）**：不显示指示（避免闪烁）
- **短时（400ms - 3s）**：spinner 或骨架屏
- **长时（> 3s）**：进度条 + 可中断按钮
- **超长（> 15s）**：弹出"操作未响应"浮层（M15 统一规范）

### 错误态规范
- **小错误**：inline 红底文字 + 重试按钮
- **中错误**：横幅 + 具体文案 + 操作指引
- **大错误**：错误对话框（M15-REQ-021 三档视觉）

### 受限态规范
- **功能禁用**：灰色按钮 + tooltip 说明原因
- **权限不足**：锁图标 + 引导去授权
- **登录要求**：本次 PRD 不涉及（V2 功能）

## 状态切换触发

| 源状态 | 事件 | 目标状态 |
|---|---|---|
| 空态 | 有数据到达 | 加载态或正常态 |
| 加载态 | 数据就绪 | 正常态 |
| 加载态 | 加载失败 | 错误态 |
| 正常态 | 操作失败 | 错误态（inline）+ 保留正常态框架 |
| 正常态 | 数据被清空 | 空态 |
| 错误态 | 用户重试成功 | 正常态 |
| 受限态 | 用户授权 | 正常态 |

---

## 五态设计检查清单

UI 设计时，每个主要页面都要问一遍：
1. ✅ 用户第一次打开看到什么（**空态**）
2. ✅ 数据正在来的路上看到什么（**加载态**）
3. ✅ 一切正常看到什么（**正常态**）
4. ✅ 网络断了/数据坏了看到什么（**错误态**）
5. ✅ 没权限或功能被禁看到什么（**受限态**）

任何一态缺失，都需在对应模块的 §7.3 补足或明确标注"不适用 + 理由"。
