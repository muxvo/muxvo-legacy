# A4. 用户可见错误文案目录

> 本附录汇总所有用户可能遇到的错误提示。文案应统一遵循 M15 APP_RELIABILITY 定义的三档基调：信息 / 警告 / 错误。

> 原则（来自 [M15 §9]）：**能降级的都不弹窗，只有需要用户立刻决定的才弹错误对话框。**

---

## 1. 视觉档位

| 档位 | 用户视觉 | 触发场景 |
|---|---|---|
| **信息（蓝）** | 顶部横幅 / 轻量 toast | 非关键通知（同步完成、更新可用） |
| **警告（黄）** | 顶部横幅 / Inline 提示 | 需关注但不阻塞（离线、资源占用高） |
| **错误（红）** | 对话框 / Inline 高亮 | 需用户立刻决定（文件损坏、关闭确认、发送失败） |

统一视觉规范见 [M15-REQ-APP_RELIABILITY-021/022]。

## 8. 文案口吻规范

### 必须
- 简短：≤30 字
- 指向动作：告诉用户"接下来做什么"
- 使用"用户"或"你"，禁用"系统"
- 中英文对应，保持语义一致

### 禁止
- 技术术语（进程 / 线程 / Exception / NullPointer 等）
- 代码片段或错误码
- "未知错误"（必须给出可能原因）
- "请稍后再试"（没有具体指引，不推荐）
- 情绪化词汇（"抱歉"、"糟糕"）

### 错误文案对照

| ❌ 不推荐 | ✓ 推荐 |
|---|---|
| "Error: EACCES" | "无法访问此目录" |
| "未知错误" | "发送失败：终端未就绪" |
| "请稍后再试" | "按 Enter 重试" |
| "进程崩溃" | "终端意外退出" |
| "JSON 解析失败" | "此配置无法识别" |
