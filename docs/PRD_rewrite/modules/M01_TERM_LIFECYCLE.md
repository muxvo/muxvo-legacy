# M01 TERM_LIFECYCLE – 终端生命周期 PRD

> 版本 v1.0 · 适用 Muxvo 重构 · 行数预算 467-632 行

## 1. 模块定位

- **一句话**：管理"一个终端从被创建到被关闭"全过程，让用户随时知道终端在哪个目录、处于什么状态、可以怎样命名和收尾。
- **不用它会怎样**：用户无法新建终端、关不掉跑着任务的终端、看不出哪个终端在等输入、也无法把多个终端取上有意义的名字，整个工作台会退化成一个静态壳子。
- **与相邻模块的分界**：
  - 单个终端的创建 / 关闭 / 重启 / 重命名 / 工作目录追踪 / 状态点显示 / 默认启动数 属于本模块
  - 多个终端在屏幕上的网格平铺、拖拽排序、间隙拖拉调整 属于 [M02 TERM_GRID]
  - 双击放大单个终端、侧栏缩略图切换 属于 [M03 TERM_FOCUS]
  - 等待输入的红色徽标、Dock 角标、应用层提醒 属于 [M04 TERM_NOTIFY]
  - 终端右上角"文件"按钮唤起的目录树面板 属于 [M11 FILE_PANEL]
  - 偏好设置中"启动终端数量"的默认值定义 属于 [M14 ONBOARD_PREFS]
  - 关闭确认对话框的通用视觉规范 属于 [M15 APP_RELIABILITY]

## 2. 目标用户与场景

### 主要用户画像

- **CLI 重度用户**：每天保持 4-12 个终端常驻，需要快速地新建一个终端跑个临时命令，再快速关掉。对快捷键、状态点、命名都很敏感。
- **多项目并行者**：同时跟踪多个仓库或多个工作分支，需要给每个终端贴上有意义的名字（例如 "frontend"、"测试服日志"），而不是只看到一长串路径。
- **新手**：第一次打开 Muxvo，期望"打开就能用"，不希望被"还要先新建一个终端"挡住。

### Top3 使用场景

**场景 1 — 跑个临时命令**：用户正在主终端里写代码，突然想跑一个 `git status`，但又不想中断当前命令。用户按 ⌘T 起一个新终端，跑完命令，再按关闭按钮把它收掉。整个过程不需要切到菜单栏，眼睛不离开屏幕中部。

**场景 2 — 给终端贴名字**：用户同时开着 5 个终端，每个终端的工作目录看起来差不多（都是 `~/Nutstore/.../muxvo/...`），用户记不清哪个是 dev、哪个是 release。用户依次双击每个终端的标题区，输入 "dev"、"release"、"日志"、"db"、"临时"，按回车保存，从此一眼分辨。

**场景 3 — 关掉一个跑着脚本的终端**：用户开了一个长跑脚本，发现脚本卡住了，决定强制结束。用户点 ✕ 按钮，弹出确认对话框，用户确认后终端立即消失。下次启动 Muxvo 不会再恢复这个终端。

### 使用频率

日常高频。CLI 重度用户每天会触发新建/关闭终端 20-50 次，状态点的颜色变化每分钟都有，命名是中频（每个项目大约一次），重启是低频（出问题才用）。

## 3. 用户故事

```

Given  用户第一次安装并打开 Muxvo
When   主界面加载完成

US-TERM_LIFECYCLE-002   通过快捷键新建终端
Given  用户已经在使用 Muxvo
When   用户按下 ⌘T（macOS）或 Ctrl+T（其他系统）
Then   屏幕上出现一个新终端，目录是偏好里的默认目录或主目录，且新终端被自动选中

US-TERM_LIFECYCLE-003   通过底栏 + 按钮新建终端
Given  用户已经在使用 Muxvo
When   用户点击屏幕底部状态条右侧的"+"按钮
Then   屏幕上出现一个新终端，效果与按 ⌘T 相同

US-TERM_LIFECYCLE-004   通过悬浮控件新建终端
Given  用户处于平铺模式
When   用户点击右下角悬浮的"+ 新建终端"控件
Then   屏幕上出现一个新终端

US-TERM_LIFECYCLE-005   关闭一个空闲终端
Given  终端里没有正在跑的任务，标题区状态点为绿色
When   用户点击该终端标题栏右侧的红色 ✕ 按钮
Then   终端立即从屏幕上消失，无确认询问

US-TERM_LIFECYCLE-006   关闭一个有任务的终端
Given  终端里正在跑一个命令（不是默认命令行环境）

Given  终端标题区显示灰色斜体占位符"命名..."

Given  终端已经有一个名字，例如"前端开发"

Then   名字更新为"backend"

US-TERM_LIFECYCLE-009   取消编辑名字
Given  用户正在编辑名字框，原值是"前端开发"
When   用户输入了一些新字，然后按 Esc
Then   编辑框关闭，名字恢复为编辑前的"前端开发"

US-TERM_LIFECYCLE-010   清空名字
Given  终端已有名字"backend"
When   用户点击名字进入编辑，全选删除后按回车
Then   名字消失，标题区重新显示"命名..."占位符

US-TERM_LIFECYCLE-011   终端目录变化

US-TERM_LIFECYCLE-012   通过路径区切换工作目录

US-TERM_LIFECYCLE-014   等待输入状态变化
Given  终端跑着一个命令，正常运行
When   命令开始等待用户输入（例如 yes/no 提示）
Then   终端标题区的状态点变成红色脉冲，标题区右侧出现红色数字徽标"1"

US-TERM_LIFECYCLE-015   关闭后不再恢复

When   用户在稍后重启 Muxvo
```

## 5. 详细需求条目

### REQ-TERM_LIFECYCLE-001 首次启动自动创建终端

**触发方式**：用户第一次安装并打开 Muxvo。
**前置条件**：用户偏好里没改过"启动终端数量"，没改过"默认终端目录"。
**正常流程**：
  1. 用户双击 Muxvo 图标
  2. 主界面加载完成后，屏幕中部出现一个全屏大小的终端
  3. 终端的标题区显示当前工作目录（默认是用户的主目录），状态点为绿色
**用户看到的反馈**：终端有进入动画，约 0.6 秒缓动出现，命令行光标已就绪。
**结束状态**：用户可以直接在终端里输入命令。
**异常情况**：终端创建失败 → 主区显示空态 + "+"按钮 + 提示"暂无终端，点击 + 新建"。
**相关**：REQ-TERM_LIFECYCLE-002、REQ-TERM_LIFECYCLE-008、[M14-REQ-ONBOARD_PREFS-008]

### REQ-TERM_LIFECYCLE-002 启动时按偏好数量创建终端

**触发方式**：每次启动 Muxvo（不是从崩溃恢复）。
**前置条件**：偏好里设置了"启动终端数量"的值（1-20 之间）。
**正常流程**：
  1. 用户启动 Muxvo
  2. 按照偏好里的数量自动创建对应个数的终端
  3. 所有终端落在偏好"默认终端目录"里，没设的话用主目录
**用户看到的反馈**：所有终端依次出现，依次有进入动画。
**结束状态**：网格内出现 N 个并列的终端。
**异常情况**：偏好值大于 20 → 取 20；小于 1 → 取 1。
**相关**：REQ-TERM_LIFECYCLE-030、[M14-REQ-ONBOARD_PREFS-008]、[M15-REQ-APP_RELIABILITY-021]

### REQ-TERM_LIFECYCLE-005 快捷键 ⌘T / Ctrl+T 新建

**触发方式**：用户在 Muxvo 主界面任意位置按 ⌘T（macOS）或 Ctrl+T（其他系统）。
**前置条件**：当前终端数量小于 20。
**正常流程**：
  1. 用户按下快捷键
  2. 屏幕上立刻出现一个新终端，目录为偏好默认目录或主目录
  3. 新终端被自动选中（标题栏出现选中高亮）
**用户看到的反馈**：新终端从加入位置缓动出现，状态点为绿色。
**结束状态**：网格自动重排，新终端就绪可输入。
**异常情况**：已达 20 个上限 → 快捷键无效，无任何变化（按钮已变灰）。
**相关**：REQ-TERM_LIFECYCLE-006、REQ-TERM_LIFECYCLE-013、REQ-TERM_LIFECYCLE-030

### REQ-TERM_LIFECYCLE-006 底栏 + 按钮新建

**触发方式**：用户点击屏幕底部状态条右侧的圆形"+"按钮。
**前置条件**：当前终端数量小于 20。
**正常流程**：
  1. 用户单击 + 按钮
  2. 屏幕上出现一个新终端
**用户看到的反馈**：与 REQ-TERM_LIFECYCLE-005 一致。
**结束状态**：同上。
**异常情况**：已达 20 个上限 → 按钮变灰、不可点击，悬浮提示"已达最大 20 个终端"。
**相关**：REQ-TERM_LIFECYCLE-005、REQ-TERM_LIFECYCLE-030、REQ-TERM_LIFECYCLE-031

### REQ-TERM_LIFECYCLE-009 关闭按钮（标题栏右侧 ✕）

**触发方式**：用户点击终端标题栏右侧的红色 ✕ 按钮。
**前置条件**：终端处于绿色（空闲）状态。
**正常流程**：
  1. 用户单击 ✕
  2. 终端立即从屏幕上消失，无确认询问
  3. 网格自动重排剩余终端
**用户看到的反馈**：被关闭的终端瞬间消失，相邻终端平滑补位。
**结束状态**：终端总数 -1，底栏计数同步刷新。
**异常情况**：终端里有正在跑的命令 → 进入 REQ-TERM_LIFECYCLE-010 的确认流程。
**相关**：REQ-TERM_LIFECYCLE-010、REQ-TERM_LIFECYCLE-011、REQ-TERM_LIFECYCLE-031

### REQ-TERM_LIFECYCLE-010 关闭前检查是否有任务

**触发方式**：用户在一个跑着命令的终端上点击 ✕。
**前置条件**：终端的当前活动命令不是默认命令行环境。
**正常流程**：
  1. 用户点 ✕
  2. 屏幕中央弹出确认对话框
  3. 用户选择"确定"或"取消"
**用户看到的反馈**：对话框带半透明遮罩，主体居中，文案如"确定关闭此终端？"。
**结束状态**：见 REQ-TERM_LIFECYCLE-011。
**异常情况**：用户点遮罩或按 Esc → 等同"取消"。
**相关**：REQ-TERM_LIFECYCLE-011、REQ-TERM_LIFECYCLE-012、[M15-REQ-APP_RELIABILITY-021]

### REQ-TERM_LIFECYCLE-011 关闭确认对话框

**触发方式**：见 REQ-TERM_LIFECYCLE-010。
**前置条件**：对话框已经弹出。
**正常流程**：
  1. 用户阅读正文"确定关闭此终端？"
  2. 用户点击"确定"或"取消"
**用户看到的反馈**：
  - "取消"按钮：低视觉权重的次要按钮
  - "确定"按钮：高视觉权重的主按钮
**结束状态**：
  - 选"确定"：终端被强制收掉，对话框关闭
  - 选"取消"：对话框关闭，终端保持原状
**异常情况**：用户点对话框外部 → 等同"取消"。
**相关**：REQ-TERM_LIFECYCLE-012、[M15-REQ-APP_RELIABILITY-021]

### REQ-TERM_LIFECYCLE-013 标题区显示工作目录

**触发方式**：终端创建后或用户切换目录后。
**前置条件**：终端处于正常运行状态。
**正常流程**：
  1. 标题区在状态点和名字之间显示当前目录
  2. 主目录会被替换为 `~`
  3. 路径段超过 3 段时，中间段用 `…` 省略
**用户看到的反馈**：路径文字使用青色突出显示，鼠标悬浮显示完整路径。
**结束状态**：用户一眼看到当前目录的关键段（首段 + 末段）。
**异常情况**：路径包含未知字符 → 直接原样显示，不报错。
**相关**：REQ-TERM_LIFECYCLE-014、REQ-TERM_LIFECYCLE-015、REQ-TERM_LIFECYCLE-016

### REQ-TERM_LIFECYCLE-014 工作目录自动更新

**触发方式**：用户在终端里输入 `cd <某目录>` 并执行。
**前置条件**：终端处于命令行环境，可识别 cd 命令。
**正常流程**：
  1. 用户输入 cd 命令
  2. 标题区路径在 1 秒内更新为新目录
  3. 文件按钮、Worktree 浮层等都跟着用新目录
**用户看到的反馈**：路径文字直接变化，无明显闪烁，无加载动画。
**结束状态**：标题区显示新目录的简写。
**异常情况**：cd 失败（例如目录不存在）→ 路径不变。
**相关**：REQ-TERM_LIFECYCLE-013、REQ-TERM_LIFECYCLE-040

### REQ-TERM_LIFECYCLE-017 点击路径切目录

**触发方式**：用户点击标题区的路径文字。
**前置条件**：终端处于平铺模式（聚焦模式下不响应点击）。
**正常流程**：
  1. 用户点击路径
  2. 路径下方弹出工作目录浮层
  3. 用户在浮层中选一个快捷路径或点"浏览..."选目录
  4. 浮层关闭，终端目录切到新位置
**用户看到的反馈**：浮层标题为"切换工作目录"，"当前:"开头的一行展示完整当前路径。
**结束状态**：终端工作目录变化，标题区路径同步更新。
**异常情况**：终端不是常规命令行环境 → 浮层提示无法切换，要求用户先退出当前命令。
**相关**：REQ-TERM_LIFECYCLE-018、REQ-TERM_LIFECYCLE-019

### REQ-TERM_LIFECYCLE-020 状态点（绿/灰/红）

**触发方式**：终端忙碌状态变化时自动刷新。
**前置条件**：无。
**正常流程**：
  1. 用户查看任意终端的标题区左侧
  2. 看到一个直径约 6 像素的圆点
**用户看到的反馈**：
  - **绿色 + 缓慢呼吸光晕**：终端正在运行（命令行就绪 / 命令在跑）
  - **灰色（无动画）**：终端处于空闲、停止或断开
  - **红色 + 快速呼吸光晕**：终端正在等待用户输入（详见 [M04 TERM_NOTIFY]）
**结束状态**：颜色随状态实时变化。
**异常情况**：终端状态长时间无变化 → 颜色保持。
**相关**：REQ-TERM_LIFECYCLE-021、REQ-TERM_LIFECYCLE-022、[M04-REQ-TERM_NOTIFY-001]

### REQ-TERM_LIFECYCLE-023 自定义名称编辑入口

**触发方式**：用户点击标题区的"命名..."占位符或已有名字。
**前置条件**：终端处于平铺模式（聚焦模式只显示名字，不允许编辑）。
**正常流程**：
  1. 用户单击占位符或名字
  2. 占位符变成可编辑输入框，焦点进入输入框
  3. 输入框内显示原值（占位符状态时为空）
**用户看到的反馈**：占位符是灰色斜体"命名..."；输入框边框可见，光标闪烁。
**结束状态**：进入编辑态，等待用户输入。
**异常情况**：聚焦模式下点击 → 不响应，仅显示，不进入编辑。
**相关**：REQ-TERM_LIFECYCLE-024、REQ-TERM_LIFECYCLE-026、REQ-TERM_LIFECYCLE-027

### REQ-TERM_LIFECYCLE-024 名字 Enter 保存

**触发方式**：用户在编辑名字的输入框里按回车。
**前置条件**：处于编辑态。
**正常流程**：
  1. 用户输入新名字
  2. 用户按回车
  3. 输入框关闭，名字以普通文字显示
**用户看到的反馈**：编辑框立刻收起，新名字出现在标题区。
**结束状态**：名字已被保存，下次启动仍可见。
**异常情况**：输入为空时按回车 → 保存为空，回到占位符态（详见 REQ-TERM_LIFECYCLE-027）。
**相关**：REQ-TERM_LIFECYCLE-025、REQ-TERM_LIFECYCLE-028

### REQ-TERM_LIFECYCLE-026 名字 Esc 取消

**触发方式**：用户在编辑名字的输入框里按 Esc。
**前置条件**：处于编辑态。
**正常流程**：
  1. 用户已经输入了一些字（也可能没有）
  2. 用户按 Esc
  3. 输入框关闭，名字恢复为编辑前的值
**用户看到的反馈**：与 REQ-TERM_LIFECYCLE-024 相同的视觉收起，但内容是回滚。
**结束状态**：名字与编辑前完全一致。
**异常情况**：编辑前名字本来就为空 → 恢复为占位符。
**相关**：REQ-TERM_LIFECYCLE-024、REQ-TERM_LIFECYCLE-027

### REQ-TERM_LIFECYCLE-030 同时最多 20 个终端

**触发方式**：用户尝试新建第 21 个终端。
**前置条件**：当前已经有 20 个终端。
**正常流程**：
  1. 用户按 ⌘T 或点击 + 按钮
  2. 没有任何新终端被创建
  3. 底栏 + 按钮变灰，鼠标悬浮显示提示
**用户看到的反馈**：按钮灰色不可点击；悬浮提示文案"已达最大 20 个终端"。
**结束状态**：终端总数仍为 20。
**异常情况**：用户先关掉一个，按钮立刻恢复正常。
**相关**：REQ-TERM_LIFECYCLE-005、REQ-TERM_LIFECYCLE-006、REQ-TERM_LIFECYCLE-013

### REQ-TERM_LIFECYCLE-033 文件按钮入口

**触发方式**：用户点击终端标题栏右侧的"文件夹"图标按钮。
**前置条件**：终端处于平铺或聚焦的常规状态。
**正常流程**：
  1. 用户单击"文件夹"图标
  2. 屏幕右侧滑出文件面板，显示当前终端的工作目录
**用户看到的反馈**：按钮是琥珀色胶囊形图标按钮，鼠标悬浮显示提示"文件"。
**结束状态**：用户进入 [M11 FILE_PANEL] 流程。
**异常情况**：详见 [M11-REQ-FILE_PANEL-001]。
**相关**：[M11-REQ-FILE_PANEL-001]、REQ-TERM_LIFECYCLE-034

### REQ-TERM_LIFECYCLE-035 Worktree 切换入口

**触发方式**：当前终端的工作目录处于一个 Git 仓库内时自动出现。
**前置条件**：终端目录是 Git 仓库。
**正常流程**：
  1. 用户看到标题栏右侧多了一个"分支"图标按钮
  2. 用户单击该按钮
  3. 按钮下方弹出 Worktree 浮层
**用户看到的反馈**：按钮使用分支形小图标，浮层标题为 "Worktrees"，列出主分支与所有子工作树。
**结束状态**：用户选择某个分支或创建新分支后，会新开一个终端切到对应目录（详见 REQ-TERM_LIFECYCLE-037、REQ-TERM_LIFECYCLE-038）。
**异常情况**：仓库过大检测到 .git 目录较大时，浮层顶部出现警告"创建可能较慢"。
**相关**：REQ-TERM_LIFECYCLE-036、REQ-TERM_LIFECYCLE-037、REQ-TERM_LIFECYCLE-038

## 6. 主要用户旅程

### Journey 1：第一次打开 Muxvo

1. **你**双击 Muxvo 图标
   → **你看到**：主界面加载完成，屏幕中部已经躺着一个全屏大小的终端，光标在闪
   → **你感受**："开门见山，不用我先点新建。"
2. **你**抬头看终端标题栏
   → **你看到**：左侧一个绿色小圆点，旁边是 `~` 路径，再后面是灰色斜体的"命名..."
   → **你感受**："噢，这是我的主目录，可以直接干活。"
3. **你**输入 `cd projects/muxvo`
   → **你看到**：路径区在不到 1 秒内变成 `~/projects/muxvo`
   → **你感受**："标题会跟着我走。"
4. **你**点击"命名..."，输入 "muxvo"，按回车
   → **你看到**：占位符变成 "muxvo"，与路径之间用 `·` 分隔
   → **你感受**："以后这个终端就有名字了。"
5. **你**按 ⌘T
   → **你看到**：右边出现第二个新终端，工作目录是同样的主目录或偏好默认目录
   → **你感受**："想开几个开几个。"

### Journey 2：早晨打开多个项目

1. **你**早上打开 Muxvo
   → **你看到**：上次主动关闭的终端没有恢复，只有偏好里设置的 N 个新终端
   → **你感受**："干净的开始。"
2. **你**按 ⌘T 三次，连开三个新终端
   → **你看到**：网格自动从 1 个排到 4 个
   → **你感受**："很顺手。"
3. **你**依次双击每个终端的"命名..."，分别取名 frontend、backend、db、log
   → **你看到**：每个终端标题区都从灰色占位符变成实色名字
   → **你感受**："一眼能找到我要的那一个。"
4. **你**在 frontend 终端里启动 dev 服务
   → **你看到**：状态点保持绿色但呼吸更明显，命令在跑
   → **你感受**："终端正在干活。"
5. **你**临时想看一下 backend 项目结构
   → **你看到**：你点击 backend 终端右上角的文件夹按钮，文件面板从右侧滑出
   → **你感受**："查目录不用打 ls。"
6. **你**关闭文件面板，继续工作

### Journey 3：关掉一个跑得有问题的终端

1. **你**发现 db 终端跑的脚本卡住了
   → **你看到**：状态点是绿色但终端没有任何输出
   → **你感受**："不对劲。"
2. **你**点击该终端右上角的红色 ✕
   → **你看到**：屏幕中央弹出确认对话框，正文写"确定关闭此终端？"
   → **你感受**："好，它知道里面有命令在跑。"
3. **你**点击"确定"
   → **你看到**：对话框消失，db 终端瞬间消失，右侧的 log 终端补位
   → **你感受**："果断收掉了。"
4. **你**按 ⌘T 重新开一个 db 终端
   → **你看到**：新终端从默认目录开始，状态点绿色
   → **你感受**："重新来过。"
5. **你**给它取名 "db-retry"
   → **你看到**：标题区显示新名字
   → **你感受**："和上一个区分开。"

## 7. 界面规格

### 7.1 页面/面板清单

| 名称 | 作用 | 进入方式 | 退出方式 |
|---|---|---|---|
| 终端标题栏 | 状态点、路径、名字、工具按钮 | 终端创建后自动出现 | 终端被关闭 |

| 主区空态 | 一个终端都没有时 | 用户关掉了所有终端 | 创建任何一个终端 |

### 7.2 各页关键区域

**终端标题栏**（自左向右）：
- 状态点（约 6 像素圆点）
- 可选 Worktree 项目徽标（绿色小标签 + 分支图标）
- 工作目录路径（青色，可点击）
- `·` 分隔符
- 自定义名字 / "命名..."占位符 / 编辑输入框
- 等待输入红色数字徽标（仅等待时出现）
- 右侧工具按钮组：分支按钮（仅 Git 仓库）、文件按钮（琥珀胶囊）、放大/回到平铺按钮、关闭按钮（红色 ✕）

**关闭确认对话框**：
- 半透明全屏遮罩
- 居中卡片，内含一行正文 + 两个按钮（取消 / 确定）

**工作目录浮层**：
- 顶部标题"切换工作目录"

- 快捷路径列表（主目录 / 桌面 / 文档）
- 底部"浏览..."按钮

**Worktree 浮层**：
- 顶部标题 "Worktrees"
- 顶部"+ New Worktree"按钮
- 中部分支列表，每行一个分支，标记 main / current / merged
- 已合并分支右侧出现 ✕ 删除入口

### 7.3 五态规格（终端标题栏 + 主区）

| 状态 | 用户看到什么 | 可做的动作 |

| **空态** | 主区显示大号 + 按钮和"暂无终端，点击 + 新建"（一个终端都没有时） | 点 + 创建第一个终端 |

## 8. 状态与交互规则

### 8.1 可见状态清单

用户可以在终端标题区看到以下"可见状态"，全部用状态点颜色 + 动画 + 徽标传达：

- **运行中（绿色 + 缓呼吸）**：终端命令行就绪，可以输入命令
- **空闲 / 已停止（灰色无动画）**：终端关闭流程或断开后短暂保留
- **等待输入（红色 + 快呼吸 + 数字徽标）**：终端在问你 yes/no 或类似问题
- **启动中**：刚创建的瞬间，状态点先灰后绿，用户感知不到延迟

### 8.2 状态切换触发

| 用户做 | 用户看到 |
|---|---|
| 按 ⌘T / 点 + | 出现新终端，状态点先灰再绿 |
| 在终端跑命令 | 状态点保持绿色 |
| 命令进入交互问答 | 状态点变红色脉冲 + 出现红色 1 徽标 |
| 在终端里回答问题 | 红色徽标消失，状态点回到绿色 |
| 在终端里 cd | 路径文字立即更新 |
| 双击命名区 | 名字变成可编辑输入框 |
| 按回车 | 输入框收起，新名字保存 |
| 按 Esc | 输入框收起，名字回滚 |
| 按 ✕ | 终端立即消失（无任务时）或弹出确认（有任务时） |
| 在确认框选"确定" | 终端被强制收掉 |
| 在确认框选"取消"/外部点击/Esc | 对话框关闭，终端保留 |

### 8.3 快捷键与手势

| 按键 / 手势 | 作用 | 前置条件 |
|---|---|---|
| ⌘T (macOS) / Ctrl+T | 新建终端 | 当前终端数 < 20 |
| 单击 ✕ 按钮 | 关闭终端 | 终端可见 |
| 单击命名占位符 | 进入编辑名字 | 处于平铺模式 |
| 单击已有名字 | 重新编辑名字 | 处于平铺模式 |
| 编辑框回车 | 保存名字 | 处于编辑态 |
| 编辑框 Esc | 取消编辑、回滚名字 | 处于编辑态 |
| 编辑框失去焦点 | 按当前内容保存 | 处于编辑态 |
| 单击路径文字 | 弹出工作目录浮层 | 处于平铺模式 |
| 浮层 Esc / 点外部 | 关闭浮层 | 浮层处于打开状态 |

### 8.4 多窗口/多标签行为

本版 Muxvo 只支持单主窗口，每个终端只属于一个窗口。在主窗口外没有"多标签"概念。详见 [M15 APP_RELIABILITY]。

## 9. 边界、限制与异常

- **数量限制**：同时最多 20 个终端；下限恒为 0（用户可以全部关掉）
- **启动数量范围**：偏好里 1-20，超出范围会被夹紧到边界
- **目录切换前提**：只有终端处于常规命令行环境时才能用浮层切目录
- **名字长度**：本版未在 UI 层强制硬限制，但建议 ≤ 30 字符以保证显示
- **名字可见性**：聚焦模式下名字只读不可编辑
- **明确不支持**：
  - 用菜单栏的"文件 → 新终端"创建（本版不提供菜单栏入口，菜单文案仅作为 i18n 资源）
  - 同时拖拽多个终端
  - 把一个终端拆出主窗口变成独立窗口
  - 在终端外部用快捷键"关闭"某个终端（关闭只能用 ✕ 按钮）
  - 手动重启已关闭的终端（请用新建）
- **错误提示文案**：
  - 已达上限：按钮悬浮"已达最大 20 个终端"
  - 关闭确认：正文"确定关闭此终端？"
  - 主区空态：主区中央"暂无终端，点击 + 新建"
- **数据丢失风险**：
  - 用户主动关闭终端 → 终端内容立即丢失，不可恢复
  - 强制关闭跑任务的终端 → 命令进度丢失，确认对话框已提示
  - 自定义名字 → 已持久化，下次启动仍在；意外退出时由 [M15-REQ-APP_RELIABILITY-021] 负责恢复

## 10. 明确不做的事（Out of Scope）

- **终端会话录制 / 回放**：本版不录制终端的命令历史，原因是体积大、隐私风险。后续若有"会话快照"需求再考虑。
- **多窗口拆分**：本版不允许把终端拖出主窗口形成独立窗口，原因是窗口管理复杂、与聚焦模式冲突。等用户提出明确需求再考虑。
- **菜单栏新建项**：菜单文案 "新建终端" 已存在 i18n，但本版不提供原生菜单栏入口，避免与底栏 + 浮层 + 快捷键重复。
- **批量关闭按钮**：不提供"一键关闭所有终端"按钮，原因是误操作风险高，用户可逐个关闭。
- **关闭后撤销**：终端关闭不可撤销，原因是命令行环境无法可靠恢复。
- **重命名右键菜单**：不在右键菜单里提供"重命名"项，原因是直接点击名字已经足够直观。
- **手动重启已关闭终端**：不提供"复用刚才的终端"按钮，请用新建。
- **每个终端独立工作目录偏好**：本版不支持给单个终端记住"我希望它每次都从这个目录开始"，所有新终端共享一个偏好默认目录。
