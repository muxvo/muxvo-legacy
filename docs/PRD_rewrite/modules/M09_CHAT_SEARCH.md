# M09 CHAT_SEARCH – 聊天搜索与筛选 PRD

> 版本 v1.0 · 适用 Muxvo Rust 重构 · 行数上限 518

## 1. 模块定位

- **一句话**：在 Chat Tab 里按关键词和条件快速找到想看的那条旧对话。
- **不用它会怎样**：用户只能靠上下滚动翻几千条历史会话，想不起什么时候问过某个问题时完全找不回来，相当于"历史对话只有最近的有用"。
- **与相邻模块的分界**：
  - 搜索框、筛选条件、结果高亮、结果排序、结果跳转 属于本模块
  - Chat Tab 的三栏布局、项目列表、会话卡片、会话详情的默认展示 属于 [M08 CHAT_BROWSE]
  - 会话的云端归档、同步进度条、导出文件 属于 [M10 CHAT_SYNC]
  - 全局快捷键的注册与冲突仲裁（⌘F 绑定本身）属于 [M15 APP_RELIABILITY]

## 2. 目标用户与场景

### 主要用户画像

- **CLI 重度用户**：一周内会在 Claude Code 里开几十个项目、上百个会话，经常想回到"上周问过的那个 bug"。
- **知识工作者**：把 Claude 当笔记本，需要从几个月前的对话里翻出具体一段答复。
- **新手**：对历史列表不熟悉，第一次想找"之前那个 hello world 的例子"，需要一个显而易见的搜索入口。

### Top3 使用场景

**场景 1 — 找回一段具体答复**：用户记得两周前让 Claude 写过一段 "debounce 的实现"，但记不清是在哪个项目。用户进入 Chat Tab，在搜索框输入 `debounce`，中栏立刻把标题含有这个词的会话列在上面，再下面排出"内容里出现 debounce"的会话，点击其中一条，右栏打开详情，Claude 的回复里 `debounce` 被黄色高亮，用户一眼定位。

**场景 2 — 只看某个项目最近的会话**：用户需要回顾 `muxvo` 项目这周做了什么。用户在左栏点击 `muxvo` 项目，中栏立即只显示这个项目下的会话；再结合搜索输入 `bug`，只在 `muxvo` 里找含 bug 的会话。项目筛选和关键词叠加生效。

**场景 3 — 翻很久以前的对话**：用户想看一个月前某次长聊天，记得关键词但不记得什么时候。用户输入关键词搜索全部项目，结果几十条，用户从上往下翻卡片，每条卡片显示摘要片段和命中项目名，翻到目标后单击进入详情。

### 使用频率

日常高频。活跃用户每天会触发搜索 3-10 次，每次从输入到找到目标通常在 5-15 秒内完成。本模块是 Chat Tab 的"第二大入口"，仅次于默认浏览。

## 5. 详细需求条目

### REQ-CHAT_SEARCH-001 / 002  中栏顶部常驻搜索框与占位文案

**触发方式**：用户进入 Chat Tab，中栏渲染完成时搜索框自动出现。
**正常流程**：中栏自上而下的第一块区域是"会话"标题栏，紧贴下方是一个占一整行的搜索输入框；内容为空时显示灰色占位"搜索会话..."，输入任意字符后占位立即消失。
**用户看到的反馈**：无论中栏有没有数据，搜索框都在固定位置显示；占位字重较轻、颜色为次要灰，与真实输入明显区分。
**异常情况**：Chat Tab 仍在加载骨架 → 搜索框与骨架一起呈灰色占位，不影响打字后触发搜索。
**相关**：[M08-REQ-NNN]（Chat Tab 三栏布局）

### REQ-CHAT_SEARCH-003  即输即搜

**触发方式**：用户在搜索框连续敲入或删除字符。
**前置条件**：搜索框得到焦点。
**正常流程**：
  1. 用户每敲一个字符，系统记录最新内容但不立即查询。
  2. 用户停顿约 0.3 秒（不再敲字）后，系统把当前关键词交给后端执行查询。
  3. 结果返回后中栏刷新为搜索结果。
**用户看到的反馈**：打字期间中栏内容保持不变；停顿后很快出现结果；期间不需要按回车。
**结束状态**：用户看到新结果；输入框内容保持不变。
**异常情况**：查询失败 → 中栏回到"无结果"提示（详见 REQ-CHAT_SEARCH-014 的兜底），输入框保持原样。
**相关**：REQ-CHAT_SEARCH-023（过期请求取消）

### REQ-CHAT_SEARCH-004  搜索过程加载指示

**触发方式**：系统正在为当前关键词执行查询。
**正常流程**：中栏会话列表的头部出现一个小的动效指示（细小的旋转或滚动条），表示"还在算"；结果头部计数暂时显示为通用"会话"字样，不显示具体数字。
**用户看到的反馈**：用户知道"刚打的字已经接收了，只是在查"，不会误以为没反应。
**结束状态**：查询完成后指示消失，头部改显具体结果数。
**异常情况**：查询超过一个相对长的时间仍未返回 → 前端保持指示，但不弹报错（详见 §9）。

### REQ-CHAT_SEARCH-005 / 006  结果分段：标题匹配 + 内容匹配

**触发方式**：搜索完成且至少一条会话命中。
**正常流程**：中栏自上而下先显示小标题横条"标题匹配 (N)"列出所有标题或自定义名命中的会话卡片；在其下方再显示小标题"内容匹配 (M)"列出正文命中的会话卡片；"标题匹配"里已经出现过的会话不会在"内容匹配"中重复出现。标题段由前端即时完成，通常打完字的一刻就能看到它。
**用户看到的反馈**：段落之间有清晰的分隔和小标题，用户能立刻分辨"这条是因为标题还是因为正文命中"；主观延迟非常短。
**异常情况**：某一段没有命中 → 该段整体不显示；两段都没命中 → 进入无结果空态。
**相关**：REQ-CHAT_SEARCH-026 / 027

### REQ-CHAT_SEARCH-007  命中词在卡片内高亮

**正常流程**：每张结果卡片的标题、摘要预览里，凡是与当前关键词相同的片段都会被套上黄色底色；其它文字颜色不变。
**用户看到的反馈**：即使摘要里有两三处命中也能一眼看到；高亮不会改变行高、不会让卡片"跳行"。
**异常情况**：关键词只是标点符号或纯空格 → 视为无效输入，不触发搜索。

### REQ-CHAT_SEARCH-008  摘要片段显示命中上下文

**正常流程**：内容匹配的会话卡片显示的"预览"不是会话原标题，而是从消息正文里截取一段包含命中词的上下文（命中词居中，前后各若干字符），并对这段文字应用高亮。
**用户看到的反馈**：用户一眼就知道"这条会话里关键词出现在什么场景"，不需要打开详情也能判断大致相关性。
**异常情况**：命中位于很靠前或很靠后 → 片段从可用位置开始/结束，不报错。

### REQ-CHAT_SEARCH-009 / 010 / 011  项目过滤、跨项目搜索、项目归属徽章

**触发方式**：用户在左栏选中某具体项目或聚合项"所有项目"。
**正常流程**：选中具体项目时，结果只显示属于该项目的会话；选中"所有项目"时结果覆盖全部项目，且每张结果卡片底部徽章区会额外显示一个项目名徽章。
**用户看到的反馈**：同一个关键词，全部项目下 100 条，切到单个项目只剩 3 条，数字变化让用户明确感知过滤生效；跨项目模式下用户能一眼区分"同样是 bug 会话，一条属于 muxvo，一条属于其它项目"。
**异常情况**：选中具体项目时项目徽章不显示（避免冗余）。
**相关**：[M08-REQ-NNN]（项目列表与选中态）

### REQ-CHAT_SEARCH-012  结果按最近修改时间倒序

**正常流程**："标题匹配"和"内容匹配"两段内部均按最后修改时间倒序排列，最新的在最上。
**用户看到的反馈**：用户通常更想看到最近的匹配，因此从上往下翻即可。
**异常情况**：两条会话修改时间完全相同 → 顺序不额外保证，但稳定不跳动。

### REQ-CHAT_SEARCH-013  结果总数显示

**正常流程**：搜索结果存在时，中栏头部文案显示"N 个结果"；其中 N 是过滤后标题匹配 + 内容匹配的总数。
**异常情况**：正在查询时头部改显通用"会话"字样，不显示具体数字（避免抖动）。

### REQ-CHAT_SEARCH-014  搜索无结果提示

**触发方式**：查询完成且过滤后总命中数为 0。
**正常流程**：中栏内容区居中显示：
  - 一行主文案："没有找到匹配的记录"
  - 一行副文案："请尝试其他关键词"
  - 一个"清除搜索"按钮
  - 一个搜索图标图示
**用户看到的反馈**：用户知道不是 bug，是真没匹配；有明确的下一步（改词或清空）。
**结束状态**：用户点按钮或改词都能脱离空态。

### REQ-CHAT_SEARCH-015 / 016  ✕ 清除按钮与删光输入

**触发方式**：搜索框内有任意内容时，输入框尾部出现 ✕ 按钮；用户点击它；或用户用退格键一个个删除字符直到输入框变空。
**正常流程**：两种操作行为一致 —— 输入框内容清空；搜索结果消失；中栏回到默认会话列表；左栏项目筛选保持不变。
**用户看到的反馈**：一次点击即可"回到搜索前"，无需擦除每个字符。

### REQ-CHAT_SEARCH-017 / 018 / 019  点击结果 → 详情 → 高亮 → 自动滚动

**触发方式**：用户单击任一结果卡片。
**正常流程**：
  1. 右栏加载该会话的消息列表。
  2. 右栏内容呈现后，命中词在每条消息的文本里被黄色底色高亮。
  3. 右栏滚动位置自动对齐到第一处命中的消息（使其出现在可视区内）。
**用户看到的反馈**：不需要自己在长消息里找词；从点击到定位通常一秒内完成。
**结束状态**：搜索框右侧出现"1/N"计数和上下箭头按钮。
**异常情况**：该会话内实际没有命中（例如跨项目去重时出现边缘情况）→ 不报错，不显示计数，用户可正常阅读。
**相关**：[M08-REQ-NNN]（会话详情渲染）

### REQ-CHAT_SEARCH-020 / 021  命中计数与上下导航

**触发方式**：右栏已显示一条会话且存在至少一处命中。
**正常流程**：搜索框右侧出现三个控件：
  - 计数"当前/总数"（例如 `1/5`）
  - 向上箭头（跳到上一处命中）
  - 向下箭头（跳到下一处命中）
**用户看到的反馈**：每次点击箭头，右栏滚动到对应命中，计数跟着更新；已经在第一处时向上箭头禁用，已经在最后一处时向下箭头禁用（也可选择允许循环，本 PRD 允许循环行为视具体实现，见 §11.3）。
**异常情况**：该会话命中总数为 0 → 不显示计数和箭头，改显 ✕ 清除按钮。

### REQ-CHAT_SEARCH-022  切换项目时保留关键词

**正常流程**：搜索结果已出现时，用户在左栏改选另一个项目，搜索输入框的内容不变；结果按新项目立即重新过滤。
**用户看到的反馈**：用户感觉"项目筛选就是在搜索上叠加了一层范围"。

### REQ-CHAT_SEARCH-023  取消过期请求

**正常流程**：用户在上一次查询尚未返回前又修改了关键词，系统把旧请求的结果丢弃；只有对应当前输入框内容的结果才会被渲染。
**用户看到的反馈**：不会看到"刚出现又被另一结果覆盖"的闪烁。
**异常情况**：旧请求报错回来 → 同样丢弃，不弹报错。

### REQ-CHAT_SEARCH-024  滚到底自动加载更多

**触发方式**：用户在中栏结果列表中向下滚动接近底部。
**正常流程**：结果卡片初始显示一批（通常若干十条），用户滚到接近底部时继续追加下一批；用户无需手动翻页。
**用户看到的反馈**：翻阅大结果集时没有"下一页"按钮的打断；列表感觉是连贯的。
**异常情况**：结果总数较少、全部都能一次显示 → 不触发加载更多行为。

### REQ-CHAT_SEARCH-025 / 026 / 027  头部状态 + 标题段即时 + 内容段骨架

**正常流程**：
- 查询进行中时中栏头部显示"会话"（不带数字），查询完成后改显"N 个结果"；数字只在"可信"时出现，避免快速跳动。
- 标题命中由前端即时过滤得出，因此"标题匹配"段总是先于"内容匹配"段出现，输入完最后一个字符的一瞬间用户就能看到它。
- 后端内容搜索尚未返回时，"内容匹配"段位置显示小标题"搜索会话内容..."加几张灰色骨架卡片；返回后替换为真实卡片，不会造成"是不是搜不到内容"的误判。

### REQ-CHAT_SEARCH-028  空查询不触发搜索

**正常流程**：搜索框只有空格或完全为空时，不发起任何查询，中栏保持默认会话列表；头部不显示"N 个结果"也不显示"搜索中"。

### REQ-CHAT_SEARCH-029 / 030  不区分大小写

**正常流程**：关键词匹配和高亮都按无大小写规则；用户不需要关心英文大小写。

### REQ-CHAT_SEARCH-031  切走再回来重置搜索

**触发方式**：用户离开 Chat Tab（切到终端 / 编辑器 / 配置），稍后再回来。
**正常流程**：回到 Chat Tab 时搜索框内容已清空，中栏显示默认会话列表；每次进入 Chat Tab 都是"干净"的起点，不会被上次遗留的筛选意外限制住视野。
**异常情况**：用户希望长期保留关键词 → 当前版本不支持（详见 §10）。

### REQ-CHAT_SEARCH-032  结果包含尚未浏览加载的历史

**正常流程**：搜索范围是"所有已知会话"，不局限于当前中栏列表里已渲染的会话；命中的历史会话即使未曾被用户点开也会出现在结果里。用户不需要先滚动浏览再搜索；直接搜就能翻出很久以前的对话。
**相关**：[M10-REQ-NNN]（会话归档存储范围）

## 6. 主要用户旅程

### Journey 1：新手第一次搜索

1. **你** 打开 Muxvo，进入 Chat Tab。
   → **你所见**：左栏是项目列表，中栏头部有一行"会话 (XX)"，紧接着一个空的搜索输入框写着"搜索会话..."；右栏是空白欢迎页。
   → **你感受**：搜索入口很明显，我不需要找。
2. **你** 点一下搜索框，开始输入 `hello world`。
   → **你所见**：没敲完时界面没动；停顿一下，中栏出现"标题匹配 (2)"和"内容匹配 (8)"两段，共 10 条卡片，命中词黄色高亮。
   → **你感受**：不需要按回车、结果快、"哦原来我问过这些"。
3. **你** 点第一条内容匹配卡片。
   → **你所见**：右栏加载会话，自动滚到一条 Claude 的回复，回复里"hello world"被高亮；搜索框右侧出现 `1/3` 和上下箭头。
   → **你感受**：不用自己在聊天里找词，一次到位。
4. **你** 点下箭头两次。
   → **你所见**：右栏依次滚到第 2、3 处命中，计数变成 `3/3`。
   → **你感受**：像在 VSCode 里按 F3 一样顺。
5. **你** 想回到正常列表，按一下输入框尾部的 ✕；搜索结果消失，中栏回到刚进入时的样子。退出路径干净。

### Journey 2：老手叠加筛选找回老记录

1. **你** 是个每天在 Claude Code 工作的开发者，想回顾"上周在 muxvo 项目里修过的那个光标 bug"。
   → **你所见**：Chat Tab 默认视图，左栏列着十几个项目，中栏大量会话。
2. **你** 先在左栏点 `muxvo` 项目。
   → **你所见**：中栏只剩 muxvo 的会话，头部变成"会话 (47)"。
   → **你感受**：先缩小范围，再找词会更清晰。
3. **你** 在搜索框输入 `cursor`。
   → **你所见**：标题匹配 1 条，内容匹配 6 条，共 7 个结果；每条卡片都在 muxvo 项目内。
4. **你** 瞥一下标题匹配那条，发现不是你要的；点开"内容匹配"第 2 条。
   → **你所见**：右栏打开会话，滚动到包含 `cursor` 的一条消息，`1/4` 计数出现。
5. **你** 点下箭头翻到 `3/4`，看到你记忆中的那段答复，十几秒完成从"大脑回忆"到"看到原文"。
6. **你** 切到别的项目继续工作，搜索框里的 `cursor` 暂时不动；左栏切项目后中栏立刻按新项目过滤，关键词还在。
   → **你感受**：筛选叠加的心智模型稳了。

### Journey 3：搜不到 / 超时 / 出错的恢复

1. **你** 想找 "tauri-rs"，打进搜索框。
   → **你所见**：下段显示"搜索会话内容..."加骨架卡。几百毫秒后后端返回 0 命中。
   → **你所见**：中栏显示空态："没有找到匹配的记录 / 请尝试其他关键词 / [清除搜索]"。
   → **你感受**：清楚知道确实没有，不是 bug。
2. **你** 点"清除搜索"按钮，改输入 `tauri` 再等一下。
   → **你所见**：结果出现一批会话，都是你真正想要的。
   → **你感受**：空态的提示起到了"换词"的引导作用。
3. **你** 继续搜索时后端连接短暂异常，中栏头部一直显示"会话"指示灯转动。
   → **你所见**：没有弹出报错对话框；你改一下词，下一次查询正常返回。
   → **你感受**：异常不会把你踢出搜索流程。

## 7. 界面规格

### 7.1 页面/面板清单

| 名称 | 作用 | 进入方式 | 退出方式 |
|---|---|---|---|
| 搜索输入框 | 输入关键词、显示清除/命中导航控件 | 进入 Chat Tab 时常驻显示 | 清除输入或离开 Chat Tab |
| 搜索结果列表 | 分段展示"标题匹配 / 内容匹配"的会话卡片 | 用户输入非空关键词后自动出现 | 清除输入后消失 |
| 无结果空态 | 零命中时的引导提示 | 搜索完成且过滤后命中数为 0 | 清除输入或修改关键词 |

### 7.2 关键区域

**搜索输入框**：
- 位于中栏"会话"标题下方、结果卡片列表之上。
- 宽度占满中栏减两侧留白。
- 左侧内边距留 ~8 像素给占位文字，右侧内边距根据当前状态预留 ~110 像素给"清除按钮 / 结果数 / 命中导航"三种情况之一。
- 输入框右侧三档状态：
  - 有输入但尚未选中任一结果会话 → 显示"N 个结果"文字 + ✕ 清除按钮
  - 有输入且右栏已选中某会话 → 显示"当前/总数"计数 + 上下箭头按钮 + ✕ 清除按钮
  - 无输入 → 不显示任何右侧控件

**搜索结果列表（中栏 cards 区）**：
- 顶部小标题横条：灰底小字"标题匹配 (N)" / "内容匹配 (M)" / "搜索会话内容..."（加载态）。
- 每张卡片结构（与 [M08] 的默认卡片同源）：顶部标题 + 时间戳 + 中间两行预览 + 底部徽章行（来源、项目名、关键字标签、大小）。
- 关键词高亮：标题和预览文字里命中片段用黄色底色 `<mark>` 包裹。

**无结果空态**：
- 居中排布：搜索图标 → 主文案 → 副文案 → 清除按钮。
- 按钮样式与普通次要按钮一致，便于点击。

### 7.3 五态规格（搜索结果列表）

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 输入框空、中栏显示默认会话列表（由 [M08] 规定），不显示任何搜索结果段 | 点输入框开始打字 |
| **加载态** | 输入了关键词，"标题匹配"段已显示或为空；"内容匹配"段位置显示小标题"搜索会话内容..."和骨架卡片；头部计数显示通用"会话" | 继续修改关键词、切换项目 |
| **正常态** | 显示"标题匹配 (N)"和/或"内容匹配 (M)"段，每段下面若干张真实结果卡片；头部显示"N 个结果" | 点击卡片、滚动、切项目、改词、清除 |
| **错误态** | 后端查询失败时，前端把该次结果视为零命中，进入无结果空态；不弹报错框 | 改关键词或清除 |
| **受限态** | 本模块无独立受限态（登录/权限问题由 [M08] / [M10] 处理） | — |

> 输入框占位："搜索会话..."
> 头部计数（正常）："47 个结果"
> 头部计数（查询中）："会话"
> 段小标题："标题匹配 (1)" / "内容匹配 (6)"
> 段小标题（加载）："搜索会话内容..."
> 空态主文案："没有找到匹配的记录"
> 空态副文案："请尝试其他关键词"
> 空态按钮："清除搜索"
> 命中导航计数："1/5"（分数形式）

## 8. 状态与交互规则

### 8.1 可见状态清单

- **未搜索**：输入框为空，中栏显示默认会话列表。
- **打字中**：输入框有字符，后端尚未被调用（处于即输即搜的停顿等待里）。
- **查询中**：后端正在执行，中栏头部显示通用"会话"指示。
- **有结果**：查询完成，命中数 ≥ 1，中栏显示分段结果。
- **无结果**：查询完成，命中数 = 0，中栏显示空态提示。
- **详情已选**：某张卡片被点击、右栏已加载对应会话；搜索框右侧从"N 个结果"切换为"当前/总数"和上下箭头。
- **导航高亮**：在详情里按箭头切换命中位置，滚动位置和高亮随之变化。

### 8.2 状态切换触发

- 输入第一个字符 → 从"未搜索"进入"打字中"。
- 停顿若干毫秒 → 从"打字中"进入"查询中"。
- 后端返回有结果 → 进入"有结果"。
- 后端返回 0 条 → 进入"无结果"。
- 再改一个字符 → 返回"打字中"（放弃旧请求）。
- 点击任一结果卡片 → 进入"详情已选"。
- 在详情里点上下箭头 → 在"导航高亮"之间切换。
- 点 ✕ 或删光输入 → 回到"未搜索"。
- 离开 Chat Tab → 回到"未搜索"，输入框清空。

### 8.3 快捷键与手势

| 按键/手势 | 作用 | 前置条件 |
|---|---|---|
| 任意字符输入 | 编辑关键词 | 搜索框获得焦点 |
| 退格键删到空 | 等同于点 ✕ | 搜索框内有内容 |
| 单击结果卡片 | 打开详情并跳到第一处命中 | 有结果 |
| 单击向上/向下箭头 | 在本会话命中间前后切换 | 详情已选且有命中 |
| 点击 ✕ 清除按钮 | 清空搜索 | 搜索框内有内容 |
| 点击"清除搜索"按钮 | 同上 | 处于无结果空态 |

> 说明：全局 ⌘F 是否绑定本模块"进入搜索框焦点"在当前上线版本中未完全连线，本 PRD 不作强制规定；详见 §11.3。

### 8.4 多窗口/多标签行为

- 多个 Muxvo 窗口彼此独立，每个窗口各自维护自己的搜索状态。
- 同窗口内切到其它 Tab 会清空搜索；再切回来后关键词不恢复。
- 左栏项目切换不清空关键词（详见 REQ-CHAT_SEARCH-022）。

## 9. 边界、限制与异常

### 数量限制

- 搜索结果不设硬性上限，但中栏一次只渲染若干张卡片，剩余通过滚动到底追加。
- 单次查询允许的关键词长度未设硬性上限，实际过长的字符串会被视作普通文本搜索。
- 搜索在后端耗时较长时前端不强制 abort；用户可随时改词，前端会放弃旧结果。

### 明确不支持

- 不支持正则表达式或通配符搜索（`*` / `?` / `/.../` 都被视作普通字符）。
- 不支持按角色（只看用户消息 / 只看 AI 消息）过滤结果。
- 不支持按会话状态（进行中 / 已完成 / 已归档）过滤结果。
- 不支持按时间范围（最近 7 天 / 本月 / 自定义日期）过滤结果。
- 不支持"只搜标题"或"只搜内容"的单选开关（两段总是同时显示）。
- 不支持多关键词的 AND / OR 组合，输入的整个字符串作为一个片段匹配。
- 不支持按消息数或会话长度排序；排序一律按最近修改时间倒序。
- 不支持保留搜索历史或"最近搜索过的词"下拉提示。
- 不支持在搜索结果上右键进行批量重命名、批量删除、批量导出。
- 不提供独立的"清除筛选"全局按钮；清除靠输入框的 ✕ 或删光输入。

### 错误提示文案

| 用户遇到的情况 | 用户看到的提示 | 用户能做的事 |
|---|---|---|
| 查询返回 0 条 | "没有找到匹配的记录 / 请尝试其他关键词 / [清除搜索]" | 改词或清除 |
| 后端查询失败 | 与 0 条等同的空态（不弹报错） | 改词重试或清除 |
| 后端查询长时间未返回 | 头部小指示持续旋转，中栏内容不变 | 改词即可放弃上次请求 |
| 点击一张"内容命中"卡片但会话正文里实际无命中（边缘情况） | 详情正常渲染，但搜索框右侧不显示命中计数和箭头 | 正常阅读或改词 |
| 关键词只是空格 | 不触发查询，中栏保持默认会话列表 | 删掉空格或输入有效字符 |

### 数据丢失风险

本模块只进行只读查询与高亮渲染，不写入、不删除、不修改任何聊天数据。因此不存在本模块导致数据丢失的场景。用户对会话的删除/重命名/导出等写入操作由 [M08] 与 [M10] 处理。

## 10. 明确不做的事（Out of Scope）

- **搜索历史下拉**：输入框下方不显示"最近搜过的词"。理由：首发以"用完即清"的轻量模型为准。**再考虑**：用户反馈需要"重复搜同一批词"时再引入。
- **按角色过滤**（只看用户消息 / 只看 AI 消息）。理由：本版把"筛选正文"统一为"内容匹配"段，不细分角色。
- **按会话状态过滤**（进行中 / 已完成 / 已归档）。理由：状态在 [M08] 浏览列表中由徽章体现，搜索不额外叠加此维度。
- **按时间范围过滤**（最近 7 天 / 本月 / 自定义日期）。理由：结果已按时间倒序，长列表配合项目过滤已能解决 80% 需求。**再考虑**：需要审计特定周/月时再引入。
- **排序切换**（按消息数 / 按最旧 / 按相关度）。理由：多种排序增加心智成本，首发统一按"最新在上"。
- **正则 / 通配符**：理由：保持搜索行为"可预期"，不让关键词语法学习成本进入主流程。
- **⌘F 全局快捷键的默认绑定到本模块**：理由：快捷键冲突需要全局仲裁，交由 [M15] 统一决定。**再考虑**：全局快捷键方案定稿后回填。
- **保留筛选状态在 Tab 切换之间**：理由：首发选择"每次回到 Chat Tab 是干净起点"，以降低用户被隐形筛选误导的概率。

## 11. 附：术语与跨模块引用

### 11.1 本模块独有术语

| 术语 | 定义 |
|---|---|
| 关键词 | 用户在搜索框中输入的字符串，作为一个整体与会话标题或正文比对 |
| 标题匹配 | 关键词出现在会话标题或自定义名中的命中类别 |
| 内容匹配 | 关键词出现在会话正文消息中的命中类别 |
| 命中 | 单次关键词与某段文字完全相同（不区分大小写）的出现 |
| 命中导航 | 在详情里按上下箭头前后切换命中位置的操作 |
| 过期请求 | 用户快速改词时，尚未返回就被放弃的早先一次查询 |
| 骨架卡片 | 内容匹配段加载过程中显示的灰色占位卡片 |
| 即输即搜 | 用户停止敲字后很短时间内自动发起查询的交互模式 |

### 11.2 引用的其他模块

- [M08-REQ-NNN]（Chat Tab 三栏布局、项目列表与选中、会话卡片结构、详情默认渲染）— 本模块复用这些视图组件，只扩展"搜索/筛选/高亮"维度
- [M10-REQ-NNN]（会话归档与历史存储）— 本模块搜索范围覆盖归档内的历史会话
- [M15-REQ-NNN]（全局快捷键注册）— 本模块可能依赖 ⌘F 的分发决策，本 PRD 暂不强制
- [M14-REQ-NNN]（偏好设置）— 若未来增加"默认筛选偏好"会回到本处

> 注：上述 `REQ-NNN` 待对应模块 PRD 写作完成后回填具体编号。

### 11.3 待确认项

- **即输即搜的停顿时长**：当前上线版本约 0.3 秒停顿后触发查询，具体数值是否调整为 0.2 或 0.5 秒，**待与产品对齐**。
- **命中导航是否循环**：从最后一处命中再按向下箭头是否自动回到第一处，本 PRD 允许两种策略，**待与产品对齐**。
- **⌘F 全局快捷键的归属**：测试文档提到 "⌘F 打开搜索"，但跨模块快捷键一致性由 [M15] 决定，本 PRD 不作强制绑定，**待与产品对齐**。
- **后端失败的提示强度**：本 PRD 沿用"零命中空态"兜底，对"连续多次失败"是否需要显式横幅，**待与产品对齐**。
- **关键词最短长度**：是否需要规定至少 2 个字符才发起查询（避免极短关键词命中过多），**待与产品对齐**。
- **跨项目徽章的显示规则**：若未来项目名过长是否截断或省略，**待与产品对齐**。
