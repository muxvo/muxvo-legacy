# M04 TERM_NOTIFY – 等待输入通知 PRD

> 版本 v1.0 · 适用 Muxvo 重构 · 行数预算 450 ±15%

## 1. 模块定位

- **一句话**：任何一个终端需要用户回答 yes/no 或填入内容时，让用户在任何角落都能第一时间知道——标题上闪红、角落弹提示、应用图标亮数字。
- **不用它会怎样**：用户切到聊天、文件、设置等面板时，看不到终端在等人回复，命令会一直卡住；多个终端同时等输入时用户不知道哪个在等，会漏掉关键问答。
- **与相邻模块的分界**：
  - 终端标题区左侧的状态点颜色本身（绿 / 灰 / 红） 属于 [M01 TERM_LIFECYCLE]，本模块只负责红色情况下的"脉冲动画 / 徽标数字 / 右下角提示 / 应用图标角标"四层通知
  - 终端的网格平铺与侧栏布局 属于 [M02 TERM_GRID]
  - 终端放大到聚焦模式后的主-侧栏结构 属于 [M03 TERM_FOCUS]
  - "Dock 角标模式 / 定时间隔"偏好项的默认值与设置入口 属于 [M14 ONBOARD_PREFS]，引用 [M14-REQ-ONBOARD_PREFS-011] 与 [M14-REQ-ONBOARD_PREFS-012]

## 2. 目标用户与场景

### 主要用户画像

- **CLI 重度用户**：同时挂 4-8 个终端，Claude / Codex / 脚本在里面问 yes/no 的频率很高，一次漏掉就要等几分钟；他希望"不管我在看什么，终端喊我我都能马上知道"。
- **多任务切换者**：上午写代码、下午看聊天历史、中间偶尔去改设置，经常离开终端区。他需要"切到其它面板时仍然有醒目提醒"。
- **新手**：第一次看到终端进入等待输入状态，如果只有状态点变红，他可能不懂要点进去回话；需要右下角的文字提示告诉他"有 1 个终端在等你操作"。

### Top3 使用场景

**场景 1 — 单终端等待的第一眼通知**：用户同时盯着多个终端，其中一个 Claude 会话突然问"是否确认改动？"。状态点立刻变红并开始呼吸闪烁，标题右侧弹出一个红色数字"1"徽标，整个终端外框被红光包围。用户余光看到后，点进去回答即可，通知随之消失。

**场景 2 — 用户已切到其它面板时被呼唤**：用户正在浏览聊天历史面板，看不到终端。此时后台某个终端进入等待输入。右下角从下往上滑出一个小卡片："1 等待操作"，旁边一颗红色脉冲点。用户点卡片，界面立即回到终端区，红色那个终端出现在面前；也可以点右上角 ✕ 暂时忽略。

**场景 3 — 多个终端同时等输入**：用户离开片刻回来，发现应用图标右上角挂着数字"3"，同时界面右下角（如果在非终端面板）显示"3 等待操作"。用户点图标或卡片，切回终端区一看——三个终端都红色脉冲，他可以一个个回答。每回答完一个，图标数字会递减。

### 使用频率

- **Tile 徽标与脉冲**：高频，每次终端问答都出现，日常每小时数次
- **右下角全局通知**：中频，仅在用户离开终端区时才出现
- **Dock 角标**：可选，取决于用户选了哪种模式；多数 macOS 用户会长期开着

## 5. 详细需求条目

### REQ-TERM_NOTIFY-001 等待输入的红色脉冲状态点

**触发方式**：终端内命令开始等待用户回答（如 `(y/n)`、密码、菜单选择）。
**前置条件**：终端此前处于运行中（绿色状态点）。
**正常流程**：
  1. 命令进入等待输入
  2. 标题左侧圆点从绿变红，开始明显的快速呼吸闪烁（比绿色运行中更急促）
**用户看到的反馈**：纯红（ef4444），直径约 6 像素，快速呼吸（约每秒一次循环），带外发光光晕，余光可感知。
**结束状态**：持续到用户点进终端或命令收到回复。
**异常情况**：终端关闭 → 状态点随之消失；终端被拖到网格其它位置 → 脉冲不中断。
**相关**：[M01-REQ-TERM_LIFECYCLE-020]（状态点本体归属 M01，本 REQ 定义红色情况的动画与细节）、REQ-TERM_NOTIFY-002

### REQ-TERM_NOTIFY-002 等待输入的数字徽标

**触发方式**：终端进入等待输入时自动出现。
**前置条件**：同 REQ-TERM_NOTIFY-001。
**正常流程**：标题区右侧（名字后面、右侧工具按钮前面）出现一个红底白字圆形徽标，文字固定为"1"。
**用户看到的反馈**：红（ef4444）白字粗体，圆形直径约 18 像素，与状态点同节奏呼吸脉冲，带红色半透明外发光。
**结束状态**：一直显示到等待解除。
**异常情况**：同一终端同时弹多个问题 → 徽标仍为"1"（不做多问题计数，区分交给终端内容本身）。
**相关**：REQ-TERM_NOTIFY-001、REQ-TERM_NOTIFY-003

### REQ-TERM_NOTIFY-003 等待输入的整框红色描边光晕

**触发方式**：终端进入等待输入时自动出现。
**前置条件**：同上。
**正常流程**：整个终端外边框变红描边并缓慢呼吸（比状态点慢一点），带一层半透明红色光晕，类似"被红灯照亮"。
**用户看到的反馈**：外边框略加粗，颜色在深红亮红之间呼吸；若该终端同时被选中/聚焦（边框已是琥珀色），红色以外部描边光晕形式共存，不替换琥珀边框。
**结束状态**：等待解除后平滑回到普通外框。
**异常情况**：多终端同时等待 → 每个都有独立红色外框，互不影响。
**相关**：REQ-TERM_NOTIFY-001、REQ-TERM_NOTIFY-002、REQ-TERM_NOTIFY-017

### REQ-TERM_NOTIFY-004 点击终端清除等待视觉

**触发方式**：用户点击红色等待中的终端（标题区、内容区、外框任意位置）。
**前置条件**：终端正处于红色等待状态。
**正常流程**：
  1. 用户点击终端
  2. 键盘焦点进入终端
  3. 红色脉冲状态点变回绿色呼吸，数字徽标消失，外框红色光晕消散
**用户看到的反馈**：一次性、瞬间的切换，无渐隐动画；状态点颜色变化可感知。
**结束状态**：终端回到普通运行中外观；如果当前有右下角卡片显示"N 等待操作"，N 减 1 或卡片整体消失。
**异常情况**：用户点了但没真正输入 → 视觉仍会清除（对应"已确认看到了这个终端在等"的心智）。
**相关**：REQ-TERM_NOTIFY-005、REQ-TERM_NOTIFY-006

### REQ-TERM_NOTIFY-005 输入回复后自动清除

**触发方式**：用户在等待中的终端里敲入字符并提交。
**前置条件**：终端在等待输入。
**正常流程**：
  1. 用户输入内容
  2. 按回车
  3. 终端命令收到输入，回到运行中
  4. 所有红色视觉同步消失
**用户看到的反馈**：徽标、脉冲、外框光晕三者一起消失，状态点回到绿色。
**结束状态**：终端恢复正常运行中。
**异常情况**：命令随后立刻又弹新问题 → 状态点短暂变绿后再变红，用户会看到一次"红→绿→红"的闪回，代表有新的问答。
**相关**：REQ-TERM_NOTIFY-004

### REQ-TERM_NOTIFY-006 右下角全局等待卡片

**触发方式**：同时满足"有至少一个终端在等待"且"用户当前看不到终端视图"（例如打开了聊天历史、技能市场、MCP / Hooks / Plugins 面板、文件面板或三栏临时视图）。
**前置条件**：非受限状态。
**正常流程**：
  1. 用户切到非终端面板
  2. 屏幕右下角（距底部和右边都约 16 像素）滑出一个小卡片
  3. 卡片内容：左侧一颗红色脉冲圆点，中间文字"N 等待操作"，右上角一个灰色 ✕ 按钮
**用户看到的反馈**：
  - 卡片边框：红色半透明描边
  - 背景：应用当前主题的浮层背景
  - 阴影：带红色调的轻微投影，让它从背景里浮出来
  - 宽度：约 280 像素
  - 鼠标悬浮时卡片整体可点
**结束状态**：卡片一直悬停在右下角，直到等待数变为 0、用户点击主体或点击 ✕。
**异常情况**：用户同时打开多个面板 → 卡片只出现一次，不会叠加。
**相关**：REQ-TERM_NOTIFY-007、REQ-TERM_NOTIFY-008、REQ-TERM_NOTIFY-010

### REQ-TERM_NOTIFY-007 全局卡片的聚合计数

**触发方式**：等待中的终端数量变化时自动更新。
**前置条件**：卡片已出现。
**正常流程**：
  1. 卡片显示当前等待总数 N
  2. 新终端加入等待 → 文案变为 "N+1 等待操作"
  3. 某个终端被回复 → 文案变为 "N-1 等待操作"
  4. N 减到 0 → 卡片整体消失
**用户看到的反馈**：
  - 文案示例：`1 等待操作` / `3 等待操作` / `12 等待操作`
  - 数字变化时卡片不会整体闪消重建，而是原地更新
**结束状态**：若数字归 0 卡片消失，否则持续显示。
**异常情况**：N 变化的瞬间如果用户刚好按下 ✕ → 以用户动作为准，卡片消失。
**相关**：REQ-TERM_NOTIFY-006

### REQ-TERM_NOTIFY-008 点击全局卡片跳回终端

**触发方式**：用户点击卡片主体（除右上角 ✕ 以外的任何位置）。
**前置条件**：卡片正在显示。
**正常流程**：
  1. 用户点卡片
  2. 所有已打开的侧边面板和三栏临时视图被一次性关闭
  3. 界面回到终端主视图（平铺或聚焦，取决于上次状态）
  4. 等待中的红色终端直接出现在视野内
**用户看到的反馈**：面板切换像用户自己点了关闭；终端视图一旦可见，卡片同时消失。
**结束状态**：用户停留在终端视图，准备直接点进需要处理的终端。
**异常情况**：若有多个终端等待，跳转后不帮用户自动聚焦任何一个；由用户自行选择先处理哪个。
**相关**：REQ-TERM_NOTIFY-006、REQ-TERM_NOTIFY-009

### REQ-TERM_NOTIFY-009 全局卡片手动关闭

**触发方式**：用户点击卡片右上角 ✕。
**前置条件**：卡片正在显示。
**正常流程**：
  1. 用户点 ✕
  2. 卡片立即消失
  3. 在等待数没有变化的情况下，本次会话里卡片不会再自动出现
**用户看到的反馈**：一次性消失，无过渡动画。
**结束状态**：卡片进入"本次已读"。等待数字再增加（新的终端进入等待）时，重新出现并恢复计数。
**异常情况**：用户 ✕ 之后立刻切回终端视图再切回 → 卡片也不会重新弹，除非等待数变化。
**相关**：REQ-TERM_NOTIFY-006、REQ-TERM_NOTIFY-007

### REQ-TERM_NOTIFY-010 全局卡片仅在离开终端时出现

**触发方式**：自动判定。
**前置条件**：当前屏幕主区正显示终端平铺或聚焦视图 → 不显示卡片。
**正常流程**：用户在终端视图时，Tile 徽标与外框光晕已经足够醒目，不再弹右下角卡片；一旦用户打开聊天 / 市场 / 文件 / 设置 / 三栏临时视图等，卡片自动出现。
**用户看到的反馈**：卡片是否出现对用户而言等同于"是否还能看到终端本体"。
**结束状态**：切回终端 → 卡片消失；再切走 → 卡片再次出现（除非用户刚点过 ✕ 且数字未变）。
**相关**：REQ-TERM_NOTIFY-006、REQ-TERM_NOTIFY-009

### REQ-TERM_NOTIFY-011 Dock 角标 - 实时模式

**触发方式**：用户在偏好设置将"Dock 角标通知"设为"实时"。
**前置条件**：macOS 平台。
**正常流程**：
  1. 任何终端进入等待 → 应用图标右上角瞬间出现数字角标
  2. 等待数变化 → 角标数字立即跟随
  3. 等待数为 0 → 角标消失
**用户看到的反馈**：macOS 原生的 Dock 红底白字数字角标，位于应用图标右上。
**结束状态**：角标与等待数实时同步。
**异常情况**：应用未在前台 → 角标仍然刷新；用户 ⌘Q 退出 → 角标随应用消失。
**相关**：REQ-TERM_NOTIFY-014、[M14-REQ-ONBOARD_PREFS-011]

### REQ-TERM_NOTIFY-012 Dock 角标 - 定时模式

**触发方式**：用户设为"定时"并设定检查间隔。
**前置条件**：macOS 平台。
**正常流程**：
  1. 用户把间隔设为 N 分钟（最小 1）
  2. 应用每隔 N 分钟看一次当前等待数，再刷新角标
  3. 终端中途进入或离开等待 → 角标不立即变，要等下一次检查
**用户看到的反馈**：感觉像"隔一阵才会提醒"，避免频繁打扰；具体间隔由用户自己设。
**结束状态**：长期运行，按节拍刷新。
**异常情况**：用户在设置里把间隔改成更短 / 更长 → 下一次检查按新间隔执行。
**相关**：REQ-TERM_NOTIFY-014、[M14-REQ-ONBOARD_PREFS-012]

### REQ-TERM_NOTIFY-013 Dock 角标 - 关闭模式

**触发方式**：用户设为"关闭"。
**前置条件**：无。
**正常流程**：应用图标永远不显示数字角标，无论多少终端在等待。
**用户看到的反馈**：图标始终干净，仅 Tile 徽标与右下角卡片在工作。
**结束状态**：图标无角标。
**相关**：REQ-TERM_NOTIFY-018、[M14-REQ-ONBOARD_PREFS-011]

### REQ-TERM_NOTIFY-014 Dock 角标数字含义

**触发方式**：角标显示时。
**前置条件**：当前处于实时或定时模式。
**数字规则**：
  - 数字等于"当前等待中的终端总数"（每个终端最多贡献 1，不因单终端有多个问答而加）
  - 0 时角标消失
  - 上限无硬约束，但本应用同时最多 20 个终端 → 角标最大 20
**用户看到的反馈**：用户看到数字即知道"还有几个终端在等我"。
**相关**：REQ-TERM_NOTIFY-011、REQ-TERM_NOTIFY-012、[M01-REQ-TERM_LIFECYCLE-030]

### REQ-TERM_NOTIFY-015 非 macOS 平台降级

**触发方式**：应用启动时自动判定当前系统。
**前置条件**：系统是 Windows 或 Linux。
**正常流程**：
  1. 偏好设置里整块"Dock 角标通知"（含间隔）都不显示
  2. Tile 徽标、红色脉冲、外框光晕、右下角卡片 仍完全正常
**用户看到的反馈**：Windows / Linux 上没有应用图标数字角标，也不会看到相关设置项。
**结束状态**：通知能力仅限应用窗口内，不占任务栏/图标层。
**异常情况**：无。
**相关**：REQ-TERM_NOTIFY-011、REQ-TERM_NOTIFY-012、REQ-TERM_NOTIFY-013

### REQ-TERM_NOTIFY-016 侧栏预览的等待标记

**触发方式**：聚焦模式下某个侧栏小预览对应的终端进入等待。
**前置条件**：当前在聚焦模式，该终端不是主终端。
**正常流程**：
  1. 侧栏小预览的状态点变红并脉冲
  2. 用户点这个小预览
  3. 该终端成为新的主终端，红色视觉随即清除
**用户看到的反馈**：小预览里也能明显看出"这个在等我"。
**结束状态**：用户关注后视觉清除，回到常规预览外观。
**相关**：[M03-REQ-TERM_FOCUS-007]、REQ-TERM_NOTIFY-004

### REQ-TERM_NOTIFY-017 通知优先级视觉一致性

**规则**：
  - 单终端等待与多终端等待在视觉表现上完全一致（每个都独立脉冲），不因数量增大放大个别终端的视觉
  - 右下角卡片只有一张，文案用数字表达聚合度
  - Dock 角标也只一个数字
**用户感受**：不会因为同时 5 个终端等待而造成屏幕红色溢出；聚合层（卡片 + 角标）负责"数量感"，单终端层（徽标 + 外框）负责"具体位置感"。
**相关**：REQ-TERM_NOTIFY-003、REQ-TERM_NOTIFY-007

### REQ-TERM_NOTIFY-018 用户主动静音（偏好路径）

**触发方式**：用户把"Dock 角标通知"设为"关闭"，或在右下角卡片上点 ✕。
**前置条件**：无。
**两条路径的区别**：
  - **永久静音**：偏好里设为"关闭" → Dock 角标再也不出现；Tile 徽标与右下角卡片不受影响
  - **本次忽略**：右下角卡片点 ✕ → 本次会话内不再弹卡片，但数字变化时会重置为可再弹；Tile 徽标与 Dock 角标不受影响
**用户看到的反馈**：用户可以选择"只是这次烦了"还是"我不想要这类提醒"，两者清晰分层。
**相关**：REQ-TERM_NOTIFY-009、REQ-TERM_NOTIFY-013、[M14-REQ-ONBOARD_PREFS-011]

## 6. 主要用户旅程

### Journey 1：首次看到终端等待并学会处理

1. **用户** 第一次让 Claude 在某个终端跑长任务
   → **用户所见**：终端状态点是绿色呼吸
   → **用户感受**："它在干活"
2. **用户** 稍微走神看别处
   → **用户所见**：没变化
   → **用户感受**：继续等
3. **Claude** 问了 "Do you want to proceed? (y/n)"
   → **用户所见**：状态点秒变红并快速呼吸，标题右边冒出一个红色数字"1"徽标，整个终端框有了红色光晕
   → **用户感受**："诶？是不是在叫我"
4. **用户** 把视线移回这个终端，点进去
   → **用户所见**：所有红色瞬间消失，状态点回到绿色
   → **用户感受**：心里有个确认——"它看到我了"
5. **用户** 输入 y 并回车
   → **用户所见**：终端继续跑，回到日常绿色
   → **用户感受**：整条流程顺畅，下次碰到还会用同样方式处理

### Journey 2：切到聊天面板被右下角卡片呼唤

1. **你** 正在终端里盯一个 Claude 会话，同时有另一个终端在后台跑脚本
   → **你看到**：两个终端都绿色
2. **你** 左侧点开"聊天历史"面板想查一条旧消息
   → **你看到**：主区被聊天历史占满，终端平铺不再可见
3. **你** 在翻历史的时候，后台那个脚本刚好问了一个确认
   → **你看到**：屏幕右下角滑出一个红色描边的小卡片，写着"1 等待操作"，左边一颗脉冲红点
   → **你感受**：马上意识到有个终端在等
4. **你** 点一下卡片主体
   → **你看到**：聊天历史面板被关闭，界面立即回到终端视图，那个红色脉冲的终端就在眼前
5. **你** 直接点进去回 y
   → **你看到**：红色视觉消失，终端继续运行
   → **你感受**：没切错、没漏消息，回得很准

### Journey 3：同时多个等待 + Dock 角标兜底

1. **你** 早上打开 Muxvo，挂着 5 个终端在跑不同任务，自己去开早会
   → **你看到**：出门前所有终端都绿色
2. **开会中** 其中 3 个终端先后进入等待
   → **你看到**：你不在电脑前，看不到 Tile 徽标
3. **你** 瞥一眼桌面 Dock
   → **你看到**：Muxvo 图标右上有个红底白字"3"
   → **你感受**："三个在等我，先别急开别的"
4. **你** 点 Dock 图标切回 Muxvo
   → **你看到**：回到终端平铺视图，三个终端都是红色脉冲；同时因为你本就处于终端视图，不会再弹右下角卡片
5. **你** 一个一个点进去回复
   → **你看到**：每回一个，Dock 角标数字减 1，对应终端的外框光晕和徽标消失
6. **你** 回完第三个
   → **你看到**：Dock 角标消失，界面回到"5 个终端都在正常运行"的状态
   → **你感受**：被系统兜住了，没漏掉任何一个

## 7. 界面规格

### 7.1 页面/面板清单

| 名称 | 作用 | 进入方式 | 退出方式 |
|---|---|---|---|
| Tile 上的等待视觉 | 在具体终端上提示"这个在等" | 终端进入等待时自动出现 | 用户点入或输入完成后自动消失 |
| 右下角全局通知卡片 | 跨终端聚合提醒 | 满足条件时自动滑出 | 等待数归 0 / 点卡片 / 点 ✕ |
| macOS Dock 角标 | 应用外的最外层兜底 | 按偏好模式显示 | 等待数归 0 / 偏好改为关闭 |

### 7.2 各页关键区域

**Tile 上的等待视觉**：
- 标题左侧：红色脉冲状态点
- 标题中部偏右：红色圆形数字"1"徽标
- 整个 tile 外框：红色半透明描边 + 光晕

**右下角全局通知卡片**：
- 位置：固定在视口右下角，距底 16 像素、距右 16 像素
- 最大宽度：约 280 像素
- 左侧：8×8 像素红色脉冲圆点
- 中部：文字 "N 等待操作"（"等待操作"为国际化文案）
- 右上：灰色 ✕ 按钮

**macOS Dock 角标**：
- 位置：macOS 系统在应用图标右上角绘制
- 样式：红底白字数字（由系统渲染，不可定制颜色）

### 7.3 五态规格

**Tile 上的等待视觉**

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 从未进入等待 → 状态点绿色、无徽标、无红框 | 正常使用终端 |
| **加载态** | 不适用：本模块无加载过程，状态切换是即时的 | — |
| **正常态** | 状态点红色脉冲、数字"1"徽标、外框红色光晕三者同步 | 点进去、输入回复 |
| **错误态** | 终端意外断开 → 红色视觉立即消失（让位给状态点的灰色"断开") | — |
| **受限态** | 不适用：等待通知不依赖登录或权限 | — |

**右下角全局通知卡片**

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 没有终端在等 / 用户在终端视图 → 卡片不出现 | 无 |
| **加载态** | 不适用 | — |
| **正常态** | 小卡片悬停在右下角，显示"N 等待操作"、脉冲圆点、✕ | 点主体跳回终端 / 点 ✕ 暂时忽略 |
| **错误态** | 卡片从不报错：真遇异常 → 卡片不出现 | — |
| **受限态** | 不适用 | — |

**macOS Dock 角标**

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 偏好为关闭 → 永远无角标；非 macOS → 永远无角标 | 改偏好 |
| **加载态** | 定时模式首次应用间隔前短暂可能是旧值 | 稍等 |
| **正常态** | 图标右上红底白字数字 | 点 Dock 图标激活应用 |
| **错误态** | 不适用 | — |
| **受限态** | 非 macOS 平台天然受限 | — |

### 7.4 文案示例

> 单终端等待：`1 等待操作`
> 多终端等待：`3 等待操作` / `12 等待操作`
> 英文：`1 Waiting` / `3 Waiting`
> 设置项标题：`Dock 角标通知`（英：`Dock Badge`）
> 设置项副文案：`终端等待输入时在 Dock 图标上显示数字角标`
> 三段式按钮：`关闭` / `实时` / `定时`（英：`Off` / `Real-time` / `Timed`）
> 间隔单位："分钟"（英：`min`）

## 8. 状态与交互规则

### 8.1 可见状态清单

- **终端运行中**：状态点绿色缓呼吸，无徽标，无外框光晕
- **终端等待输入**：状态点红色快呼吸 + 数字"1"徽标 + 外框红色光晕
- **全局卡片隐藏**：用户在终端视图 或 等待数为 0 或 用户已点 ✕
- **全局卡片可见**：用户在非终端面板 且 等待数 ≥ 1 且 未被本轮 ✕ 抑制
- **Dock 角标隐藏**：模式为关闭 / 非 macOS / 等待数为 0
- **Dock 角标可见**：模式为实时或定时 且 等待数 ≥ 1 且 macOS 平台

### 8.2 状态切换触发

| 用户做 A | 看到 B |
|---|---|
| 终端进入等待 | Tile 三件套（脉冲点 + 徽标 + 外框光晕）同时出现 |
| 点入等待中的终端 | 三件套消失，状态点变绿 |
| 在等待终端里敲字并回车 | 三件套消失，状态点变绿 |
| 切到非终端面板且有等待 | 右下角滑出全局卡片 |
| 点全局卡片主体 | 关闭所有面板，回到终端视图 |
| 点全局卡片 ✕ | 卡片消失，等待数不变时不再出现 |
| 等待数从 N 变 N-1 | 卡片数字递减 / N=0 时卡片消失 |
| 偏好把 Dock 模式改为实时 | Dock 角标立刻出现（若有等待） |
| 偏好把 Dock 模式改为关闭 | Dock 角标立刻消失 |

### 8.3 快捷键与手势

本模块无独立快捷键。所有通知的"消除"都通过点击终端本身、点击卡片、或直接输入回复完成。

### 8.4 多窗口/多标签行为

本版本仅有单主窗口，通知仅在主窗口内生效。若未来出现多窗口，Dock 角标始终反映全部窗口的总等待数，右下角卡片各窗口独立。

## 9. 边界、限制与异常

- **数量限制**：同时最多 20 个终端 → Dock 角标数字最大 20；右下角卡片文案按实际数显示，无上限截断
- **定时间隔**：最小 1 分钟，无明示上限；非法输入（空、0、负数、字母）一律归 1
- **全局卡片宽度**：约 280 像素，文案长度不会爆边
- **明确不支持**：
  1. 不支持"为某个终端单独关闭通知"（通知是全局的）
  2. 不支持自定义徽标颜色、自定义脉冲速度
  3. 不支持声音提醒
  4. 不支持弹出系统原生通知横幅
  5. 不支持徽标数字显示"未读问答数"（始终是"1"，一个终端只算一次）
  6. 不支持在 Windows / Linux 的任务栏图标上模拟角标
- **错误提示文案**：本模块本身不产生错误对话框；异常情况由 [M15 APP_RELIABILITY] 统一处理
- **数据丢失风险**：无。通知是纯视觉瞬态，不持久化任何用户数据

## 10. 明确不做的事（Out of Scope）

1. **系统原生通知横幅**（如 macOS 通知中心弹卡）。理由：需要权限请求、容易打扰；如用户强烈需求再考虑。
2. **声音 / 震动提醒**。理由：默认打扰程度高，偏好配置复杂；等社区反馈再评估。
3. **徽标数字显示未回答问题数**（同一终端多个 prompt 合并计数）。理由：难以可靠识别"几个问题"，反而容易误导；保持"1 代表这个终端在等"。
4. **通知历史列表**。理由：当前是纯瞬态提醒，不需要回看。
5. **按终端名字在卡片上列出具体等待中的终端名**。理由：280 像素容不下；优先保证简洁。
6. **Windows / Linux 的任务栏角标**。理由：各平台机制差异大、维护成本高，当前仅 macOS Dock 有原生能力。
7. **给等待状态加自定义超时**（如"等 30 分钟没回就当已超时"）。理由：终端本身的命令有自己的超时逻辑，应用层不介入。

### 11.1 本模块独有术语
