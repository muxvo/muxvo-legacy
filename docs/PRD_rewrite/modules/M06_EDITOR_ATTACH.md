# M06 EDITOR_ATTACH – 编辑器附件与图片粘贴 PRD

> 版本 v1.0 · 适用 Muxvo Rust 重构 · 行数上限 575

## 1. 模块定位

- **一句话**：让用户把截图、图片、文件带进富编辑器，和文字一起发给 Claude / Codex / Gemini CLI。
- **不用它会怎样**：用户没法把报错截图、设计稿、日志文件直接给 AI 看，只能退回到"先存文件 → 再手敲路径"的两步动作，体感倒退 10 年。
- **与相邻模块的分界**：
  - 附件的粘贴、拖入、缩略图、删除、上限提示 属于本模块
  - 纯文本输入、草稿保留、撤销重做 属于 [M05 EDITOR_INPUT]
  - 发送按键（Enter / Cmd+Enter）、发送后编辑器清空 属于 [M07 EDITOR_SEND]
  - 附件发送到具体 CLI 的行为差异（Claude Code 剪贴板方式 vs 路径方式）属于 [M07 EDITOR_SEND]
  - 文件面板里预览图片 属于 [M11 FILE_PANEL] / [M12 FILE_VIEWER]

## 2. 目标用户与场景

### 主要用户画像

- **让 AI 看截图的开发者**：本地跑出一个报错或 UI bug，Cmd+Shift+4 截图后直接 Cmd+V 粘到编辑器里，一句话"为什么会这样？"就发出去。每天若干次。
- **做设计对齐的前端作者**：手上有一张 Figma 导出的 png，拖到编辑器里配文字"按这个布局改一下"发给 Claude。一周 3-5 次。
- **给 AI 一段日志或示例文件的运维**：把一个日志文件或配置文件拖进编辑器，让 AI 读完再回答。这种情况附件不是图片，但同样需要挂上来。

### Top3 使用场景

**场景 1 — 粘贴报错截图问原因**：用户在浏览器里看到一个红色报错，截图后切回 Muxvo 的终端，光标停在编辑器里，按 Cmd+V。编辑器出现一个小缩略图，上面悬停时右上角露出一个 × 号。用户在缩略图后面敲一句"这个 null 是从哪冒出来的？"，按 Enter 发送。

**场景 2 — 拖拽设计稿开始改版**：用户从访达里把一张 `mockup.png` 拖进某个终端的编辑器框。拖进来的瞬间，编辑器整体出现一圈琥珀色描边表示"可以在这松手"。松手后缩略图出现在编辑器最前方，用户继续敲"把 header 改成左右布局"后发送。

**场景 3 — 附件太大被提示精简**：用户想把一张 8 MB 的 4K 原图粘进编辑器。编辑器短暂显示"读取中"，然后弹出一条提示"这张图片超出 5 MB 上限，请先压缩再试"。附件区没有留下任何缩略图，用户重新截一张小一点的再试。

### 使用频率

高频用户每天 10-30 次粘贴或拖入附件；低频用户每周若干次。附件出现在编辑器里的时间通常很短（从粘贴到发送一般不超过 30 秒），是典型的"用完就丢"的一次性资源。

## 5. 详细需求条目

### REQ-EDITOR_ATTACH-001 粘贴剪贴板图片

**触发方式**：用户在编辑器里按 Cmd+V（macOS）或 Ctrl+V（Windows / Linux）。
**前置条件**：剪贴板里有图片；编辑器当前可见且接收键盘（见 [M05-REQ-EDITOR_INPUT-001]）；附件数量未达上限。
**正常流程**：
  1. 用户按下粘贴键
  2. 附件区立刻出现一个正在转圈的小方块
  3. 约 0.5-1.5 秒后，方块变成这张图的缩略图
**用户看到的反馈**：占位方块的转圈图标、缩略图淡入替换占位的动画。
**结束状态**：附件区出现新缩略图，光标停留在文字输入区，用户可以继续敲字。
**异常情况**：图片大于 5 MB → 见 REQ-EDITOR_ATTACH-011；格式不是 PNG/JPG/GIF → 见 REQ-EDITOR_ATTACH-012；读取失败 → 见 REQ-EDITOR_ATTACH-010。
**相关**：[M05-REQ-EDITOR_INPUT-001]、[M07-REQ-EDITOR_SEND-001]。

### REQ-EDITOR_ATTACH-002 拖拽图片进编辑器

**触发方式**：用户从访达 / 资源管理器把图片文件拖到编辑器区域。
**前置条件**：编辑器当前可见；附件数量未达上限。
**正常流程**：
  1. 用户拖动文件进入编辑器的矩形范围
  2. 编辑器整体浮现一圈琥珀色描边，中间显示"松开以添加附件"
  3. 用户松开鼠标
  4. 每个被拖入的图片依次出现占位 → 缩略图
**用户看到的反馈**：琥珀色描边、提示文案、缩略图出现动画。
**结束状态**：附件区多了对应数量的缩略图；描边和提示消失。
**异常情况**：中途拖出编辑器外再松手 → 描边消失、不添加；任一图片超限 / 格式不支持 → 该图片单独被拒并提示，其他图片正常添加。

### REQ-EDITOR_ATTACH-003 拖拽非图片文件

**触发方式**：用户拖入日志文件、配置文件、PDF 等非图片文件。
**前置条件**：编辑器当前可见；附件数量未达上限。
**正常流程**：
  1. 用户拖入文件，编辑器描边变琥珀
  2. 松手后附件区出现一个"带文件图标 + 文件名"的占位块（与图片缩略图形态不同）
**用户看到的反馈**：文件图标（通用占位图）+ 文件名（过长时省略号截断）。
**结束状态**：附件区多了一个文件块，用户可继续敲字或删除。
**异常情况**：文件不存在 / 读取失败 → 变成红色错误块，见 REQ-EDITOR_ATTACH-010。

### REQ-EDITOR_ATTACH-004 加号按钮挑附件

**触发方式**：用户点击编辑器左下角的"+"按钮。
**前置条件**：编辑器当前可见；附件数量未达上限。
**正常流程**：
  1. 用户点击"+"
  2. 弹出操作系统原生的文件选择窗口
  3. 用户选 1 个或多个文件后确认
  4. 所选文件依次出现在附件区（走 001 / 003 同一套流程）
**用户看到的反馈**：系统文件窗口、附件依次出现。
**结束状态**：系统窗口关闭，附件区更新。
**异常情况**：用户点"取消" → 无变化；选的文件超限 → 弹出超限提示。

### REQ-EDITOR_ATTACH-005 多附件横向排列

**触发方式**：附件区有 2 个及以上附件时自动触发。
**前置条件**：附件数量 ≥ 2。
**正常流程**：附件区从左到右排列，每个缩略图等宽等高，缩略图之间留固定缝隙。附件数量超过一行宽度时自动折到下一行。
**用户看到的反馈**：排列整齐的一行或多行缩略图。
**结束状态**：用户一眼看清所有已附加的东西。
**异常情况**：单行放不下 5 个缩略图时 → 折到下一行，文字输入区顺势下移。

### REQ-EDITOR_ATTACH-006 缩略图删除按钮

**触发方式**：鼠标悬停在已有缩略图上。
**前置条件**：附件区有至少 1 个附件。
**正常流程**：
  1. 鼠标移到缩略图上
  2. 缩略图右上角出现一个圆形 × 按钮
  3. 用户点击 ×
  4. 这个附件从附件区移除，其余附件向左补位
**用户看到的反馈**：× 按钮的悬停淡入、点击后附件消失的动画。
**结束状态**：附件区少一项；编辑器文字内容保持不变。
**异常情况**：无。
**相关**：[M05-REQ-EDITOR_INPUT-005]（删除附件不影响草稿文字）。

### REQ-EDITOR_ATTACH-007 加载中占位

**触发方式**：用户开始粘贴 / 拖入 / 选择附件的瞬间。
**前置条件**：附件尚未读完。
**正常流程**：
  1. 附件区立刻出现一个灰色方块
  2. 方块中间是一个转圈图标
  3. 读取完成后方块被正式缩略图 / 文件块替换
**用户看到的反馈**：灰底、转圈动画。
**结束状态**：占位被替换为成功态或错误态。
**异常情况**：读取超时 → 见 REQ-EDITOR_ATTACH-010。

### REQ-EDITOR_ATTACH-008 成功态缩略图

**触发方式**：附件读取完成。
**前置条件**：图片格式合法、大小合法。
**正常流程**：占位方块变为这张图的缩略图（等比例裁切居中），缩略图有细边框与圆角，悬停出现 × 按钮。
**用户看到的反馈**：缩略图淡入覆盖占位。
**结束状态**：附件区多一张可删除的缩略图。
**异常情况**：无。

### REQ-EDITOR_ATTACH-009 失败态错误块

**触发方式**：读取过程中出错（文件损坏、无权限、超时等用户可感知的失败）。
**前置条件**：已进入加载态。
**正常流程**：
  1. 占位方块变红，中间出现感叹号图标
  2. 鼠标悬停显示"读取失败，请重试"
  3. 用户点击该块可直接将其移除
**用户看到的反馈**：红色块 + 感叹号 + tooltip。
**结束状态**：失败的附件被移除或由用户手动删除。
**异常情况**：无。

### REQ-EDITOR_ATTACH-010 超大文件拒绝

**触发方式**：附件读取时发现大小超过单个 5 MB 上限。
**前置条件**：用户刚粘贴 / 拖入 / 选择了图片。
**正常流程**：
  1. 占位方块出现后立刻消失
  2. 编辑器底部弹出红色提示条"这张图片超出 5 MB 上限，请先压缩再试"
  3. 附件区保持原样，超限图片未被添加
**用户看到的反馈**：提示条从编辑器下方滑入，停留数秒后淡出。
**结束状态**：附件区无变化；用户可以重新挑一张更小的图。
**异常情况**：一次拖入多张图时，只有超限的那一张被拒，其他正常添加。
**相关**：[M15-REQ-APP_RELIABILITY-??]（错误提示统一样式，待确认）。

### REQ-EDITOR_ATTACH-011 不支持格式拒绝

**触发方式**：附件读取时发现不是 PNG / JPG / GIF。
**前置条件**：用户粘贴 / 拖入 / 选择了非支持格式的图片（如 BMP、WEBP、HEIC、TIFF）。
**正常流程**：
  1. 占位方块立刻消失
  2. 编辑器底部弹出提示"仅支持 PNG / JPG / GIF 格式的图片"
**用户看到的反馈**：提示条弹出。
**结束状态**：附件区无变化。
**异常情况**：无。

### REQ-EDITOR_ATTACH-012 附件数量上限

**触发方式**：用户在附件数量已到 5 时继续添加。
**前置条件**：当前附件数量 = 5。
**正常流程**：新附件不被添加；编辑器底部弹出提示"每条消息最多 5 个附件，请先发送或删除"。
**用户看到的反馈**：提示条弹出；"+"按钮在鼠标悬停时变灰 tooltip 提示"已达上限"。
**结束状态**：附件数量维持 5。
**异常情况**：无。

### REQ-EDITOR_ATTACH-013 删除附件

见 REQ-EDITOR_ATTACH-006。

### REQ-EDITOR_ATTACH-014 发送后清空附件区

**触发方式**：用户按 Enter / Cmd+Enter 触发发送（见 [M07-REQ-EDITOR_SEND-001]）。
**前置条件**：附件区至少有一个附件，且所有附件都处于成功态。
**正常流程**：
  1. 用户按发送键
  2. 消息连同附件一起送出
  3. 编辑器的文字清空，附件区的所有缩略图一并消失
**用户看到的反馈**：附件区缩略图消失动画、编辑器高度回缩。
**结束状态**：编辑器回到完全空白状态，等待下一次输入。
**异常情况**：存在加载态附件 → 发送被阻止，提示"还有附件正在处理，请稍候"；存在失败态附件 → 发送被阻止，提示"有附件读取失败，请删除后重试"。
**相关**：[M07-REQ-EDITOR_SEND-001]、[M07-REQ-EDITOR_SEND-002]。

### REQ-EDITOR_ATTACH-015 模式切换时附件区隐藏

**触发方式**：当前终端从富编辑器模式自动切换到原生终端模式（例如用户在终端里启动 vim / htop 这类全屏 TUI）。
**前置条件**：附件区有附件；用户的前台程序触发了全屏 TUI。
**正常流程**：编辑器整体隐藏，附件区也随之不可见；用户退出 vim 后附件仍在原位重新出现（会话期内不丢）。
**用户看到的反馈**：编辑器淡出；回到富编辑器模式时淡入。
**结束状态**：附件保留但临时不可见。
**异常情况**：若会话本身被关闭 → 附件连同编辑器一起清除，见 [M01-REQ-TERM_LIFECYCLE-??]。

## 6. 主要用户旅程

### Journey 1：新手第一次粘截图

1. **你** 第一次装 Muxvo，打开一个终端让 Claude Code 跑起来
   → **所见**：主区底部是带光标的编辑器空框。
   → **感受**：这像个聊天框，应该能粘点东西。
2. **你** 切到浏览器截了一张报错的图，切回 Muxvo，光标落在编辑器，按 Cmd+V
   → **所见**：附件区立刻出现一个灰色方块在转圈。
   → **感受**：哦它在处理。
3. **你** 等不到 1 秒，方块变成缩略图
   → **所见**：一张小小的截图浮在编辑器上方。
   → **感受**：成了。
4. **你** 把鼠标悬到缩略图上
   → **所见**：右上角出现一个圆圆的 ×。
   → **感受**：知道怎么删了。
5. **你** 在缩略图下方敲"这个报错是为什么"
   → **所见**：文字正常出现在输入区，缩略图保持不动。
6. **你** 按 Enter
   → **所见**：附件和文字一起消失，编辑器重新变空；终端里随即出现 AI 的回复。
   → **感受**：完全够用。

### Journey 2：老手一次贴 3 张图带文字发送

1. **你** 熟练地用截图工具连续截了 3 张屏，剪贴板里是多图
2. **你** 在编辑器里按 Cmd+V
   → **所见**：附件区从左到右一连出现 3 个灰色方块，依次变成缩略图。
3. **你** 发现第 2 张不是你想要的
   → **所见**：悬停它的 × 按钮。
4. **你** 点 ×
   → **所见**：第 2 张消失，第 3 张向左补位。
5. **你** 接着往后敲"对比这两张的 spacing 差异"
6. **你** 按 Cmd+Enter 发送
   → **所见**：附件连同文字一起清空，回到空编辑器。
   → **感受**：流畅。

### Journey 3：异常恢复 — 附件读取失败和超大图

1. **你** 把一张 8 MB 的 4K 原图拖进编辑器
   → **所见**：琥珀色描边亮起，松手后出现占位方块。
2. **你** 等了半秒，方块消失
   → **所见**：编辑器下方弹出一条红色提示"这张图片超出 5 MB 上限，请先压缩再试"。
   → **感受**：哦，这张太大。
3. **你** 用预览压缩到 3 MB 再拖进来
   → **所见**：这次占位正常变成缩略图。
4. **你** 又拖进来一个已经损坏的文件
   → **所见**：占位方块过一会儿变红，中间有感叹号。
5. **你** 鼠标悬上去
   → **所见**：tooltip 提示"读取失败，请重试"。
6. **你** 点一下这个红块，它被移除。
7. **你** 敲字发送剩下那张有效的图
   → **所见**：发送成功，附件区清空。
   → **感受**：出错不耽误正事。

## 7. 界面规格

### 7.1 页面/面板清单

| 名称 | 作用 | 进入方式 | 退出方式 |
|---|---|---|---|
| 附件区 | 显示当前编辑器已附加的所有缩略图/文件块 | 添加第 1 个附件时自动出现 | 附件全部删除 / 发送后自动隐藏 |
| 附件错误提示条 | 显示粘贴/拖入失败的原因 | 附件被拒时自动出现 | 数秒后自动淡出 |
| 加号按钮菜单 | 打开系统文件选择窗口 | 点击编辑器左下角"+" | 选完 / 取消 |

附件区不是独立页面，而是富编辑器上方的一行水平区域，和文字输入区同属编辑器覆盖层。

### 7.2 各页关键区域

**附件区**（位于编辑器顶部，横跨编辑器宽度）：
- **左右两端**：无标题、无按钮，左右留出与编辑器边缘对齐的内边距
- **主区**：从左到右排列缩略图 / 文件块，等间距，等大小
- **缩略图**：正方形（固定尺寸），圆角、细边框；悬停时右上角露出 × 按钮
- **文件块**：与缩略图等高，左侧是通用文件图标，右侧是文件名（过长截断），同样悬停露 ×

**加号按钮**：位于编辑器文字输入区的左下角，是一个圆形小按钮，与发送键（见 [M07]）视觉对齐。

**错误提示条**：位于编辑器下沿外侧，整个编辑器宽度，红色背景、白色文字，不阻挡编辑器内容。

### 7.3 五态规格

**附件区**：

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 附件区不占位，编辑器只有文字输入区 | 粘贴 / 拖入 / 点"+"添加第一个附件 |
| **加载态** | 附件区出现灰色方块，中间是转圈图标 | 按 Ctrl+C 可取消该次读取（穿透到终端信号，见 [M05]）|
| **正常态** | 附件区有 1-5 个缩略图 / 文件块，整齐排列 | 悬停删除 / 继续添加 / 发送 |
| **错误态** | 附件区有红色错误块 + 底部错误提示条 | 点击红块移除 / 重新选文件 |
| **受限态** | "+"按钮变灰、悬停 tooltip 显示"已达上限" | 先删除或发送腾出位置 |

### 7.4 文案示例

> 加载态占位：（无文字，仅转圈图标）
> 成功态缩略图：（无文字，仅图片本身）
> 失败态悬停 tooltip："读取失败，请重试"
> 超大图提示："这张图片超出 5 MB 上限，请先压缩再试"
> 格式不支持提示："仅支持 PNG / JPG / GIF 格式的图片"
> 数量上限提示："每条消息最多 5 个附件，请先发送或删除"
> 加号按钮悬停 tooltip（正常）："添加图片或文件"
> 加号按钮悬停 tooltip（受限）："已达附件上限"
> 发送时还在读取："还有附件正在处理，请稍候"
> 发送时有失败项："有附件读取失败，请删除后重试"
> 拖拽悬停提示："松开以添加附件"

## 8. 状态与交互规则

### 8.1 可见状态清单

每个附件在用户眼中的 5 态：
- **加载中**：灰色占位方块 + 转圈图标
- **成功**：正方形缩略图（图片）或带图标的文件块（非图片）
- **失败**：红色方块 + 感叹号图标
- **超限**：不出现在附件区，直接以底部提示条形式通知
- **被拒**：不出现在附件区，直接以底部提示条形式通知（区别于超限：文案指向格式而非大小）

附件区整体的 3 态：
- **无附件**：附件区折叠不占高度
- **有附件**：附件区展开显示所有缩略图
- **编辑器隐藏态**：当前终端自动切到原生终端模式时附件区同步隐藏

### 8.2 状态切换触发

- 用户按 Cmd+V / Ctrl+V → 附件进入加载中
- 读取成功 → 加载中 → 成功
- 读取失败 → 加载中 → 失败
- 文件大小检测超限 → 不进入附件区，弹超限提示
- 格式检测不通过 → 不进入附件区，弹被拒提示
- 用户点击 × → 从附件区移除
- 用户按发送键 → 所有成功态附件连同文字一起送出，附件区清空
- 终端切到 vim / htop → 编辑器隐藏，附件区同步隐藏但数据保留
- 终端关闭 → 附件连同编辑器一起销毁

### 8.3 快捷键与手势

| 按键/手势 | 作用 | 前置条件 |
|---|---|---|
| Cmd+V / Ctrl+V | 从剪贴板添加图片附件 | 焦点在编辑器 + 附件未满 |
| 从访达/资源管理器拖入 | 添加图片或文件附件 | 拖动目标落在编辑器范围内 |
| 点击 "+" 按钮 | 打开系统文件选择窗口 | 附件未满 |
| 悬停缩略图 → 点 × | 删除该附件 | 附件处于成功或失败态 |
| Ctrl+C | 若附件正在加载中，取消该次读取；否则穿透到终端（见 [M05]） | 焦点在编辑器 |
| Enter / Cmd+Enter | 连同附件发送（见 [M07]） | 所有附件处于成功态 |

### 8.4 多窗口/多标签行为

- 每个终端的附件区相互独立，切换终端时看到的是该终端自己的附件状态
- 附件只存在于当前会话的内存中，Muxvo 退出后不保留（发送前未发送的附件会丢失，见 §9 数据丢失风险）

## 9. 边界、限制与异常

### 数量限制

- 每条消息最多 **5 个附件**（图片 + 文件合计）
- 单个图片附件最大 **5 MB**
- 每条消息附件总大小最大 **20 MB**（5 个 × 4 MB 余量，待与产品对齐）
- 支持的图片格式：**PNG / JPG / GIF**
- 非图片附件：任意常见文本或二进制文件都可添加（具体如何送达 CLI 见 [M07]）
- 附件读取超时阈值：**10 秒**（超时判为失败）

### 明确不支持

- 附件不支持视频、音频（用户可能期待但本版不做）
- 附件不支持文件夹（拖入一个目录会被整体拒绝）
- 附件不支持编辑（不能裁剪、旋转、涂鸦）
- 附件粘贴不支持从网页直接拖图片链接（只接受本地文件系统中的文件）
- 附件不支持重新排序（缩略图位置由添加顺序决定，删除后向左补位）
- 附件不支持"部分发送"（要么全发，要么全删）

### 错误提示文案

> **超大**："这张图片超出 5 MB 上限，请先压缩再试"
> **不支持格式**："仅支持 PNG / JPG / GIF 格式的图片"
> **数量上限**："每条消息最多 5 个附件，请先发送或删除"
> **读取失败**："读取失败，请重试"
> **发送时还在加载**："还有附件正在处理，请稍候"
> **发送时有失败项**："有附件读取失败，请删除后重试"
> **拖入文件夹**："不支持拖入整个文件夹"

### 数据丢失风险

- **编辑器未发送就关闭终端** → 附件和文字一起丢弃，不持久保留；风险提示：关闭有附件的终端时，用户先看到确认对话框（见 [M01-REQ-TERM_LIFECYCLE-??]）
- **Muxvo 崩溃重启** → 未发送的附件丢失（文字草稿由 [M05] 保留，附件本次不保留）
- **同一附件反复粘贴** → 每次都是一次新的读取，不去重

## 10. 明确不做的事（Out of Scope）

1. **附件编辑（裁剪、旋转、马赛克、涂鸦）** — 用户期待但本版不做，Muxvo 定位是传话筒而不是图片编辑器；有第三方截图工具已经做得很好。再考虑条件：出现大量"截图 + 涂鸦"需求（估计 V2 以后）。
2. **附件持久化草稿** — 未发送的附件不像文字那样跨会话保留。再考虑条件：用户明确反馈"崩溃后图丢了很难受"。
3. **粘贴网页图片 URL** — 不会自动下载远程图片转成本地附件。再考虑条件：接入 Skill 市场后图片分享变成高频。
4. **拖入整个文件夹** — 会被整体拒绝，不自动展开。
5. **附件 OCR / 自动文字提取** — 本版不处理图片内容的识别，直接把原图交给 CLI。
6. **附件重新排序** — 用户不能手动调整附件顺序。
7. **附件部分发送** — 不支持"发送其中 2 张，保留另外 3 张"。
8. **视频 / 音频附件** — 不在本次范围。
9. **附件上限的个人化配置** — 不开放"让我设 10 个附件"的偏好设置。

## 11. 附：术语与跨模块引用

### 11.1 本模块独有术语

| 术语 | 定义 |
|---|---|
| 附件区 | 富编辑器上方的一行（或多行）区域，显示当前消息已附加的缩略图和文件块 |
| 缩略图 | 图片附件的正方形小预览，圆角细边框，悬停露出 × 按钮 |
| 文件块 | 非图片附件的显示形态，左侧通用文件图标，右侧文件名 |
| 加载中占位 | 附件正在读取时显示的灰色转圈方块 |
| 错误块 | 附件读取失败的红色方块 + 感叹号图标 |
| 错误提示条 | 附件被超限 / 格式被拒时从编辑器下沿弹出的红色文字横条 |
| 加号按钮 | 编辑器左下角的圆形按钮，点击后打开系统文件选择 |

### 11.2 引用的其他模块

- [M01 TERM_LIFECYCLE] — 终端关闭时附件连同编辑器销毁；关闭有附件的终端需要确认对话框
- [M05 EDITOR_INPUT] — 富编辑器模式判断、Ctrl+C 穿透规则、文字草稿独立于附件
- [M07 EDITOR_SEND] — 发送键触发、附件送达各 CLI 的具体方式（剪贴板 vs 文件路径）、发送后编辑器整体清空
- [M11 FILE_PANEL] / [M12 FILE_VIEWER] — 文件面板里的图片预览是另一套视图，与编辑器附件无交互
- [M14 ONBOARD_PREFS] — 附件上限数值属于系统内置，不进用户偏好（见 §10.9）
- [M15 APP_RELIABILITY] — 错误提示条的统一视觉样式

### 11.3 待确认项

- **附件总大小 20 MB 的硬上限** — 测试文档只明确了单图 5 MB，总量未写，20 MB 是推理值，待与产品对齐。
- **非图片附件的送达方式** — 归属 [M07]，但本模块描述"文件块出现在附件区"时默认用户知道它会随文本一起发送；具体机制待 M07 交付后回填引用。
- **附件错误提示条停留时长** — 文案示例写"数秒后淡出"，具体几秒待与设计对齐（建议 4 秒）。
- **Ctrl+C 取消加载中附件** 的行为是否与 [M05] 的 Ctrl+C 穿透冲突 — 待 M05 交付后对齐：本模块倾向"有加载中附件时 Ctrl+C 优先取消附件，否则穿透"。
- **拖拽多文件时其中一张超限** — 本模块定义为"单独拒绝该张，其他正常添加"，需与产品确认是否更偏好"整批拒绝"。
- **加载超时阈值 10 秒** — 推理值，待确认。
- **非图片文件有没有大小上限** — 测试文档只写了图片的 5 MB，非图片未写，建议同步沿用，待对齐。
