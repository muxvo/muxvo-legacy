# M12 FILE_VIEWER – 文件三栏临时视图 PRD

> 版本 v1.0 · 适用 Muxvo 重构 · 行数上限 575

## 1. 模块定位

- **一句话**：点开一个文件后全屏覆盖出现的"左树 / 中预览 / 右终端栏"三栏浮层，让用户不离开 Muxvo 就能读写多种类型的文件。
- **不用它会怎样**：用户只能靠终端里 `cat`、`less`、系统自带的图片/PDF 应用来看文件，读 Markdown 没法看到渲染效果，修 CLAUDE.md 要跳到 VS Code，工作流被频繁打断。
- **与相邻模块的分界**：
  - 三栏临时视图的进入、布局、分栏拖拽、中列文件预览（Markdown / 代码 / 图片 / PDF / 电子表格）、未保存提示、退出方式 属于本模块
  - 从终端右侧滑出的文件面板（列表型浏览器）属于 [M11 FILE_PANEL]
  - Skills / Plans / Tasks / Memory 等配置资源的 Markdown 编辑器 属于 [M13 CONFIG_MGMT]（复用同一个底层组件，但用户视角是"在配置管理器里编辑"）
  - 三栏默认宽度、"默认显示隐藏文件"等偏好默认值 属于 [M14 ONBOARD_PREFS]
  - 终端本体、终端标题栏、文件改动徽标同步 属于 [M01 / M02 / M15]

## 2. 目标用户与场景

### 主要用户画像

- **CLI 重度用户**：一天里会频繁让 Claude Code 生成或修改 Markdown 文档、代码、配置文件，需要在终端旁边快速瞥一眼改成了什么样。
- **Skill 作者**：在项目里维护 Skill 的 README、规范文档、样例图片，需要一边看文档一边让终端跑脚本验证。
- **新手**：对"在终端之外还能看文件"毫无概念，期望像在文件管理器里那样双击打开一个文件就能看到内容。

### Top3 使用场景

**场景 1 — 看 Claude 刚生成的 Markdown**：用户让 Claude Code 生成了一份技术方案。他从文件面板双击 `PLAN.md`。屏幕进入三栏视图，中栏以带格式的方式渲染 Markdown（标题、列表、代码块、表格、流程图全都显示正常），他滚动阅读、心里确认，再按 Esc 回到终端继续对话。

**场景 2 — 顺手改一个配置**：用户发现 Claude 生成的 `README.md` 有两处错别字。他在三栏视图里直接点击段落，以所见即所得方式改掉；顶部文件名旁出现一个小圆点，提示"有未保存修改"；按 ⌘S 保存，圆点消失。整个过程不需要打开外部编辑器。

**场景 3 — 左树多文件浏览 + 右栏终端对照**：用户打开了项目里的一个 `.pdf` 规格书，一边翻页一边看右栏里这个项目对应的终端缩略图（终端还在跑命令）。他从左树切换到另一个 `.xlsx` 报表检查数据，切换时系统会提醒他"当前文件有未保存修改，要保存吗"。

### 使用频率

日常中频。CLI 重度用户每天会进入 5-20 次三栏视图，每次停留从十几秒（瞥一眼）到几分钟（改文档、读 PDF 规格）不等。本模块承担"在 Muxvo 内完成的阅读和轻编辑"。

## 5. 详细需求条目

### REQ-FILE_VIEWER-001  从文件面板进入三栏视图

**触发方式**：用户在 [M11 FILE_PANEL] 文件面板中点击一个文件条目。
**前置条件**：该文件可读；文件大小在本模块的上限内（§9）。
**正常流程**：
  1. 文件面板消失。
  2. 屏幕以淡入方式出现三栏浮层，覆盖整个终端网格。
  3. 左列加载当前项目的文件树，中列加载刚点击的文件内容，右列加载相关终端缩略图。
**用户看到的反馈**：短暂的入场动画（约 0.2-0.3 秒），随后三栏内容逐步就位。
**结束状态**：三栏视图停留在"正常态"，用户可以阅读或编辑中列内容。
**异常情况**：
- 文件读取失败 → 中列区域显示失败提示（详见 §9）。
- 文件类型完全不支持 → 中列以纯文本方式尝试显示（REQ-FILE_VIEWER-029）。

**相关**：[M11-REQ-010]

### REQ-FILE_VIEWER-002  三栏浮层覆盖整个屏幕

**触发方式**：任何进入本模块的路径。
**正常流程**：三栏视图是一个全屏覆层，位于终端网格之上；进入期间用户看不到、也不能直接操作原终端网格。
**用户看到的反馈**：屏幕"变"成了左树 + 中预览 + 右终端栏的新布局。
**结束状态**：保持到用户退出为止。
**异常情况**：退出后终端网格恢复为进入前的状态（焦点、布局都不变）。

### REQ-FILE_VIEWER-003  进入/退出动画

**触发方式**：进入或退出三栏视图时自动触发。
**正常流程**：进入时三栏整体淡入；退出时整体淡出，持续约 0.2-0.3 秒；右列终端缩略图略晚一点点再出现，避免所有元素同时 pop。
**用户看到的反馈**：平滑的过场，不是瞬间切换。
**异常情况**：动画期间用户的新操作会等动画结束后响应。

### REQ-FILE_VIEWER-004 ~ 010  左列文件树基本能力

**触发方式**：进入三栏视图后自动加载；期间用户可点击展开、折叠、切换文件。
**正常流程**：
  1. 从项目根目录读取一级条目，文件夹排在文件前面，按名称字母排序；默认不显示以 "." 开头的条目。
  2. 顶部左侧显示项目名（取路径最后一段，兜底为 "~"），右侧有一个"眼睛"按钮切换是否显示点开头条目（与 [M11 FILE_PANEL] 的偏好保持一致）。
  3. 单击文件夹：已折叠则读取内容插入下方并缩进一层；已展开则收起其下方所有后代条目。
  4. 当前中列显示的文件，其对应的树条目自动高亮一行。
  5. 打开深层文件时，系统自动把从项目根到该文件所在目录的所有上级文件夹逐层展开，并把该文件行滚动到可见区域。
**用户看到的反馈**：一份整齐、熟悉的项目树；高亮行让用户一眼知道自己在看哪个文件；深层文件也不会"迷路"。
**异常情况**：
- 某个子目录读取失败 → 该文件夹保持"已展开"图标但下方没有子条目。
- 自动展开祖先期间用户又点了另一个文件 → 以新的文件为准。

**相关**：[M11-REQ-004 ~ 008]

### REQ-FILE_VIEWER-011  左列右键菜单

**触发方式**：用户右键点击左树里的某个条目。
**正常流程**：弹出系统原生右键菜单，内容与 [M11-REQ-017 / 018 / 019] 保持一致："复制路径"、"在 Finder 中打开"，以及仅对文件显示的"用默认应用打开"。
**用户看到的反馈**：熟悉的右键菜单在光标位置出现。
**异常情况**：右键点击树空白区域 → 不弹菜单。

### REQ-FILE_VIEWER-012  拖拽文件到终端

**触发方式**：用户按住左树里的文件条目拖拽。
**正常流程**：文件可被拖到右列终端缩略图，松开后对应终端的输入区插入完整路径。
**相关**：[M05 EDITOR_INPUT]

### REQ-FILE_VIEWER-013 / 014  Markdown 渲染视图（默认） + 流程图

**触发方式**：用户打开扩展名被识别为 Markdown 的文件（典型为 `.md`）。
**正常流程**：
  1. 中列顶部类型标签显示 "MD"。
  2. 中列正文以所见即所得的方式呈现 Markdown：标题分层、粗体斜体、有/无序列表、勾选列表、代码块（等宽字体 + 背景）、表格、引用、水平线、链接、图片占位。
  3. 文档中 `mermaid` 语言的代码块自动渲染为流程图、时序图、甘特图等图形，而不是源代码。
  4. 用户可以滚动阅读、选中复制，或点击编辑（见 REQ-FILE_VIEWER-015）。
**用户看到的反馈**：像在阅读一份格式化好的文档。
**异常情况**：
- 文档里有无法识别的语法 → 按纯文本段落显示，不崩溃。
- 流程图语法错误 → 原位显示源代码并标记为"渲染失败"。

### REQ-FILE_VIEWER-015  Markdown 所见即所得编辑

**触发方式**：用户在渲染视图里点击任意段落并开始输入。
**前置条件**：文件类型是 Markdown，当前中列是渲染视图（非源码模式）。
**正常流程**：
  1. 点击位置出现光标，可以像在富文本编辑器里一样修改内容。
  2. 支持常见操作：换行（回车）、删除、粘贴文本、修改列表层级等。
  3. 任一修改都会立即在顶部文件名左侧触发一个小圆点，提示"有未保存修改"。
**用户看到的反馈**：文字以最终排版样子变化；标题仍是标题、列表仍是列表。
**结束状态**：修改保留在内存里，等待 ⌘S 保存或用户选择放弃。
**异常情况**：
- 用户修改的内容破坏了某种复杂语法 → 保存后下次打开可能以纯文本显示，不会丢失文字本身。
- 用户在渲染视图下修改了流程图代码块 → 切到源码模式后可见源代码；保存仍是纯文本。

### REQ-FILE_VIEWER-016  Markdown 源码模式切换

**触发方式**：用户按 ⌘/，或点击顶部工具栏上的"源码"/"可视"切换按钮。
**前置条件**：当前打开的是 Markdown 文件。
**正常流程**：
  1. 中列在两种视图间切换：默认为"渲染视图"（所见即所得），切换后为"源码视图"（纯文本编辑，看得到 `#`、`*`、`[]()` 等原始符号）。
  2. 按钮文案在"源码 / 可视"之间切换。
  3. 切换不丢失修改；未保存圆点保留。
**用户看到的反馈**：同一份文字一会儿是带样式的文档，一会儿是带符号的源代码。
**异常情况**：切换时文件已被外部改动 → 使用用户当前编辑中的内容，不自动覆盖。

### REQ-FILE_VIEWER-017  代码/文本预览编辑

**触发方式**：用户打开一个被识别为代码或纯文本的文件（例如 `.ts`、`.py`、`.rs`、`.json`、`.txt` 等）。
**正常流程**：
  1. 中列顶部类型标签显示 "CODE" 或 "TXT"。
  2. 中列正文以等宽字体显示全部内容。
  3. 用户可以选中复制、键入修改，与编辑文本一样。
  4. 任一修改触发未保存圆点。
**用户看到的反馈**：一个全屏、等宽的文本编辑区，容纳整个文件内容。
**异常情况**：
- 文件里有无法显示的字节 → 用替代符号显示，不崩溃。
- 超大文件（参见 §9）→ 不进入本视图，直接提示过大。

**说明**：本模块不对代码做彩色语法高亮；如果用户需要彩色阅读体验，建议用系统默认应用（右键菜单）。这是本期的已知取舍，详见 §10。

### REQ-FILE_VIEWER-018  图片预览

**触发方式**：用户打开常见图片类型（例如 `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.svg` 等）。
**正常流程**：中列以"适应宽度"方式居中显示整张图片；顶部类型标签显示 "IMG"。
**用户看到的反馈**：一眼看到完整图片，不会显示一半。
**异常情况**：
- 图片损坏 → 显示一个占位符 + "无法预览此图片"文案。
- 图片超过上限 → 给出"此图片过大，无法预览"提示。

**说明**：本期不支持图片缩放、旋转、拖动查看细节（详见 §10）。

### REQ-FILE_VIEWER-019 / 020  PDF 分页与缩放

**触发方式**：用户打开一个 `.pdf` 文件。
**前置条件**：文件大小在上限内。
**正常流程**：
  1. 中列顶部出现 PDF 专用工具条："上一页 / 页码指示（"当前 / 总页数"）/ 下一页 / 缩小 / 缩放百分比 / 放大"。
  2. 中列主体显示当前页。
  3. 默认初始缩放约为 150%，支持 50% 到 400% 之间步进调整。
  4. 已到首页时"上一页"按钮变灰；已到末页时"下一页"变灰；缩放到上下限时对应按钮也会变灰。
**用户看到的反馈**：类似浏览器内置 PDF 阅读器，熟悉且可靠。
**异常情况**：
- PDF 解析失败 → 中列显示"无法读取此 PDF"。
- 加载期间用户频繁切页 → 只保留最新一次请求的结果，不会出现跳页闪烁。

**说明**：本期 PDF 视图为只读，不支持批注、高亮、文字选择复制、搜索（详见 §10）。

### REQ-FILE_VIEWER-021 ~ 024  电子表格预览与编辑

**触发方式**：用户打开 `.xlsx` 或 `.xls` 文件。
**正常流程**：
  1. 中列顶部类型标签显示 "XLS"；主体以表格形式显示当前 Sheet，每行带行号、每格带原始值。
  2. 多 Sheet 文件上方出现 Sheet 标签栏，点击切换。
  3. 单击单元格进入编辑态；Enter 提交、Esc 取消、Tab/Shift+Tab 提交并跳到右/左邻单元格。任一提交触发未保存圆点。
  4. 单 Sheet 显示上限 1000 行；超过时底部显示"当前显示前 1000 行，共 N 行"。
**用户看到的反馈**：像一个简化版的电子表格工具，能看、能小改。
**异常情况**：
- 文件无法读为电子表格 → "无法读取此电子表格"。
- 含有公式、图表、数据透视等 → 本期只显示单元格当前值，不显示公式、不渲染图表（详见 §10）。

### REQ-FILE_VIEWER-025  顶部文件名 + 类型标签

**触发方式**：进入三栏视图或切换文件时自动刷新。
**正常流程**：中列顶部居左显示文件名，居右显示一个类型标签（MD / CODE / TXT / IMG / XLS / PDF），最右是退出按钮。
**用户看到的反馈**：时刻知道"我在看哪个文件"。

### REQ-FILE_VIEWER-026  未保存修改圆点

**触发方式**：中列内容被修改（Markdown 渲染视图、源码视图、代码/文本视图、电子表格单元格提交均会触发）。
**正常流程**：顶部文件名左侧出现一个小圆点；保存成功后圆点消失；若用户放弃修改，圆点也消失。
**用户看到的反馈**：一个简洁的视觉提醒，不打扰主区阅读。

### REQ-FILE_VIEWER-027  ⌘S 保存

**触发方式**：用户按 ⌘S（Windows 为 Ctrl+S）。
**前置条件**：中列可编辑且存在未保存修改。
**正常流程**：
  1. 系统把当前内容写回原文件。
  2. 成功：圆点消失；中列内容保留。
  3. 失败：弹出简短错误提示，圆点不消失，用户可再次尝试。
**用户看到的反馈**：按键立即响应，不跳页、不离开当前文件。
**异常情况**：
- 文件已被外部删除 → 提示"文件已不存在"。
- 磁盘已满 / 权限不足 → 提示"保存失败，请检查文件权限"。

### REQ-FILE_VIEWER-028  退出按钮 ←

**触发方式**：用户点击中列顶部的 ← 返回箭头（悬停提示 "Esc"）。
**正常流程**：等同于按 Esc 退出。
**用户看到的反馈**：图形化的退出入口，对鼠标用户更友好。

### REQ-FILE_VIEWER-029  未知/二进制类型的降级显示

**触发方式**：用户打开一个文件扩展名不属于 Markdown / 代码 / 纯文本 / 图片 / PDF / 电子表格的文件（例如 `.log`、`.ini`、无扩展名）。
**正常流程**：本期统一尝试以纯文本方式显示；顶部类型标签显示 "TXT"。
**用户看到的反馈**：一致的、可预期的降级体验。
**异常情况**：
- 内容中包含大量不可打印字节（真正的二进制文件）→ 显示的内容会出现奇怪字符；建议用户通过右键菜单"用默认应用打开"交给系统处理。
- 超大文件 → 按 §9 的上限规则给出明确提示。

**说明**：本期不提供十六进制查看器，详见 §10。

### REQ-FILE_VIEWER-030 / 031  右列相关终端缩略图

**触发方式**：进入三栏视图时自动加载。
**前置条件**：用户从某个终端的文件面板进入本视图。
**正常流程**：
  1. 右列出现一个或多个小型终端缩略图，内容为用户从哪个终端进入的那个终端的实时画面。
  2. 每个缩略图下方显示终端标题。
  3. 用户点击某个缩略图：三栏视图关闭，屏幕回到终端网格，焦点落在被点击的终端上。
  4. 若用户是从一个单独终端（而非多终端网格）进入的，右列依然会显示其缩略图。
  5. 若当前没有相关终端可显示，右列整个隐藏，中列自然拉宽（不会留空白占位）。
**用户看到的反馈**：阅读或编辑时能余光瞥到终端进展；需要切回去时一键直达。
**异常情况**：
- 终端已结束 → 缩略图立即移除；若移除后无任何终端，右列隐藏。
- 终端太多（典型为 4+）→ 右列可纵向滚动查看更多缩略图。

**相关**：[M02-REQ-NNN]（终端网格）、[M03-REQ-NNN]（终端焦点）

### REQ-FILE_VIEWER-032 ~ 034  三栏默认宽度 / 拖拽 / 持久化

**触发方式**：首次进入使用默认宽度；用户可随时拖拽左/右分割线调整。
**正常流程**：
  1. 首次进入：左栏默认约 200 像素，右栏默认约 280 像素，中栏占据剩余空间。
  2. 按住左栏或右栏的分割线拖动，鼠标光标变为左右箭头，目标栏宽度随鼠标变化，中栏相应伸缩。
  3. 每栏有最小/最大宽度限制，无法被拖到消失或吞掉中栏。
  4. 松开鼠标时当前宽度被记住，下次进入三栏视图采用记住的值。
**用户看到的反馈**：像经典 IDE 一样可自定义布局；下次回来熟悉的比例仍在。
**异常情况**：屏幕变小或中栏曾被挤得很窄时本期不会自动重置，由用户手动再拖。默认值由 [M14 ONBOARD_PREFS] 决定。

**相关**：[M14-REQ-NNN]

### REQ-FILE_VIEWER-035 ~ 037  未保存提示对话框

**触发方式**：有未保存修改时，用户点击左树里另一个文件，或按 Esc / 点击返回按钮尝试退出。
**正常流程**：
  1. 屏幕中央弹出模态对话框，标题"未保存的修改"，正文"「文件名」有未保存的修改"。
  2. 三个按钮：**保存**（写回原文件后继续执行刚才的动作）、**放弃**（丢弃修改后继续）、**取消**（停留在当前文件）。
  3. 背景变暗、不可穿透；按 Esc 等同于"取消"。
**用户看到的反馈**：明确的三选一，不会被"意外点外部"偷偷关掉。
**异常情况**：点击"保存"后写入失败 → 对话框保留，原因提示在对话框内，用户可再试或改点"放弃"/"取消"。

### REQ-FILE_VIEWER-038 / 039  Esc / 返回按钮关闭

**触发方式**：用户按 Esc，或点击中列顶部的 ← 按钮。
**正常流程**：
  1. 若无未保存修改：三栏视图以淡出动画关闭，屏幕恢复到终端网格。
  2. 若有未保存修改：先弹出"未保存修改"对话框（REQ-FILE_VIEWER-037）。
**用户看到的反馈**：熟悉的退出快捷键始终生效；意外退出不会丢失修改。
**相关**：[M02-REQ-NNN]（终端网格恢复）

### REQ-FILE_VIEWER-040  大文件上限

**触发方式**：用户点击一个超过上限的文件。
**正常流程**：中列不尝试加载全文，直接显示"此文件过大，无法在 Muxvo 内预览。建议通过右键菜单用系统默认应用打开。"
**用户看到的反馈**：不会因为加载大文件导致界面卡顿或无响应。
**异常情况**：详见 §9 的上限数值与具体文案。

## 6. 主要用户旅程

### Journey 1：新手第一次看到一份 Markdown

1. **你** 在文件面板里双击项目根目录下的 `README.md`。
   → **你所见**：文件面板消失，屏幕淡入新布局：左边项目树、中间带标题/粗体/代码块的"漂亮文档"、右边一个小型终端缩略图。
   → **你感受**：第一眼就舒服，全在 Muxvo 里。
2. **你** 滚动中列阅读 README。
   → **你所见**：标题分层清晰，代码块有底色，文档里的流程图直接是图片。
   → **你感受**：不用再开外部软件。
3. **你** 看完按 Esc，三栏淡出，屏幕回到之前的终端，焦点全在原处。
   → **你感受**："哦，这就是个临时浮层"，读文档和跑 CLI 之间几乎零切换成本。

### Journey 2：老手一边改 CLAUDE.md 一边看终端

1. **你** 让 Claude 起草了一份项目级 CLAUDE.md，然后从文件面板双击打开。
   → **你所见**：进入三栏视图；中列是渲染视图，左树自动展开到文件所在位置并高亮当前行，右列是你刚才那个终端的缩略图。
2. **你** 点击文档中一段描述做编辑，把措辞改得更清晰。
   → **你所见**：文字立刻跟着改变；文件名左侧出现小圆点。
3. **你** 按 ⌘/ 切到源码模式，检查修改后的源代码是不是干净的。
   → **你所见**：中列变为带 `#` `*` 的纯文本视图，修改一字不少。
4. **你** 再按 ⌘/ 切回渲染视图，按 ⌘S 保存，圆点消失。
5. **你** 瞥一眼右列终端缩略图，看到命令已经跑完，点击它。
   → **你所见**：三栏视图关闭，屏幕回到那个终端的全尺寸视图。
   → **你感受**：从写文档到动命令的切换像呼吸一样自然。

### Journey 3：切换文件但有未保存修改

1. **你** 正在改 `notes.md`，有几处未保存（文件名旁有圆点）。
2. **你** 从左树里点击另一份 `plan.md`。
   → **你所见**：屏幕中央弹出对话框："notes.md 有未保存的修改"，三个按钮：保存、放弃、取消。
   → **你感受**：差点忘了改没改完；幸好被拦了。
3. **你** 选"保存"。对话框消失、圆点消失；中列平滑切换为 plan.md 的渲染内容。
4. **你** 读完 plan.md，按 Esc 退出，三栏淡出，终端恢复。
5. **你** 下次再打开三栏视图，左栏和右栏的宽度仍然是上次调好的比例。
   → **你感受**：细节到位。

## 7. 界面规格

### 7.1 页面/面板清单

| 名称 | 作用 | 进入方式 | 退出方式 |
|---|---|---|---|
| 三栏临时视图（主浮层） | 同时展示项目树、文件预览和相关终端缩略图 | 从 [M11 FILE_PANEL] 单击文件 | Esc / ← 按钮 / 点击右列终端缩略图 |
| 未保存修改对话框 | 切换文件或退出时提示保存未完成修改 | 有未保存修改时自动弹出 | 保存 / 放弃 / 取消 / Esc |
| PDF 工具条 | 翻页 + 缩放控制 | 打开 PDF 时显示在中列顶部 | 关闭 PDF 或退出三栏视图 |
| Sheet 标签栏 | 在电子表格的多个 Sheet 间切换 | 打开带多个 Sheet 的电子表格时显示 | 关闭电子表格或退出三栏视图 |

### 7.2 各页关键区域

**顶栏（中列）**：文件名 + 未保存圆点（左）；"源码"/"可视"按钮（仅 Markdown）；类型标签（MD / CODE / TXT / IMG / XLS / PDF）；← 返回按钮（右）。

**左列**：顶部是项目名 + "眼睛"开关；下方是可滚动的项目文件树。

**中列**：全屏内容区，随文件类型呈现不同形态。

**右列**：项目相关终端的纵向缩略图列表；与中列之间有可拖拽的分割线；无相关终端时整列隐藏。

**左右栏与中栏之间**：两条可拖拽的分割线，悬停时鼠标变为左右箭头。

**浮层**：未保存修改对话框在屏幕中央，背景变暗不可穿透。

### 7.3 五态规格（三栏临时视图主页面）

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 打开了一个空的纯文本/代码文件：中列是空白编辑区，可立即键入 | 键入内容后保存 |
| **加载态** | 打开 PDF / 大电子表格 / 大图片时短暂显示"Loading…" | 等待 / Esc 退出 |
| **正常态** | 左树、中预览、右终端栏三栏内容全部就位 | 阅读、编辑、切换文件、保存、退出 |
| **错误态** | 中列显示"无法读取此文件" / "无法预览此图片" / "此文件过大" 等明确提示 | 切换到另一文件 / 退出视图 / 用右键菜单交给系统默认应用 |
| **受限态** | 左树中某子目录不可读；或文件写入因权限被拒绝 | 查看其它可读目录 / 退出视图 |

### 7.4 文案示例

> 类型标签：`MD` / `CODE` / `TXT` / `IMG` / `XLS` / `PDF`
> 未保存圆点悬停提示："有未保存的修改"
> 未保存对话框标题："未保存的修改"
> 未保存对话框正文："「{文件名}」有未保存的修改"
> 未保存对话框按钮："保存" / "放弃" / "取消"
> 大文件错误："此文件过大，无法在 Muxvo 内预览。建议通过右键菜单用系统默认应用打开。"
> PDF 解析失败："无法读取此 PDF"
> 电子表格截断提示："当前显示前 1000 行，共 N 行"
> 电子表格无法读取："无法读取此电子表格"
> 图片损坏："无法预览此图片"
> 保存失败："保存失败，请检查文件权限"
> 文件不存在："文件已不存在"

### 8.2 状态切换触发

- **做**：在文件面板点击一个文件 → **看到**：三栏浮层淡入，进入正常态。
- **做**：点击左树里另一个文件（无未保存修改）→ **看到**：中列内容切换，顶部文件名更新。

- **做**：按 ⌘S → **看到**：圆点消失；失败时出现提示。
- **做**：按 Esc / 点击 ← / 点击右列终端缩略图（无未保存）→ **看到**：三栏浮层淡出。
- **做**：按 Esc / 点击 ← （有未保存）→ **看到**：未保存对话框。
- **做**：拖拽左或右分割线 → **看到**：对应栏宽度变化；松开后宽度被记住。

### 8.3 快捷键与手势

| 按键/手势 | 作用 | 前置条件 |
|---|---|---|
| 单击文件面板中的文件 | 进入三栏临时视图 | 面板已打开 |
| 单击左树中的文件 | 中列切换到该文件 | 三栏视图已打开 |
| 单击左树中的文件夹 | 展开或折叠 | 左树已加载 |
| 拖拽左分割线 | 调整左栏宽度 | 三栏视图已打开；有最小/最大限制 |
| 拖拽右分割线 | 调整右栏宽度 | 右列有相关终端时可用 |
| ⌘S / Ctrl+S | 保存当前文件 | 中列有未保存修改 |
| ⌘/ / Ctrl+/ | 切换 Markdown 渲染视图 ↔ 源码视图 | 当前文件是 Markdown |
| Esc | 退出三栏视图 / 取消未保存对话框 | — |
| 点击中列顶部 ← | 退出三栏视图 | — |
| 右键点击左树条目 | 打开右键菜单 | — |
| 拖拽左树文件到右列终端 | 向终端输入区送入路径 | 终端缩略图存在 |
| 单元格点击 → 输入 → Enter | 提交电子表格单元格编辑 | 当前是电子表格 |

### 8.4 多窗口/多标签行为

本期只在同一个 Muxvo 窗口内使用三栏临时视图；不存在"多窗口同时打开同一文件"的情形。切换到另一个项目的终端会关闭当前三栏视图，由新的文件面板重新进入。

## 9. 边界、限制与异常

### 数量限制

- **中列电子表格显示行数上限**：单 Sheet 1000 行；超过时表格底部出现明确提示，超出部分不在本视图内显示。
- **PDF 缩放范围**：50% ~ 400%，步进 25%。
- **左/右栏宽度**：有最小值（避免被拖到消失）和最大值（避免吞掉中栏）；具体像素见下。
- **默认宽度**：左栏约 200、右栏约 280（像素），首次使用的默认值由 [M14 ONBOARD_PREFS] 决定。
- **拖拽上下限**：左/右栏宽度可在约 80 到 700 像素之间调整。
- **同时打开的三栏视图**：同一时间只有一个。
- **大文件上限**（待产品最终确认）：文本/代码约 10 MB；图片约 20 MB；PDF 约 50 MB；电子表格约 10 MB。超过时不加载，直接进错误态。

### 明确不支持

- 不提供代码的语法高亮色彩（只做等宽排版 + 行号）。
- 不提供代码的智能补全、格式化、跳转定义等 IDE 能力。
- 不提供 PDF 的文字选择复制、全文搜索、批注、高亮、缩略图面板、侧栏目录。
- 不提供 PDF 的滚动连续翻页（本期以"上一页 / 下一页"为主）。
- 不提供图片缩放、旋转、拖动查看细节。
- 不提供电子表格的公式编辑、图表展示、数据透视、筛选排序。
- 不提供十六进制查看器；二进制文件只给出降级的纯文本尝试。
- 不提供多文件 Tab（一个时刻只有一个"当前文件"）。
- 不提供跨项目打开文件（左树只显示进入时那个项目的内容）。
- 不提供在三栏视图里新建文件、重命名、删除（这些由文件面板的右键菜单或终端完成）。
- 不提供文件的 Diff 视图或版本对比。
- 不自动重新加载外部改动的文件（需用户关闭再打开）。

### 错误提示文案

所有文案都已在 §7.4 列出，用户看到的每一种错误都附带一个自然语言建议（通常是"切换文件"或"用系统默认应用打开"）。

### 数据丢失风险

- **风险**：用户在渲染/源码视图里做了修改但没保存就退出 → 保障措施：进入未保存对话框，提供"保存"入口。
- **风险**：切换文件时修改被冲掉 → 保障措施：切换时也触发未保存对话框。
- **风险**：保存写入失败 → 保障措施：圆点保持存在，错误提示给出原因，用户可以重试或换动作。
- **风险**：用户点击面板外的区域误关 → 保障措施：三栏视图不响应"点击外部关闭"，只认 Esc / ← 按钮（与 [M11 FILE_PANEL] 不同，这是本模块的"保护性差异"）。

## 10. 明确不做的事（Out of Scope）

1. **代码彩色语法高亮**：成本较高且易受语言种类拖累；等到 Muxvo 稳定后再单独立项（"需要时再看"）。
2. **PDF 批注 / 搜索 / 目录**：用户可通过右键"用默认应用打开"交给系统 PDF 阅读器。
3. **图片缩放与平移**：等真实用户反馈需要时再做；当前"适应宽度"能覆盖 90% 场景。
4. **电子表格的公式 / 图表 / 筛选**：这是一个完整的子领域，本期不做；用户可用系统默认应用打开。
5. **十六进制 / 二进制结构化查看**：属于开发者小众需求，优先级低。
6. **多 Tab 同时打开多个文件**：会让本浮层变成"迷你编辑器"，偏离"临时视图"定位。
7. **Diff / 版本比较**：属于源码管理功能域，本期不做。
8. **文件外部改动自动刷新**：降低了对"我看到的就是我正在编辑的"这一点的信心，本期手动关闭再打开更稳。
9. **跨项目文件浏览**：三栏视图的左树锁定在进入时的项目内，避免用户在浮层里迷路。
10. **三栏内的新建/重命名/删除**：这些操作由文件面板或终端承担。

## 11. 附：术语与跨模块引用

### 11.1 本模块独有术语

| 术语 | 定义 |
|---|---|
| 三栏临时视图 | 覆盖在终端网格之上的浮层，包含左树、中预览、右终端栏 |
| 中列 / 中栏 | 三栏视图中间区域，显示当前打开文件的预览或编辑视图 |
| 渲染视图 | Markdown 的所见即所得形态（默认） |
| 源码视图 | Markdown 的纯文本原文编辑形态（⌘/ 切换） |
| 未保存圆点 | 文件名左侧的小圆点，表示内容有未保存修改 |
| Sheet 标签栏 | 电子表格多个工作表的切换标签 |
| 相关终端缩略图 | 右栏显示的、与本次进入相关的终端小图 |

### 11.2 引用的其他模块

- [M11-REQ-010]（从文件面板打开文件）
- [M11-REQ-017 / 018 / 019]（右键菜单项）
- [M11-REQ-004 ~ 008]（文件树基本规则与本模块保持一致）
- [M02-REQ-NNN]（终端网格隐藏与恢复）
- [M03-REQ-NNN]（点击缩略图恢复焦点）
- [M05 EDITOR_INPUT]（拖拽路径到终端输入区）
- [M14-REQ-NNN]（默认宽度与"显示隐藏文件"默认值）
- [M15 APP_RELIABILITY]（文件外部变动的全局体感）

### 11.3 待确认项

- **大文件上限数值**：§9 给出的初步上限（10 MB 文本 / 20 MB 图片 / 50 MB PDF / 10 MB 表格）需与产品最终对齐。
- **是否支持代码语法高亮**：本期标为"不支持"；若用户反馈强烈，可提级到 P1 再做。
- **PDF 是否支持滚动连续翻页**：本期只提供按钮翻页；是否补充滚动模式待定。
- **文件外部改动的自动刷新**：是否在本模块内增加"外部改动提示"待与 [M15 APP_RELIABILITY] 对齐。
- **三栏宽度的最小/最大像素阈值**：当前为 80 / 700，是否开放为偏好设置中的可配置值待定。
- **"相关终端缩略图"的筛选规则**：当前只显示"进入本视图时来源的那个终端"；是否扩展为"同目录下所有终端"待产品定。
