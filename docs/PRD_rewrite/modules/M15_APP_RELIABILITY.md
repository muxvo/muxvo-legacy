# M15 APP_RELIABILITY – 应用生命周期与异常 PRD

> 版本 v1.0 · 适用 Muxvo Rust 重构 · 行数预算 550 行（±15%）

## 1. 模块定位

- 一句话说明：定义用户打开、关闭、崩溃恢复、更新、遇到错误时的"全局感受"。
- 不用本模块用户会损失什么：没有统一的启动 / 退出 / 报错规范，用户会面对风格各异的对话框、不知道什么时候能关、遇到问题无从下手、关错时丢工作。
- 与相邻模块的分界：
  - 应用整体启动流程 / 关闭确认 / 崩溃恢复 / 更新提示 / 离线基调 / 错误对话框视觉规范 属于本模块
  - 单个终端的关闭确认（有运行中进程时）属于 [M01 TERM_LIFECYCLE]
  - Dock 角标的等待输入模式属于 [M04 TERM_NOTIFY]；Dock 角标的总开关偏好属于 [M14 ONBOARD_PREFS]

## 2. 目标用户与场景

- **主要用户画像**：
  - **日常使用者**：每天打开 Muxvo 处理多个终端任务，关心"打开快不快""关不关得掉""会不会丢数据"。
  - **偶发用户**：几天打开一次，关心"上次的东西还在吗""有新版本吗"。
  - **网络不稳定用户**：酒店 / 机场 / 家中 Wi-Fi 漂移，关心"断网时还能不能用"。

- **Top3 使用场景**：
  - **场景 1（首次打开）**：用户双击图标，预期几秒内看到主界面；第一次有引导，非第一次则上次的终端应自动出现。
  - **场景 2（一天结束关掉）**：用户点关闭，有终端时应被提醒"这些东西会被终止"，给一次后悔机会；关掉后下次打开能回到差不多的状态。
  - **场景 3（出错时）**：终端挂了 / 网断了 / 磁盘满了 / 更新失败，用户期望看到一句人话解释 + 明确下一步，而不是一堆乱码。

- **使用频率**：日常 + 全局。本模块在用户每次打开、关闭、切页面时都可能触发，是 Muxvo 的"底色"。

## 5. 详细需求条目

> 为保持紧凑，每条 REQ 用 4 行：触发 + 前置 / 正常流程 / 反馈 + 结束 / 异常 + 相关。

### REQ-APP_RELIABILITY-001 启动画面
- **触发** 双击 Dock / 应用图标 / 命令行启动。**前置** 无。
- **正常流程** 用户双击 → Dock 弹跳 → 1 秒内出现带 Muxvo 标志的深色启动画面 → 主界面加载完后自动替换。
- **反馈与结束** 深色背景 + Muxvo 文字标志 + 淡入动画；停留在主界面或欢迎引导。
- **异常** 启动超过 5 秒——启动画面持续显示，绝不出现白屏。**相关** [M14-REQ-001]

### REQ-APP_RELIABILITY-002 启动时长感知
- **触发** 打开 Muxvo。**前置** 无。
- **正常流程** 首次启动 ≤ 5 秒进入欢迎引导；非首次 ≤ 3 秒进入主界面；未及时进入则启动画面持续显示。
- **反馈与结束** 启动画面中央可有圆点加载指示；最终进入主界面或欢迎引导。
- **异常** 超过 15 秒仍停在启动画面 → 视为异常，用户可强制退出重试。**相关** [M14-REQ-001]

### REQ-APP_RELIABILITY-003 恢复上次终端
- **触发** 打开 Muxvo 时存在上次保存的终端列表。**前置** 上次退出后终端记录未被手动清空。
- **正常流程** 进入主界面 → 按上次顺序逐个恢复终端，名称 / 工作目录保持一致 → 状态点从"正在启动"变为正常。
- **反馈与结束** 终端格子按顺序逐个出现；用户看到与上次几乎一样的主界面。
- **异常** 某终端工作目录已被删除 → 红色状态点 + "重启"按钮；全部恢复失败 → 空主界面无错误弹窗。**相关** [M01]、[M14]

### REQ-APP_RELIABILITY-004 恢复上次窗口尺寸位置
- **触发** 打开 Muxvo。**前置** 上次用户调整过窗口。
- **正常流程** 窗口以上次的宽高和位置出现。
- **反馈与结束** 窗口位置与上次一致；主窗口可见并获得焦点。
- **异常** 上次的外接屏已断开 → 窗口回到主屏幕居中位置，不会跑出屏幕外。**相关** 无

### REQ-APP_RELIABILITY-005 崩溃后自动恢复
- **触发** 上次 Muxvo 因崩溃 / 强杀 / 断电退出。**前置** 用户再次打开 Muxvo。
- **正常流程** 与正常启动同路径恢复终端与偏好。
- **反馈与结束** 终端格子出现 + REQ-006 提示条；用户看到与上次相同的工作区。
- **异常** 终端记录文件损坏 → 空主界面，用户偏好仍保留。**相关** REQ-APP_RELIABILITY-006

### REQ-APP_RELIABILITY-006 崩溃恢复提示条
- **触发** 系统检测到上次是非正常退出。**前置** 同上。
- **正常流程** 主界面顶部中央出现一行浅灰横幅"已从上次意外关闭中恢复" → 5 秒后自动淡出。
- **反馈与结束** 浅灰字体，无关闭按钮；横幅消失。
- **异常** 无。**相关** REQ-APP_RELIABILITY-005

### REQ-APP_RELIABILITY-007 关闭确认：有活跃终端
- **触发** 点窗口关闭按钮 / 按系统退出快捷键 / 右键 Dock"退出"。**前置** 至少有 1 个终端正在运行。
- **正常流程** 窗口不立刻关闭 → 弹出标题"退出 Muxvo" + 正文"当前有 N 个终端正在运行，退出后将全部终止。" → 用户点"退出"或"取消"。
- **反馈与结束** 360 像素宽暗色卡片，琥珀色"退出"+ 透明"取消"；退出 → 应用关闭，取消 → 回到主界面。
- **异常** 再次点关闭 → 重新弹出同一对话框。**相关** REQ-APP_RELIABILITY-009、REQ-APP_RELIABILITY-010

### REQ-APP_RELIABILITY-008 关闭确认：无活跃终端
- **触发** 用户点关闭，当前无任何终端。**前置** 终端数 = 0。
- **正常流程** 同 REQ-007，但正文为"确定要退出 Muxvo 吗？"。
- **反馈与结束** 同 REQ-007。
- **异常** 无。**相关** REQ-APP_RELIABILITY-007

### REQ-APP_RELIABILITY-009 关闭确认 Esc 取消
- **触发** 关闭确认对话框显示中。**前置** 对话框处于焦点。
- **正常流程** 按 Esc → 对话框淡出 → 应用继续运行。
- **反馈与结束** 对话框淡出动画；回到主界面。
- **异常** 无。**相关** REQ-APP_RELIABILITY-007

### REQ-APP_RELIABILITY-010 关闭前保存工作区
- **触发** 用户在关闭确认对话框选"退出"。**前置** 关闭被确认。
- **正常流程** 记录终端列表 + 窗口尺寸与位置 → 关闭所有终端 → 窗口消失。
- **反馈与结束** 关闭过程不超过 2 秒；应用退出。
- **异常** 某终端无响应 → 超过 2 秒后强制终止，用户不会卡在退出状态。**相关** REQ-APP_RELIABILITY-003

### REQ-APP_RELIABILITY-011 单窗口行为
- **触发** Muxvo 已在运行时，用户再次双击图标。**前置** 已有一个 Muxvo 窗口。
- **正常流程** 不出现新窗口 → 原窗口被带到最前 → 若之前最小化则恢复。
- **反馈与结束** 原窗口获得焦点；用户看到原窗口。
- **异常** 无。**相关** 无

### REQ-APP_RELIABILITY-012 更新后台下载
**触发方式**：后台检测到新版本。
**前置条件**：用户联网。
**正常流程**：自动下载 → 不打断用户任何操作 → 完成后等待下次启动应用新版本。
**用户看到的反馈**：菜单栏右侧出现下载指示（REQ-013）。
**结束状态**：更新已就绪。
**异常情况**：下载失败 → REQ-015。
**相关**：REQ-APP_RELIABILITY-013

### REQ-APP_RELIABILITY-013 更新进度指示
**触发方式**：更新下载开始。
**前置条件**：同上。
**正常流程**：菜单栏右侧出现 24 像素圆形指示，内部箭头图标，外圈随进度填满。
**用户看到的反馈**：指示只在下载期间 / 完成 / 失败三种情形出现。
**结束状态**：REQ-015。
**异常情况**：无。
**相关**：REQ-APP_RELIABILITY-014

### REQ-APP_RELIABILITY-014 更新详情悬停
**触发方式**：鼠标悬停到下载指示。
**前置条件**：下载中或刚完成。
**正常流程**：气泡显示"正在下载更新..."+ 进度条 +"12.3 MB / 45.6 MB"+"1.2 MB/s"。
**用户看到的反馈**：悬停气泡。
**结束状态**：移开鼠标后气泡关闭。
**异常情况**：无。
**相关**：REQ-APP_RELIABILITY-013

### REQ-APP_RELIABILITY-015 更新完成/失败提示
**触发方式**：下载结束。
**前置条件**：更新包已完整下载或失败。
**正常流程**：完成 → 圆形指示变绿色对勾，悬停气泡"v1.X.Y 下载完成 / 下次启动时自动更新"，3 秒后淡出；失败 → 变红色叉，气泡"下载失败"，3 秒后淡出。
**用户看到的反馈**：颜色切换 + 淡出动画。
**结束状态**：菜单栏恢复原样。
**异常情况**：无。
**相关**：REQ-APP_RELIABILITY-016、REQ-APP_RELIABILITY-019

### REQ-APP_RELIABILITY-016 重启以应用更新
**触发方式**：更新已下载完成。
**前置条件**：绿色对勾已出现。
**正常流程**：用户下次正常退出并重新打开 → 新版本被应用。
**用户看到的反馈**：重启后通过 REQ-017 看到新版本号。
**结束状态**：用户使用新版本。
**异常情况**：无。
**相关**：REQ-APP_RELIABILITY-017

### REQ-APP_RELIABILITY-017 更新内容弹窗
**触发方式**：首次启动某个新版本。
**前置条件**：上次记录的版本号与当前不同。
**正常流程**：主界面出现约 2 秒后弹窗 → 顶部星号图标 + "更新内容 / What's New" → 正文列出新增 / 变更 / 修复 / 移除 / 弃用 / 安全分组 → 底部"知道了 / Got it"按钮。
**用户看到的反馈**：460 像素弹窗，版本徽章"v1.2.3 2026-04-10"。
**结束状态**：用户点"知道了"或点外部 → 弹窗关闭，后续不再出现。
**异常情况**：本版本无说明 → 显示"v1.2.3 暂无更新说明"。
**相关**：REQ-APP_RELIABILITY-018

### REQ-APP_RELIABILITY-018 更新内容历史
**触发方式**：在更新内容弹窗中下滑。
**前置条件**：弹窗已打开。
**正常流程**：看到"历史版本"区块，点击某个版本号可展开其条目。
**用户看到的反馈**：每个版本默认折叠，点击展开。
**结束状态**：同 REQ-017。
**异常情况**：无。
**相关**：REQ-APP_RELIABILITY-017

### REQ-APP_RELIABILITY-019 离线横幅
**触发方式**：网络不通。
**前置条件**：用户处于任何页面。

## 6. 主要用户旅程

### Journey 1：首次打开 Muxvo（新手视角）

1. **你** 双击 Muxvo 图标
   → **你所见**：Dock 图标弹跳，0.3 秒后出现带 Muxvo 标志的深色启动画面
   → **你感受**：有反馈，不会怀疑启动失败
2. **你** 等待约 2 秒
   → **你所见**：启动画面被欢迎引导替换
   → **你感受**：被带着走
3. **你** 点"开始引导"→ 进入主界面，菜单栏顶部出现 Muxvo 标题和各个标签
4. **你** 点 + 创建第一个终端
5. **你** 点关闭按钮
   → **你所见**：弹窗"当前有 1 个终端正在运行，退出后将全部终止。"
   → **你感受**：被提醒过了，不会误关
6. **你** 点"取消"→ 弹窗消失，终端还在

### Journey 2：日常使用中途遇到新版本（老手视角）

1. **你** 正在操作某个终端
   → **你所见**：菜单栏右侧悄悄出现一个圆形下载指示
   → **你感受**：没被打断
2. **你** 悬停 → 气泡"正在下载更新... 12.3 MB / 45.6 MB  1.2 MB/s"
3. **你** 继续工作几分钟
   → **你所见**：指示变绿色对勾，悬停显示"v1.3.0 下载完成 / 下次启动时自动更新"
4. **你** 3 秒后指示淡出消失
5. **你** 晚上结束工作点关闭按钮 → 确认弹窗 → 点"退出"
6. **你** 第二天重新打开
   → **你所见**：主界面出现约 2 秒后"更新内容"弹窗列出本版本新增条目
   → **你感受**：知道为什么界面有变化

### Journey 3：断网 + 终端崩溃 + 应用崩溃恢复

1. **你** 正在用 2 个终端跑命令
2. **你** 家里 Wi-Fi 突然断了
   → **你所见**：菜单栏下方出现橙色横幅"当前离线，部分功能不可用"
   → **你感受**：知道是网络问题
3. **你** 想打开聊天历史 → 本地已同步的聊天仍可看
4. **你** 其中一个终端前台进程崩溃
   → **你所见**：该终端状态点变红 + "重启"按钮（[M01]）；另一个终端不受影响
5. **你** 点"重启"→ 终端恢复
6. **你** Muxvo 本身被强杀 → 窗口突然消失
7. **你** 重新双击图标
   → **你所见**：主界面恢复，2 个终端都被自动拉回 + 顶部浅灰提示"已从上次意外关闭中恢复"
   → **你感受**：没丢工作
8. **你** 5 秒后浅灰提示自动消失
9. **你** Wi-Fi 恢复 → 橙色横幅淡出

- 关闭确认对话框：显示 / 隐藏

### 8.2 状态切换触发

- 双击图标 → 启动画面
- 主界面加载完 → 启动画面消失

- 点关闭且无终端 → "确定退出"关闭确认

- 首次进入新版本主界面 → 2 秒后弹出更新内容
- 网络断开 → 离线横幅
- 网络恢复 → 横幅淡出
- 内存过阈值 → 内存告警
- 内存降下 → 下次检查后消失
- 非正常退出 → 下次打开时崩溃恢复提示条
- 操作 > 3 秒无响应 → 卡顿浮层

- 多标签（终端 / Skills / 聊天 / 文件）在同一窗口内切换，共享同一份状态，无跨窗口同步需求。

## 9. 边界、限制与异常

- **数量限制**：
  - 同时运行的 Muxvo 主窗口：1 个
  - 启动画面最长允许显示：15 秒
  - 关闭时等待终端清理最长：2 秒
  - 卡顿浮层"处理中"最长显示：15 秒后文案升级

- **明确不支持**：
  - 多窗口并排使用
  - 后台常驻（关闭窗口 = 完全退出）
  - 系统托盘图标 / 菜单栏驻留图标
  - 关闭后仍保留终端在后台运行
  - 用户手动点击触发立即检测更新

- **错误提示文案**（统一原则：**能降级的都不弹窗，只有需要用户立刻决定的才弹错误对话框**）：
  - 启动阶段无法读取终端记录 → 空主界面打开，不弹错误
  - 某终端恢复失败 → 红色状态点 + 重启按钮（[M01]），不弹全局错误
  - 更新下载失败 → 菜单栏红色叉 + 悬停"下载失败"，不弹窗
  - 离线 → 顶部橙色横幅，不弹窗
  - 内存过高 → 黄色三角，不弹窗
  - 非正常退出 → 浅灰提示条，不弹窗
  - 操作卡顿 → 卡顿浮层，不弹窗
  - 日志目录无法写入 → 错误档对话框"无法写入日志目录 / 请检查磁盘空间或权限"

- **数据丢失风险**：
  - 崩溃时：终端记录已实时保存，下次打开可恢复
  - 关闭时：关闭确认给出后悔机会
  - 更新时：下次启动才真正应用新版本
  - **明确告知**：终端内正在运行的未保存数据（如命令尚未落盘）不在恢复范围

## 10. 明确不做的事（Out of Scope）

- **不做**：多窗口并排工作
  - 为什么：单屏工作者为主，多窗口带来数据同步复杂度
  - 何时再考虑：用户反馈量 ≥ 30 且明确提出

- **不做**：系统托盘驻留 / 后台隐藏运行
  - 为什么：Muxvo 是重交互工具，驻留会诱发"以为退出实则仍占资源"的错觉
  - 何时再考虑：引入推送通知后再评估

- **不做**：用户手动触发"立即检查更新"按钮
  - 为什么：后台定期检测已覆盖 99% 场景
  - 何时再考虑：用户明确反馈"想立刻升级"

- **不做**：崩溃上报对话框让用户确认
  - 为什么：打扰用户，应默认静默或不收集
  - 何时再考虑：引入主动反馈机制后

- **不做**：离线时禁用所有页面
  - 为什么：Muxvo 的终端 / 本地文件 / 本地聊天完全离线可用
  - 何时再考虑：永不

- **不做**：应用内内建日志查看器
  - 为什么：日志受众是高级用户，直接打开文件夹足以
  - 何时再考虑：用户反馈"找不到日志"比例 > 10%
