# M05 EDITOR_INPUT – 编辑器输入与草稿 PRD

> 版本 v1.0 · 适用 Muxvo 重构 · 行数预算 425-575 行

## 1. 模块定位

- **一句话**：让用户像写聊天消息一样写命令 / prompt，按 Enter 发走、按 Shift+Enter 换行，切到别的终端不会把草稿弄丢。
- **不用它会怎样**：用户只能直接在终端里敲一行字就发一行字。多行 prompt 要靠反斜杠续行，敲错字要按 ⌫ 一个个删，敲到一半切终端一回来内容就没了。面向 Claude Code / Codex 这种"一次贴几十行上下文"的工具，体验会退化成原始终端。
- **与相邻模块的分界**：
  - 编辑器的"文字输入、多行、占位、撤销、草稿、模式切换、焦点" 属于本模块
  - 编辑器里的"图片附件、截图粘贴、文件拖拽" 属于 [M06 EDITOR_ATTACH]
  - 按下发送键后"怎么把文本送进终端、前台是 Claude Code 还是命令行、发送后的反馈动画" 属于 [M07 EDITOR_SEND]
  - 终端本身的输出渲染、滚动、光标 属于 [M01 TERM_LIFECYCLE]
  - 等待输入红点、Dock 角标 属于 [M04 TERM_NOTIFY]

## 2. 目标用户与场景

### 主要用户画像

- **Claude Code / Codex 用户**：每次 prompt 少则 3 行，多则几十行，里面有代码块、路径、待办清单。需要能反复修改、回看、粘贴，不能敲错一个字就只能重打。
- **Shell 用户**：只敲一行命令，按 Enter 直接走。对编辑器存在感要求低，但不希望每次敲字都要先点一下才有焦点。
- **新手**：第一次打开 Muxvo，看到终端下方有个输入框，会本能地想在里面打字，期望像微信那样"点中就能写，按 Enter 就发"。

### Top3 使用场景

**场景 1 — 写多行 prompt 交给 Claude Code**：用户正在让 Claude Code 帮忙改一段代码，需要把"目标 + 约束 + 代码片段 + 期望输出"一次性贴过去。用户点一下编辑区开始写，遇到段落切换按 Shift+Enter，贴代码直接粘贴，写到一半翻了一下聊天历史，回来发现草稿还在，按 Enter 发走。

**场景 2 — 切到别的终端再切回来**：用户在终端 A 的编辑器里写了半截 prompt，突然想到另一个终端 B 里有个报错要先看，点终端 B 的标题，翻了翻输出，再点回终端 A。编辑器里上次写的那半截内容原样躺在那里，光标还在原来的位置。

**场景 3 — 用命令行工具时把编辑器收起来**：用户在当前终端跑 `vim`，编辑器对他没用反而挤占空间。用户期望 Muxvo 自动把编辑器收起来，让终端吃满整格，等退出 vim 又自动把编辑器放回来。用户也可以手动按一个按钮在两种形态之间切换。

### 使用频率

日常极高频。Claude Code 用户每天会敲 30-80 次回车，每次 prompt 平均 5-15 行；纯命令行用户每天敲 100+ 次短命令；"切终端再切回来"每小时会发生 10+ 次；手动收起编辑器是中频（每次跑交互式工具会触发 1 次）。

## 5. 详细需求条目

### REQ-EDITOR_INPUT-002 默认进入富编辑器形态

**触发方式**：用户新建终端 / 进入一个已有终端 / 打开 Muxvo。
**前置条件**：当前终端没有在跑全屏命令行工具。
**正常流程**：
  1. 终端创建完成
  2. 终端下方出现一条输入区，边框柔和
  3. 键盘焦点自动进入输入区
  4. 输入区内显示灰色占位文字
**用户看到的反馈**：输入区显示占位文案；输入区边框有淡淡的高亮表示当前拥有焦点；终端主区光标为普通暗色，不闪烁。
**结束状态**：用户随时可以开始敲字。
**异常情况**：如果终端在创建瞬间就进入了全屏命令行工具（例如配置里启动命令就是 vim），输入区会在第一时间收起，进入"不可见"形态。
**相关**：[M01-REQ-001]

### REQ-EDITOR_INPUT-003 Enter 发送文字

**触发方式**：用户在输入区按 Enter。
**前置条件**：输入区里至少有一个字符（完全空白时按 Enter 不触发发送，也不换行）。
**正常流程**：
  1. 用户敲完内容
  2. 用户按 Enter
  3. 内容被送出
  4. 输入区清空，占位文案重新出现
**用户看到的反馈**：输入区内容在 150 ms 内消失；光标留在输入区；终端主区看到刚发送内容的回显（属于 [M07]）。
**结束状态**：空态，可以直接接着敲下一条。
**异常情况**：发送失败时输入区内容不清空，并在输入区下方显示红色提示（详见 [M07-REQ-020]）。
**相关**：[M07-REQ-001] [M07-REQ-002]

### REQ-EDITOR_INPUT-005 Shift+Enter 换行

**触发方式**：用户按住 Shift 再按 Enter。
**前置条件**：焦点在输入区。
**正常流程**：
  1. 用户按 Shift+Enter
  2. 光标跳到下一行起始
  3. 输入区高度自动增高一行（未到上限时）
**用户看到的反馈**：光标垂直移动，输入区下缘向下推进；原有内容不变。
**结束状态**：用户在新一行继续打字。
**异常情况**：如果已经到达最大可见高度，编辑区内部开始滚动，新一行在可视区域底部，旧内容可向上滚回去看。
**相关**：REQ-EDITOR_INPUT-026

### REQ-EDITOR_INPUT-012 切终端草稿保留

**触发方式**：用户在终端 A 写了一半，切到终端 B，再切回终端 A。
**前置条件**：两个终端都存活。
**正常流程**：
  1. 用户在终端 A 输入区写下"帮我改 login 页…"
  2. 用户点击终端 B 的标题 / 在缩略图上点击 / 通过快捷键切换
  3. 终端 B 的输入区显示终端 B 自己的草稿（可能为空，也可能是 B 上次留下的）
  4. 用户切回终端 A
  5. 终端 A 的输入区显示"帮我改 login 页…"，光标位置、滚动位置与离开时一致
**用户看到的反馈**：切回来的瞬间内容就在，没有"空一瞬间又出现"的闪烁。
**结束状态**：用户继续从光标处输入。
**异常情况**：终端 A 在离开期间被关闭，再无法切回；草稿随终端一起消失，不遗留到新建的终端。
**相关**：REQ-EDITOR_INPUT-014 · [M01-REQ-008]

### REQ-EDITOR_INPUT-017 遇到全屏命令行工具自动收起

**触发方式**：当前终端里跑了 vim / htop / less / man / ssh 进入交互界面 / tmux 等会接管整个屏幕的工具。
**前置条件**：编辑器当前可见。
**正常流程**：
  1. 用户在终端里敲 `vim note.md` 回车
  2. vim 进入全屏界面
  3. Muxvo 检测到"终端需要整块屏幕"
  4. 编辑器在 150 ms 内淡出
  5. 终端主区向下延伸吃满原本编辑器的位置
  6. 键盘从此直接作用于终端
**用户看到的反馈**：编辑器整体淡出；终端扩张；vim 的状态栏立刻出现在屏幕靠下位置。
**结束状态**：用户可以用 vim 的所有快捷键，Ctrl+C 等不需要穿透规则。
**异常情况**：工具启动极慢（例如 ssh 还在连）时，收起动作会延迟到工具真正进入全屏才触发；中途用户按 ⌘T 新建了另一个终端，新终端仍然是默认的"编辑器可见"形态，互不干扰。
**相关**：REQ-EDITOR_INPUT-018 · [M01-REQ-015]

### REQ-EDITOR_INPUT-020 Ctrl+C 穿透到终端

**触发方式**：用户在编辑器处于可见形态下按 Ctrl+C。
**前置条件**：焦点在编辑器里。
**正常流程**：
  1. 用户在编辑器里写了"帮我改"三个字
  2. 用户发现终端里跑的测试任务还没停，按 Ctrl+C
  3. 终端里任务被打断，出现 ^C，回到提示符
  4. 编辑器里的"帮我改"三个字仍然在
**用户看到的反馈**：终端正文出现 ^C 和新的提示符行；编辑器内容和光标位置不变；输入区边框不闪。
**结束状态**：用户可以继续修改刚刚的草稿，或重新按 Enter 发送。
**异常情况**：如果用户期望的是"复制编辑器里的文字"，此按键组合不适用——复制需要先选中文字后按 ⌘C（macOS）或 Ctrl+Shift+C（其他系统），详见 REQ-EDITOR_INPUT-028。
**相关**：REQ-EDITOR_INPUT-021 · REQ-EDITOR_INPUT-022 · REQ-EDITOR_INPUT-023 · REQ-EDITOR_INPUT-028

### REQ-EDITOR_INPUT-027 超长输入字数提示

**触发方式**：用户在编辑区里写入 / 粘贴超过 500 行或 10 000 字的内容。
**前置条件**：焦点在编辑器里，编辑器处于可见形态。
**正常流程**：
  1. 用户粘贴一段 2 034 行的日志
  2. 编辑器在右下角显示计数标签"2 034 行 / 128 K 字"
  3. 用户可以继续编辑，标签数字实时更新
  4. 用户按 Enter 发送，标签随内容一同消失
**用户看到的反馈**：右下角灰色胶囊标签，不遮挡内容；超过软上限时颜色从灰色变成浅橙。
**结束状态**：内容被发送或被用户清空。
**异常情况**：超过硬上限（例如 50 万字）时按 Enter 弹出确认对话框："当前输入非常长，可能影响响应速度，确定发送？"按钮"继续发送 / 取消"。
**相关**：REQ-EDITOR_INPUT-026 · [M07-REQ-015]

## 6. 主要用户旅程

### Journey 1：新手第一次打开 Muxvo 并写一条 prompt

1. **你** 第一次打开 Muxvo，屏幕中央出现默认终端
   → **你所见**：终端下方有一条带淡淡边框的输入区，里面是灰色提示"给 Claude Code 写点什么，Enter 发送，Shift+Enter 换行"
   → **你感受**：一眼认出来"这里是写字的地方"，不需要摸索
2. **你** 开始敲"帮我看看这段代码"
   → **你所见**：字符出现在输入区，占位文案消失
   → **你感受**：反应跟手，没有延迟
3. **你** 按 Shift+Enter 换行，粘贴一段代码
   → **你所见**：代码保留缩进，输入区自动变高
   → **你感受**：像在写 Markdown 那样舒服
4. **你** 按 Enter
   → **你所见**：内容在一瞬间消失，占位文案回来，终端正文区出现刚发的 prompt
   → **你感受**："对，就是这样"
5. **你** 等 Claude Code 回答时，手滑按了一下 Ctrl+C
   → **你所见**：终端正文出现 ^C，Claude Code 的响应被打断；输入区里你刚打的下一条半截还在
   → **你感受**：Ctrl+C 真的打到了任务上，没有把我正在写的草稿弄没

### Journey 2：老手多终端并行工作

1. **你** 在终端 A 写一段长 prompt 给 Claude Code
   → **你所见**：编辑区里有 12 行文字
2. **你** 想起终端 B 的一个测试可能挂了，点终端 B 的标题
   → **你所见**：主区切到终端 B，终端 B 的编辑区可能是空的，也可能是它自己的草稿
   → **你感受**：A 没丢，只是不在前台
3. **你** 在 B 里按 Ctrl+C 打断任务，看完输出
   → **你所见**：B 终端出现 ^C；你在 B 里没写过字，编辑区依然是占位文案
4. **你** 切回终端 A
   → **你所见**：12 行文字原样躺在那里，光标在你离开时的位置
   → **你感受**：不需要重打，心里稳
5. **你** 继续写完最后一段，按 ⌘Enter 发送
   → **你所见**：输入区清空；终端 A 主区出现发送后的内容
6. **你** 发现刚才多写了一行没用的，按 ⌘Z
   → **你所见**：输入区里刚删的那行没回来——因为内容已经发出去了，撤销历史已清空
   → **你感受**：略有期待落空，但逻辑一致

### Journey 3：异常路径 — 跑 vim 再回来

1. **你** 在终端里敲 `vim /tmp/note.md`
   → **你所见**：编辑器在约 150 ms 内淡出，终端向下扩展吃掉原本编辑器的位置
   → **你感受**：自动的，不用管
2. **你** 在 vim 里写了 3 行笔记，按 Ctrl+C 想退出
   → **你所见**：vim 没退，因为 vim 不吃这一招
   → **你感受**：Ctrl+C 的穿透规则只在"编辑器可见"形态下存在；现在编辑器已经收起，终端完全自理
3. **你** 敲 `:wq` 退出 vim
   → **你所见**：终端回到提示符；编辑器在 150 ms 内淡入，回到原位
   → **你感受**：无缝
4. **你** 发现编辑器里居然还留着"帮我改 login 页…"——那是你进 vim 之前写到一半的草稿
   → **你感受**：没丢
5. **你** 按 Enter 发送

## 7. 界面规格

### 7.1 页面/面板清单

| 名称 | 作用 | 进入方式 | 退出方式 |
|---|---|---|---|
| 输入区（编辑器可见形态） | 让用户写文字、多行编辑、查看草稿和超长提示 | 新建终端 / 切到一个编辑器可见的终端 | 点终端主区让焦点转移 / 跑全屏工具 / 手动切换 |
| 终端主区（编辑器隐藏形态） | 用户直接与命令行工具交互 | 跑 vim / htop / less / ssh 等 / 手动切换 | 退出全屏工具 / 手动切换 |

### 7.2 各页关键区域

**编辑器可见形态**

- **主区**：终端正文输出，占据上方绝大部分空间
- **输入区**：位于终端主区下方，全宽，与终端主区之间有一条细分隔线
  - 输入文本区域（可变高，下限约 2 行，默认上限约 12 行，超出后内部滚动）
  - 右下角的字数/行数胶囊（仅超长时出现）
  - 左下角的模式切换按钮（详见 §8.3）
- **边框**：编辑器拥有焦点时边框变淡色高亮，失焦时恢复灰色

**编辑器隐藏形态**

- **主区**：终端正文吃满整块区域，下方没有输入区
- **右上角**：保留一个"唤回输入框"按钮（详见 §8.3）

### 7.3 五态规格（编辑器可见形态）

| 状态 | 用户看到什么 | 可做的动作 |
|---|---|---|
| **空态** | 输入区为空，显示灰色占位文案；边框淡灰 | 直接开始敲字 |
| **加载态** | 不适用 + 理由：编辑器本身不从远端加载，打开即用；唯一的"等待"是发送后、终端还没回显前的瞬间，属于 [M07] | —— |
| **正常态** | 输入区有内容，占位消失，光标可见 | 继续输入 / 粘贴 / 撤销 / Enter 发送 / Shift+Enter 换行 / Ctrl+C 穿透 |
| **错误态** | 发送失败后内容不清空，下方出现一行红色文案"发送失败：<原因>，按 Enter 重试" | 修改后重发 / 复制走 / 手动清空 |
| **受限态** | 终端已经关闭 / 正在重启 / 处于全屏工具模式 → 输入区隐藏或整体置灰 | 不可输入；等待终端恢复 |

### 7.4 文案示例

> 空态占位（Claude Code 前台）："给 Claude Code 写点什么，Enter 发送，Shift+Enter 换行"
> 空态占位（Codex 前台）："向 Codex 提问，Enter 发送，Shift+Enter 换行"
> 空态占位（Gemini CLI 前台）："让 Gemini CLI 帮你做什么？Enter 发送"
> 空态占位（普通命令行前台）："输入命令，Enter 执行，Shift+Enter 多行"
> 空态占位（首次使用引导）："这里是输入区。支持多行，支持粘贴，支持撤销（⌘Z）"
> 错误态："发送失败：终端未就绪。按 Enter 重试，或复制内容后手动粘贴。"
> 超长提示（软上限内）："2 034 行 · 128 K 字"
> 超长提示（超硬上限时的确认对话框标题）："输入非常长"
> 超长提示正文："当前输入达到 52 万字，发送后可能需要较长时间响应，确定继续？"
> 超长提示按钮："继续发送" / "取消"
> 手动切换按钮文案（编辑器可见时）："收起输入框"
> 手动切换按钮文案（编辑器隐藏时）："展开输入框"

## 8. 状态与交互规则

### 8.1 可见状态清单

**编辑器两种形态**

- **可见**：用户看到终端下方的输入区，键盘作用于输入区，Ctrl+C/Z/D 三键穿透到终端
- **隐藏**：用户看不到输入区，终端吃满整块区域，键盘直接作用于终端

**输入区三种内容状态**

- **空**：显示占位文案
- **有内容**：占位消失，光标可见
- **超长**：有内容且右下角出现字数胶囊

**焦点两种归属**

- **在编辑器**：输入区边框淡色高亮，终端主区光标暗色
- **在终端主区**：终端主区光标亮起闪烁，输入区边框恢复灰色

### 8.2 状态切换触发

- 用户新建终端 → 编辑器进入"可见 + 空 + 在编辑器"
- 用户在输入区敲第一个字 → 内容状态从"空"变"有内容"
- 用户按 Enter 发送成功 → 内容状态回到"空"
- 用户按 Shift+Enter → 内容增加一行，状态保持"有内容"
- 用户粘贴超长内容 → 内容状态变"超长"，右下角出现胶囊
- 用户切到另一终端 → 当前终端的草稿记下，另一个终端的草稿显示
- 用户切回原终端 → 之前的草稿和光标位置原样出现
- 终端里跑全屏工具（vim/htop/less/man/tmux/ssh 交互界面等）→ 编辑器从"可见"淡出变"隐藏"
- 全屏工具退出 → 编辑器从"隐藏"淡入变"可见"，草稿保留
- 用户点终端右上角"收起输入框" → 编辑器手动变"隐藏"
- 用户点终端右上角"展开输入框" → 编辑器手动变"可见"
- 用户点终端主区任意位置 → 焦点转到终端主区
- 用户点输入区任意位置 → 焦点转回编辑器
- 用户关闭终端 → 此终端的草稿同步清除
- 用户按 Ctrl+C / Ctrl+Z / Ctrl+D（编辑器可见形态下）→ 信号穿透到终端，输入区内容保留

### 8.3 快捷键与手势

| 按键/手势 | 作用 | 前置条件 |
|---|---|---|
| Enter | 发送当前输入 | 编辑器可见 + 有焦点 + 输入非空 |
| Cmd+Enter / Ctrl+Enter | 发送当前输入 | 同上 |
| Shift+Enter | 在光标处换行 | 编辑器可见 + 有焦点 |
| ⌘Z / Ctrl+Z（编辑器内语义） | 撤销上一步输入/删除/粘贴 | 有焦点 且 存在撤销历史；macOS 的 ⌘Z 不走穿透，穿透只认无 Cmd 的 Ctrl+Z |
| ⌘⇧Z / Ctrl+Y | 重做 | 有撤销历史可恢复 |
| ⌘C / Ctrl+Shift+C | 复制选中文字到系统剪贴板 | 编辑器里有被选中的文字 |
| ⌘V / Ctrl+Shift+V | 粘贴剪贴板内容到编辑器 | 焦点在编辑器 |
| ⌘A / Ctrl+A | 全选编辑器内容 | 焦点在编辑器 |
| Ctrl+C（无 Cmd） | 穿透到终端：打断当前任务 | 编辑器可见 + 焦点在编辑器 |
| Ctrl+Z（无 Cmd） | 穿透到终端：挂起当前任务 | 同上 |
| Ctrl+D | 穿透到终端：发送结束输入信号 | 同上 |
| 点击终端主区 | 把焦点交给终端 | 终端存活 |
| 点击输入区 | 把焦点交给编辑器 | 编辑器可见 |
| "收起输入框" 按钮 | 手动切到隐藏形态 | 编辑器可见 |
| "展开输入框" 按钮 | 手动切到可见形态 | 编辑器隐藏 |

### 8.4 多窗口/多标签行为

- 每个终端都有自己独立的草稿与撤销历史，互不共享。
- 焦点一次只在一个终端的输入区内。
- 打开多个 Muxvo 窗口时，每个窗口各自管理自己的编辑器；窗口 A 的草稿不会出现在窗口 B。
- 从一个窗口切到另一个窗口，之前那个窗口的草稿原样保留，下次切回仍在。

## 9. 边界、限制与异常

### 数量 / 长度限制

- 输入区默认可见高度约 2 行起，最大约 12 行，超过后内部滚动（具体数值见附录 A2，待与设计确认）
- 单条输入字符数没有硬性上限，但超过约 50 万字时发送前会弹确认对话框
- 撤销历史每个终端最多保留约 200 步（超过后旧的自动丢弃）
- 草稿在 Muxvo 运行期间常驻内存；关闭整个 Muxvo 后，当前终端的草稿会在下次启动时恢复（前提是终端本身也能恢复，见 [M01-REQ-026]）

### 明确不支持

- 编辑器不支持富文本样式（粗体、颜色、字体大小等）——粘贴进来的富文本会被降级成纯文本
- 编辑器不支持拼写检查下划线（避免与命令行关键字混淆）
- 编辑器不提供"历史输入上下翻"（上下键在编辑区内就是光标移动，不是翻已发送过的 prompt 历史）
- 编辑器不提供自动补全 / 候选词菜单
- 编辑器不提供"定时自动发送"或"倒计时发送"
- 编辑器不随终端大小缩小而无限压缩高度——低于 2 行可见时会变成只能横向滚动的单行条
- 撤销历史不跨终端共享，也不会在重启 Muxvo 后保留
- 跑全屏工具期间用户手动"展开输入框"不生效（会看到按钮被禁用），因为此时编辑器让位给终端

### 错误提示文案

> "发送失败：终端未就绪。按 Enter 重试。"
> "发送失败：内容为空。"
> "粘贴的内容格式不被支持，已自动转为纯文本。"
> "输入非常长，可能影响响应速度，确定继续？"（超硬上限时）
> "当前终端正在使用全屏工具，输入框暂时不可用。退出 vim 等工具后自动恢复。"（隐藏形态下用户点展开按钮）

### 数据丢失风险

- **风险 1**：Muxvo 崩溃时正在编辑的草稿。保障：当前终端草稿每隔一小段时间被记住一次，下次启动时能看到最近一次的版本。
- **风险 2**：关闭终端时丢失该终端草稿。保障：关闭前的"确定"对话框里，如果草稿非空会在正文多一行提示"此终端有未发送的草稿，关闭后会一并丢弃"。（详见 [M01-REQ-013]）
- **风险 3**：发送后立即发现发错。保障：发送清空草稿后按 ⌘Z 无法恢复已发送的内容——建议用户在发送前善用 Shift+Enter 断行检查。

## 10. 明确不做的事（Out of Scope）

- **不做**：历史 prompt 上下翻查（用上下键在已发送的文字里翻）。**为什么**：上下键在编辑区里是光标移动，如果同时背负"翻历史"会让用户困惑。**何时考虑**：后续专门设计"历史面板"时。
- **不做**：Markdown 实时预览。**为什么**：终端场景下用户要的是原文准确送出，不是预览好看。**何时考虑**：文档撰写场景另立模块。
- **不做**：拼写纠错 / 自动大写。**为什么**：命令行关键字经常是小写、奇怪字符，系统自动纠错会把命令改错。**何时考虑**：不考虑。
- **不做**：支持粗体/斜体等富文本样式。**为什么**：终端和命令行工具不认这些样式；编辑器的目标是"纯文本 + 多行"。**何时考虑**：不考虑。
- **不做**：编辑器内 @mention / 斜杠命令菜单。**为什么**：会和 Claude Code 本身的斜杠命令冲突。**何时考虑**：如果要做需要先解决语法冲突。
- **不做**：草稿云端同步。**为什么**：属于个人即时创作内容，不适合跨设备同步。**何时考虑**：后续如果有团队协作需求再讨论。
- **不做**：输入区内插入图片预览气泡。**为什么**：图片附件属于 [M06 EDITOR_ATTACH] 模块。**何时考虑**：M06 内实现。
- **不做**：语音输入 / 听写。**为什么**：范围超出本模块，需要额外权限设计。**何时考虑**：未来平台化专项。

### 11.3 待确认项

- **待确认 1**：输入区的默认高度上限（12 行 vs 8 行 vs 屏幕 30%）需要与设计对齐。
- **待确认 2**：超长输入的软上限与硬上限数值（10 000 字 / 50 万字 仅为建议值）。
- **待确认 3**：macOS 上 ⌘Z 与 Ctrl+Z 行为分离的具体映射——当前方案是"⌘Z 在编辑器内部撤销，Ctrl+Z 穿透到终端"，需要与键盘映射表（见 [M14 ONBOARD_PREFS]）对齐。
- **待确认 4**：撤销历史 200 步上限、草稿本地记忆时机（例如每 3 秒一次）的具体数值需要与性能评估对齐。
- **待确认 5**：占位文案是否根据"前台是 Claude Code / Codex / Gemini CLI / 普通命令行"动态切换，还是只保留一条通用文案——目前设计 §7.4 按动态处理。
- **待确认 6**：输入区左下角"收起/展开"按钮的位置与 [M11 FILE_PANEL] 的"文件"按钮是否冲突——需要看终端头部整体布局。
